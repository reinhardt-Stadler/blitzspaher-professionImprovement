# Lab targets for RA-5.1 (6-8 resettable Vulhub targets)
#
# Format: name | vulhub-relative-path | expected-host-port | cve | verifier
#
# Two columns are advisory, not authority:
#   - expected-host-port: Vulhub compose files pin their own mapping. The script
#     reads the ACTUAL mapping from `docker ps` after start, so a wrong number
#     here only affects the "expected" column in `list`, never the probe.
#   - verifier: whether cve_check already has a probe spec for it.
#     "no" means it is a legitimate target for probe_forge (write one yourself),
#     not that the target is unusable.
#
# Ports collide across Vulhub targets (most Java demos bind 8080). That is why
# this tool starts ONE target at a time instead of the whole list: `lab.sh <name> start`.
#
# Run `bash deploy/labs/lab.sh list` to see which of these actually exist in
# your vulhub checkout - the list is filtered against the filesystem, so it
# stays honest if your vulhub version differs.
#
# Two traps, both verified against a real checkout on 2026-11-25:
#   1. DIRECTORY NAME IS NOT THE IMAGE TAG. `fastjson/1.2.47-rce` ships
#      `vulhub/fastjson:1.2.45`. Never infer the tag from the path, and never
#      assume a directory exists because a tag does: `fastjson/1.2.45-rce`
#      does not exist, `1.2.24-rce` / `1.2.47-rce` / `1.2.83-rce` do.
#   2. WEIGHT VARIES A LOT. `unomi` pulls elasticsearch 7.9.3 (2GB+ RSS, slow
#      start); `solr` and `ofbiz` are single containers but still heavier than
#      the three Java demos. Verify picks in file order, so the light targets
#      come first on purpose.
