## 1. 更新类型分类

### 类型 A：文档变更（不涉及代码）

**定义**：
- `docs/` 下文档的内容修改、格式优化、结构调整、文件移动/重命名
- ADR / DCR / CR 等变更记录的登记（见第 6 节四个入口）
- 删除文档或目录

**验收要求**：

| 检查项 | 验证方法 |
|--------|---------|
| **规范性检查** | 对照 `docs/README.md`「写作规则」7 条逐条核对（单一事实来源 / ID 稳定 / 追踪链 / …） |
| **一致性检查** | 上下游文档同步：需求 ↔ 规格 ↔ 验收的 ID 与结论一致；引用处无断链 |
| **完整性检查** | 删除文件需确认：① 无其他文件引用 ② `git grep` 无残留 |

**标记方式**：
```markdown
**验收结果**：
- [x] 规范性检查：符合 `docs/README.md` 写作规则
- [x] 一致性检查：FR-AGENT-03 在需求/规格/验收三处表述一致
- [ ] 功能测试：不适用（类型 A — 文档变更）
```

---

### 类型 B：代码变更（涉及功能实现/修改）

**定义**：
- 新增/修改 `src/pi-pentest/**` 下 TypeScript 代码
- 修复 Bug、实现新工具、重构控制层逻辑

**验收要求**：

| 检查项 | 说明 |
|--------|------|
| **功能测试** | 必须执行 `npm test`，全绿才可标记完成 |
| **测试依据** | 精确到需求 ID / 验收 ID / 用例名（格式见第 4 节） |
| **测试方法** | 记录完整命令与步骤，他人可复现 |
| **安全回归** | 凡改动 `security-control.ts`、工具层或授权/预算/审计逻辑，越界注入用例必须重跑（见第 5 节） |

**标记方式**：
```markdown
**验收结果**：
- [x] 功能测试：`npm test` 16/16 通过
- [x] 测试依据：`3验收文档.md` SEC-AUTHZ-01 + `security-control.test.ts` 白名单用例
- [x] 测试方法：`cd src/pi-pentest && npm test`
- [x] 安全回归：越界注入用例重跑，未授权目标 100% 拦截
```

---

### 混合类型处理

一次变更同时包含**类型 A**和**类型 B**时：

**方案 1：分别记录**（推荐）——代码与文档各写一条，各自走对应检查项。
**方案 2：合并为类型 B**（按更严格标准）——验收结果同时列出功能测试与规范性检查。

## 2. 变更条目结构

每条变更记录必须包含以下字段：

```markdown
### [YYYY-MM-DD] - <更改主题>

**更改方面**：<文件路径列表>

**类型**：A（文档）/ B（代码）/ A+B（混合）

**详细描述**：
- <技术实现或文档改动细节 1>
- <技术实现或文档改动细节 2>

**验收结果**：
- [x] <检查项 1>：<结果说明>
- [ ] 备注：<问题或后续行动>

**关联登记**：
- 需求变更 → `1.1需求变更记录.md`（CR-*）
- 决策变更 → `ADR/决策变更记录.md`（DCR-*）
- 计划变更 → `4工作项与路线图.md` §5 变更记录
- 无（纯实现迭代，不改需求/决策/计划）
```

## 3. 检查项规范

### 类型 A 专用检查项

| 检查项 | 说明 | 通过标准 |
|--------|------|---------|
| 规范性检查 | 是否符合写作规则 | `docs/README.md` 7 条全满足 |
| 一致性检查 | 追踪链上下游是否同步 | 涉及的 FR-*/SEC-*/R* 三处表述一致 |
| 完整性检查 | 删除是否有残留引用 | `git grep` 无结果 |

### 类型 B 专用检查项

| 检查项 | 说明 | 通过标准 |
|--------|------|---------|
| 功能测试 | 必须执行 | `npm test` 全 PASS |
| 测试依据 | 引用需求/验收/用例 | 精确到 ID 或用例名 |
| 测试方法 | 命令与步骤可复现 | 他人按记录可重跑 |
| 安全回归 | 控制层相关改动必查 | 越界注入用例 100% 拦截 |

### 判定词汇（引自 `3验收文档.md`）

统一使用 **PASS / FAIL / INSUFFICIENT_EVIDENCE / NOT_APPLICABLE** 四值：
- 数值未冻结（OQ-09 未关闭）前，涉及预算/调用率的结论一律标 `INSUFFICIENT_EVIDENCE`
- 文档变更的功能测试项标 `NOT_APPLICABLE`，不得打勾也不得留空

## 4. 测试依据引用格式

| 文档 | 引用格式 | 示例 |
|------|---------|------|
| `1需求文档.md` | 需求 ID | `FR-AGENT-03`、`SEC-BUDGET-01` |
| `2规格-实现约束.md` | 规格条目 C-* | `C-工具注册` |
| `3验收文档.md` | 验收 ID + 层级 | `R7 越界拦截（第一层）` |
| `test/security-control.test.ts` | 文件名 + 用例名 | `security-control.test.ts::目标越界拦截` |
| `ADR/ADR-00X` | ADR 编号 + 结论 | `ADR-001 框架选型（已关闭）` |

**❌ 不合格示例**：
- 「根据验收文档」→ 未指明 R 编号
- 「测试已通过」→ 无命令、无用例名

**✅ 合格示例**：
- 「`3验收文档.md` R7 越界拦截：未授权目标 100% 拦截」
- 「`security-control.test.ts` 白名单用例：`192.168.1.1` 被拦截」

## 5. 测试失败与安全回归处理

### 5.1 测试失败

功能测试失败时：
1. **必须记录失败原因** —— 不能只写「测试失败」
2. **必须记录后续行动** —— 修复计划或回滚决定
3. **判定标 FAIL 不打勾** —— 验收结果不能标 PASS

**示例**：
```markdown
### [2026-10-21] - 预算计数器在 halt 后仍可递增

**更改方面**：`src/pi-pentest/src/security-control.ts`

**验收结果**：
- [ ] 功能测试：1 个用例 FAIL（halt 后 callsUsed 仍 +1）
- [ ] 测试依据：`3验收文档.md` SEC-BUDGET-01 + `security-control.test.ts::超预算即停`
- [ ] 测试方法：`cd src/pi-pentest && npm test`
- [ ] 失败原因：halt 路径未走计数拦截分支
- [ ] 后续行动：修复后回归全量单测（关联 W2）
```

### 5.2 安全回归（本项目特有）

改动 `security-control.ts`、工具层、或授权/预算/审计相关逻辑时，除常规检查项外必须追加：

| 附加检查项 | 通过标准 |
|-----------|---------|
| 越界注入回归 | 未授权目标 / 未注册工具注入用例 100% 拦截（R7 反证） |
| 诚实性检查 | 不引入默认模拟回退；模拟能力仅经 `PENTEST_ALLOW_SIMULATED=1` 显式开启 |
| 审计字段检查 | JSONL 审计日志字段完整（SEC-AUDIT-01） |

> **理由**：模型选型实验（`research/模型选型实验结果.md` §4 结论 2）表明候选模型对恶意渗透请求的越界服从率达 90–100%，安全边界必须由 L3 控制层强制保证——任何削弱控制层的改动都是高风险变更。

## 6. 变更登记入口（四个通道，互不混用）

| 变更性质 | 唯一入口 | 编号 |
|---------|---------|------|
| 对抗组驱动的需求变更 | `1.1需求变更记录.md` | CR-* 递增 |
| 技术决策及其变更 | `ADR/决策变更记录.md`（DCR）；新决策新开 ADR-00X | DCR-* / ADR-00X |
| 计划/工作项/路线图变更 | `4工作项与路线图.md` §5 变更记录 | 日期 + 描述 |
| 纯实现迭代（不改需求/决策/计划） | git 提交 + 本文档第 2 节条目（附于提交说明或 PR 描述） | — |

**同步义务**：新文档或重大改动完成后，把变更摘要同步对抗组（`docs/README.md` 写作规则 4）。

## 7. 周志定位与统计格式

**定位边界**：周志**只记录本周已发生的变更**（做了什么、验收结果如何）；「接下来要做什么」一律不写进周志，由 `4工作项与路线图.md`（唯一计划入口）承载。周志条目日期不得早于实际完成日期，不预填未完成事项。

每周结束时，在周志末尾添加统计表格：

```markdown
## 本周统计

| 变更类型 | 数量 |
|---------|------|
| 功能测试通过（用例数） | <数字> |
| 安全回归通过（注入用例数） | <数字> |
| 需求变更响应（CR-*） | <数字> |
| 决策变更（DCR-*） | <数字> |
| 新增文件 | <数字> |
| 删除文件 | <数字> |
| 重构文件 | <数字> |
```

## 9. 校验命令

完成变更后，运行以下命令自查：

```bash
# 代码：全部单元测试（当前 16 项）
cd src/pi-pentest && npm test

# 文档：删除/移动文件后检查残留引用
git grep -l "<被删除的文件名或关键 ID>"

# 追踪链：确认需求 ID 在需求/规格/验收三处一致
git grep -n "FR-AGENT-03"   # 按实际改动替换 ID
```
