## 写作规则

1. **单一事实来源**：同一事实只在一个文件里维护，别处用引用 + 文档内锚点。
2. **ID 稳定**：需求号（FR-*/SEC-*/NFR-*）、验收号（R*）、ADR 号一经发出不改写，废弃则标 DEPRECATED。
3. **追踪链**：需求 → 场景 → 可观察结果 → 验证方式 → Task，任何一层变更必须同步检查上下游。
4. **同步对抗组**：新文档或重大改动写完后，把变更摘要发给对抗组（指导意见第 7 条），让对方知道我方工作状态。
5. **需求与规格分离**：需求写"做什么"，长期稳定；规格写"用什么技术手段达成指标"，随选型与迭代更新。规格里未定的一律标"待定"指向 ADR，不预填结论。
6. **验收与选型同节奏**：需求验收只依赖需求（可早写）；规格验收与模块级验收必须等对应 ADR 关闭后回填，选型未定之前不虚构内容。
7. **总导读不养细节**：计划类更新只写 `05-规划/工作项与路线图.md`；需求/规格/验收/ADR 的细节更新写各自文档。总导读（v0.4）仅在结构变化时同步指针。
