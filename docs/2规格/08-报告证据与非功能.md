## 8.1 报告字段（结构固定，模型只填内容）

| 段 | 内容 |
| --- | --- |
| 实现手段 | 模板渲染，字段由代码决定；`Finding` 新增 `verificationLevel`；结论四态不动 |
| 达成指标 | R5 ③ 四态正确 + 效率字段齐全；每条 `CONFIRMED` 有 `artifactRef` 与复现步骤。**"建议"组不进 R5 判据**（R5 已冻结），字段是否齐由 §8.7 的 U1 承接 |
| 状态 | 🟢 已有，改两处 → `FR-REPORT` / `R5` |

| 字段组 | 内容 | 数据来源 |
| --- | --- | --- |
| 元信息 | runId / 生成时间 / 扩展版本 / configHash / arm / trace_health / 停止原因 | 审计事件 |
| 范围 | 授权目标 / 实际触碰目标 | `decision` 事件 |
| 结论 | `Finding[]`：id / 标题 / CVE / 目标 / 四态 / **verificationLevel** / 依据 / 证据 / 复现 / 边界 | `execution` 事件 |
| 已执行 | 工具 / 目标 / 结果摘要 | `execution` 事件 |
| 未执行 | 项目 / 原因（含被拦截、用户拒绝、无 spec、预算耗尽） | `decision` / `human` / `stop` |
| 故障 | 工具 / stepId / 摘要 | `execution.isError` |
| 效率 | 调用数 / 决策数 / 拦截数 / 无效调用率 / 耗时 / 事实数 / **两本账余额** | `reconstruct` |
| 建议 | **修复建议**（每条结论对应）+ 后续检查建议 | 模型生成，**必须挂 `Finding.id` 且引用该 Finding 的至少一条证据键**；无引用不入报告 |
| 声明 | 固定免责四条 | 常量 |

**两处已知实现缺陷**（现有代码，实现报告时一并修掉）：

1. `extractCveFindings`（`report.ts:122`）硬编码 `tool === "cve_check"`，新增验证工具会**静默丢结论**；
2. `buildReproSteps`（`report.ts:165`）硬编码 fastjson 请求体，新 CVE 会生成**错误的复现步骤**——改为从 probe spec 生成。

另建议：`Finding` 从 `Observation.evidence.conclusion` 取结论（`tools.ts:534` 已有该字段），
停用 `resultSummary` 正则（`report.ts:130`，summary 改一个字就丢结论）。

| 缺口码 | 含义 | 完整度影响 |
| --- | --- | --- |
| `GAP_DECISION_WITHOUT_EXECUTION` | 放行但无执行（有头无尾） | DEGRADED |
| `GAP_EXECUTION_WITHOUT_DECISION` | 有执行无裁决（旁路风险） | DEGRADED |
| `GAP_MISSING_OBSERVATION_REF` | 无可回溯证据 | DEGRADED |
| `GAP_OBSERVATION_FILE_MISSING` / `GAP_ARTIFACT_FILE_MISSING` | 证据文件缺失 | DEGRADED |
| `GAP_NO_TERMINAL_EVENT` | 无终态，停止原因不可解释 | DEGRADED |
| `GAP_STATE_TRUNCATED`（新） | 状态日志末 seq 不符 | DEGRADED |
| `GAP_STATE_AHEAD_OF_AUDIT`（新） | 崩在两次写之间 | DEGRADED |
| `GAP_AUDIT_AHEAD_OF_STATE`（新） | 状态写失败但审计成功 | DEGRADED，需单列告警 |
| `GAP_REPLAY_NONIDEMPOTENT`（新） | 重放两次结果不同（实现缺陷） | 直接判 MISSING |
| `GAP_PARSE_FAILED`（新） | 工具成功但输出提不出事实（`I4` 占已执行调用 >20%） | DEGRADED |

**判 MISSING 的两条**：既无裁决也无执行；不可判定调用占比 >50%。这两条不动。

## 8.6 模型接入（沿用原规格 §5，不变）

| # | 事项 | 规格 |
| --- | --- | --- |
| 1 | 输出判定三态 | `refused` / `refused_partial`（计入误拒答率）/ `empty_not_refusal`（空输出≠拒答）；二分法曾 100% 误判 |
| 2 | 空输出防护 | 该模型是重推理模型，`max_tokens < 32K` 时 reasoning 吃光配额、content 为空；调用层强制 ≥32000 |
| 3 | 授权上下文的定位 | 实测加授权声明**不降低**越界服从率（90%→100%），故只用于**审计留痕**，不是门禁 |
| 4 | 拒答重提示 | `refused`/`refused_partial` 后带授权上下文重提示 ≤2 次；仍拒答 → 停止原因 `model_refusal`，报告如实标注 |
| 5 | 模型参数适配 | Kimi K2.7 只接受 `temperature: 1`（传 0 报 400）——按 provider 分别配置 |

**为什么 §3 要保留**：它直接支撑 R7 的立论——安全边界必须由控制层强制，不指望模型自觉。
这条也是 `SEC-HUMAN-01` 改档位模型的依据之一。

**与验收的分工**：R/P/C 判"**做没做到**"（一次性、有判据、过或不过）；本节判"**跑得好不好**"（连续、看趋势、可退化）。
一条指标若能同时当验收判据用，说明口径过窄，该退回 R/P 支，不进本卡。

### 8.7.1 三条铁律

| # | 铁律 | 违反后果 |
| --- | --- | --- |
| 1 | 探索账与验证账**分列**，不合并对外报 | 探索充分被读成效率低，倒逼模型不敢探索（`3验收/01` 总则-3.1） |
| 2 | `0` 与"不可判定"是两个结论，可判定数为 0 写 `INSUFFICIENT_EVIDENCE` | 把证据不足报成 0%，等于伪造最优成绩 |
| 3 | 阈值一律"首次试跑后冻结"，未试跑不预填数值 | 预填的数字会被后代当成已验证事实引用 |

### 8.7.3 卡上不放的东西

| 不放 | 理由 |
| --- | --- |
| "智能度""自主性"评分 | 不可判定，且与 NFR-02 冲突（不展示模型内部思维） |
| 混合 T1 / T2 的单一比率 | 人给 CVE 与只给目标，分母性质不同（总则-3.1 明令禁止） |
| 单次 run 的百分比 | 样本不足，只报计数；比率需 ≥3 次同配置 run |
| 商业指标（采纳率 / 留存 / 转化） | 无数据源，硬造就是自欺 |
