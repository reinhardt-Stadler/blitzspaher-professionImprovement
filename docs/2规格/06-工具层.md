## 6.1 注册表结构

| 段 | 内容 |
| --- | --- |
| 实现手段 | `TOOL_REGISTRY: ToolMeta[]`，补 `parameters`（JSON Schema 纯数据）、`levels`、`account` |
| 达成指标 | 新增工具只需在注册表加一条 + `TOOL_IMPL` 加一函数，`index.ts` 零改动 |
| 状态 | 🟡 → `SEC-TOOL-01` / `P10` |

```ts
export interface ToolMeta {
  name: string;
  category: "scanner" | "web_probe" | "vulnerability_check"
          | "evidence_collector" | "knowledge" | "callback" | "generated";
  description: string;
  targetParam: string;
  parameters: JsonSchemaObject;             // 新增：JSON Schema 子集
  levels: AuthorizationLevel[];              // 新增：哪些档位可用
  account: "explore" | "verify" | "none";    // 新增：记哪本账
  timeoutMs: number;                         // 新增：默认超时
}
```

**`tools.ts` 必须零依赖**：不能 import TypeBox、不能 import pi。JSON → TypeBox 的转换在 `index.ts` 做。
这条不是风格问题——`security-control.ts` 的零依赖先例一旦破例，整条"可迁移宿主"的论证就塌了。

## 6.2 表驱动注册

| 段 | 内容 |
| --- | --- |
| 实现手段 | `index.ts` 一段循环：`for (meta of TOOL_REGISTRY) pi.registerTool(defineTool({...}))` |
| 达成指标 | 注册代码从三段样板收敛为一段；新增工具不碰 `index.ts` |
| 依赖决策 | 无 |
| 状态 | 🟡 → `SEC-TOOL-01` / `P10` |

`jsonSchemaToTypeBox` 只需支持子集：`object` / `string` / `number` / `boolean` / `array` /
`required` / `optional`。超出子集直接抛错（**不允许静默降级**，否则 schema 与校验不一致）。

## 6.3 预置工具规格（三个，行为不变）

| 工具 | 输入 | 输出关键字段 | 失败语义 | 超时 |
| --- | --- | --- | --- | --- |
| `nmap_scan` | `target` / `ports`（默认 1-1000） | `evidence.openPorts[{port,service,version}]` | 命令缺失 → `ok=false` + 明确提示，**不伪造** | 60s |
| `http_probe` | `target` / `path` | `evidence.{url,status,server,bodySnippet}` | 同上 | 15s |
| `cve_check` | `target` / `cve` | `evidence.{conclusion,features,exchanges}` | 不支持 → `NOT_EXECUTED`；不可达 → `INCONCLUSIVE` | 15s |

**三条不变的性质**（不要因为重构破坏）：

1. **无损探测**：不发攻击 payload；三靶场报告 §1 的无害性说明依赖这一点。
2. **缺失真命令默认报错**：只有显式 `PENTEST_ALLOW_SIMULATED=1` 才允许模拟（保证 R5 诚实性）。
3. **`execFile(cmd,[args])` 不拼 shell** + `maxBuffer` 上限。

### 6.3.1 失败分类（`ErrorKind`，六值封闭）

"工具失败"是一个说法，不是一种情况。六类混成一类，会导致把目标重启判成工具报废。

| kind | 判据 | 归因 | 该谁修 |
| --- | --- | --- | --- |
| `tool_missing` | 命令不存在 / 工具未注册 / CVE 无对应探测器 | 能力缺口 | 用户补工具，或走 §6.7 降级 |
| `tool_crash` | 非零退出、异常抛出 | 工具缺陷 | 换工具或降级 |
| `timeout` | 超过 `ToolMeta.timeoutMs` | 规模或环境 | 缩范围后换参重试 |
| `target_unreachable` | 连接拒绝 / DNS 失败 / 主机不可达 | **目标侧** | 不修工具，改探测方式 |
| `parse_failed` | 执行成功但输出提不出任何事实（对应总则-3 `I4`） | 解析器缺陷 | 补 `extractFacts` |
| `param_rejected` | 参数被 Schema 或控制层拒绝 | 调用方 | 模型改参 |

**三条硬规则**：

1. `target_unreachable` **不得**把工具标 `toolHealth=unavailable`。靶场重启是常态，误判会让整个工具被永久废弃，后续任务全部降级。
2. 只有 `tool_missing` / `tool_crash` 允许触发降级阶梯（§6.7）；`timeout` 与 `param_rejected` 走换参重试。
3. **六值之外不允许自定义字符串**。开放字符串等于没有分类——查的时候还是只能看 `summary`。

## 6.4 探测规格（probe spec）

| 段 | 内容 |
| --- | --- |
| 实现手段 | 声明式 spec（请求模板 + 匹配 + 四态判定表达式）+ 极小布尔表达式解释器，零依赖 |
| 达成指标 | 新靶场不改 `tools.ts` 即可验证；生成的 spec 通过人工抽检 |
| 依赖决策 | C3 的可自动转换率**待实测，不预填** |
| 状态 | 🟡 → `FR-AGENT-01` / `P5` |

spec 结构与示例见 `22-难点-冲突与验证链.md` C3。执行路径：

```
cve_check(target, cve)
  → 查 probe registry（spec 优先）
  → 命中：解释器按 steps 发请求、按 verdict 表达式出四态
  → 未命中：回落 CVE_PROBES 硬编码探测器（现有 3 个）
  → 都没有：返回 NOT_EXECUTED + 可用列表（诚实，不猜）
```

**安全闸（硬）**：转换来的 spec 若 `safety.sideEffect != "none"` 一律不自动启用。
340 条里不少条目带真实攻击载荷，自动跑等于批量发攻击。

## 6.5 执行限额

| 项 | 值 | 位置 | 说明 |
| --- | --- | --- | --- |
| 单工具超时 | `ToolMeta.timeoutMs` | 注册表 | 由执行层强制，不靠工具自觉 |
| 输出上限 | 4MiB（nmap）/ 2MiB（curl） | `execFile` 的 `maxBuffer` | 超出即失败，不截断静默 |
| 端口跨度 | `paramRules.maxPortSpan = 1000` | `TaskPolicy` | 超跨度标高危（提权申请） |
| 并发 | 首版 1（串行） | 宿主 | 并发与预算/审计的交互未验证前不开 |

## 6.6 新增工具类别的登记要求

新增 `category` 必须同时更新三处，否则会出现"工具能注册但不受控"：

1. `05-执行控制.md` §5.2 的档位表（哪档可用）；
2. `05` §5.3 的账本映射（记哪本）；
3. `budget.ts` 的收束期白名单 `EVIDENCE_TOOLS`（收束时还能不能用）。

## 6.7 工具能力补充（本期只做第一级）

真实项目里"没工具"是常态，不是异常。清单给的是六级替代阶梯，本期只落实**第一级**，其余登记为全量档。

| 级 | 动作 | 本期 |
| --- | --- | --- |
| 1 | 同类别**已注册**工具能否完成同一能力 | ✅ 做 |
| 2 | 已批准的系统命令 | ❌ C |
| 3 | 已批准的 MCP / API | ❌ C |
| 4 | 复用已有工具封装 | ❌ C |
| 5 | 生成辅助脚本 | ❌ C（RA-3） |
| 6 | 请用户补充工具 | ❌ C |

**第一级的实现约束**：

- 触发：`errorKind ∈ {tool_missing, tool_crash}` 且该工具 `toolHealth=unavailable`；
- 输出：**不产工具名**（越界线，`2规格/02` §2.5 第 5 条），只经 `inject` 给一句
  "能力 X 不可用，同类别 Y 可替代"，并落 `tool_fallback` 审计事件（含原工具、替代候选、依据）；
- 无替代：`abandon(tool_unavailable)`，并在报告"未执行"组写明缺的是**哪个能力**，不是"哪个工具"——
  写工具名会让人以为换个工具就行，写能力名才会让人去补工具。

> 与 `07-扩展面.md` 的界线：`07` 是**造新工具**（生成→审查→注册），本节只是**换已有工具**。
> 前者转全量档不影响本节实现。
