# 规格 01 · 分层与模块清单

> **层**：L0 总览 | 覆盖：模块划分、依赖方向、单一事实来源 | **服务需求：NFR-03、NFR-04**
> 上位：`2规格-实现约束.md`（入口页）　下位：`02`–`08` 各层规格

## 1. 六层职责

| 层 | 职责 | 可依赖 | 不可依赖 |
| --- | --- | --- | --- |
| L5 接口层 | 命令、澄清、进度可视 | 全部 | — |
| L0 内核 | 状态机、计划、记忆、判定、停止、持久化 | node 标准库 | **pi、宿主、工具层** |
| L3 判定 | 授权裁决、预算、审计、旁路封堵 | node 标准库 + 内核类型 | pi、工具实现 |
| L4 执行 | 工具实现、注册表、隔离宿主、回连 | node 标准库 + 判定层类型 | pi（`tools.ts` 必须零依赖） |
| L2 宿主适配 | 挂接钩子、注册工具、注入、命令 | 全部（唯一允许依赖 pi 的层） | — |
| L1 沙箱 | 网络、资源、证据卷 | Docker | — |

**唯一允许 import `@earendil-works/*` 的文件是 `src/index.ts`。** 其余任何文件 import 都视为违规，
由 `test/kernel-boundary.test.ts` 做 AST 扫描断言。

> **术语澄清（高频误解）**：ADR-005 说的"内核外置"指**代码位置外置**——把状态与判定从扩展文件 `index.ts`
> 搬进独立目录 `kernel/`，依赖方向反转。**不是不用 pi**：pi 仍然是宿主，负责 loop、会话、schema 校验与 UI。
> "零依赖"也只指不 import pi API，`node:` 标准库照用。定义见 `design/agent-refactor/07-图例与编号约定.md` §10。

## 2. 模块清单

| 模块 | 文件 | 职责一句话 | 不许做什么 |
| --- | --- | --- | --- |
| 内核入口 | `kernel/index.ts` | `reduce(state,input)→{state,events,actions}` | 不写盘、不调模型、不调工具 |
| 状态机 | `kernel/machine.ts` | 七状态转移表 | 不判业务 |
| 持久化 | `kernel/persistence.ts` | `state.jsonl` + snapshot 读写与恢复 | 不解释业务语义 |
| 规划 | `kernel/plan/*` | 假设清单、`suggestNext`、重规划 | 不产工具名与参数 |
| 记忆 | `kernel/memory.ts` | `renderMemory` + 裁剪 | 不维护第二份记忆文本 |
| 认知模型 | `kernel/model/*` | TargetModel 投影、覆盖率 | 不直接读写台账 |
| 判定 | `kernel/verdict.ts` | 三态判定 | 不判是否停止整任务 |
| 停止 | `kernel/decision.ts` | 七条件停止决策（六中止 + 一完成） | 不执行停止动作 |
| 提示注入 | `kernel/inject/*` | S0/S1 文本与注入策略 | 不直接调宿主 |
| 经验 | `kernel/experience/store.ts` | 跨运行经验读写 | 不改结论，只改顺序 |
| 工具生成 | `kernel/toolgen/*` | 静态审查、注册记录 | 不执行代码 |
| 知识 | `kernel/knowledge/*` | 检索、probe spec、假设生成 | 不产生 `cve` 事实 |
| 控制 | `security-control.ts` | `authorize_call` 单一入口 | 不调工具 |
| 预算 | `budget.ts` | 四维水位 + 收束提示 | 不改判定序 |
| 审计 schema | `audit-schema.ts`（新） | 事件 kind 与必填字段 | 不写文件 |
| 工具注册表 | `tools.ts` | `TOOL_REGISTRY` + `TOOL_IMPL` | **不 import pi / TypeBox** |
| 探测规格 | `kernel/knowledge/probe-spec.ts` | spec 解释器 | 不发请求（由工具执行） |
| 宿主适配 | `index.ts` | 钩子、注册循环、注入、命令 | 不写业务判定 |
| 重建/报告/证据 | `reconstruct.ts` / `report.ts` / `evidence-collector.ts` | 离线消费审计 | 不改运行时状态 |

## 3. 依赖方向（单向，不可逆）

```
L5 接口 ──> L2 宿主 ──> L3 判定 ──> L4 执行 ──> L1 沙箱
                │           │           │
                └──────────>│<──────────┘
                            ▼
                       L0 内核（谁都能依赖它，它不依赖谁）
```

三条硬规则：

1. **内核在底层**，被所有人依赖，自己不依赖任何人（含 `node:fs`——持久化由宿主调用 `persistence.ts` 的函数，内核只产事件）。
2. **判定层不认识 pi**：`security-control.ts` 现有 21 项单测就是这条规则的证据。
3. **工具层不认识 pi**：注册表里放 JSON Schema，TypeBox 转换在 `index.ts` 做（否则零依赖先例作废）。

## 4. 单一事实来源（同一个概念只允许一处定义）

| 概念 | 唯一定义处 | 消费者 |
| --- | --- | --- |
| 审计事件 kind 与字段 | `audit-schema.ts` | reconstruct / report / evidence-collector / contract test |
| 工具元数据与参数 schema | `tools.ts` 的 `TOOL_REGISTRY` | index 注册循环 / 判定层 / 预算分配 |
| 结构化事实类型 | `evidence.ts` 的 `FactKind` | 台账 / `phaseOf` / 报告 / 覆盖率 |
| 任务状态与转移 | `kernel/machine.ts` | 持久化 / 命令 / 报告 |
| 能力授权与允许类别 | `05-执行控制.md` 的能力表（代码在 `policy.ts`） | `authorize_call` / UI / 报告 |
| 结论四态 | `report.ts` 的 `Conclusion` | 报告模板 / 事实键 / 验收总则 |

**改这六处任何一处，必须同步改消费者**，否则出现"定义改了、消费方还在用旧口径"的静默偏差。
