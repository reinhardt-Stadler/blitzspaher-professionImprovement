> 本期不实现（见 `00-索引.md` §4）。
> 上位：`06-工具层.md`　下位：`08-报告证据与非功能.md`
> 状态：静态审查与审计 ✅ 可做；**宿主实现 🔴 OQ-15、回连通道 🔴 OQ-16，本文只定接口不选方案**

## 7.1 动态工具管线

| 段 | 内容 |
| --- | --- |
| 实现手段 | 四段：生成（模型写代码）→ 静态审查（确定性规则）→ 首次注册（人工确认一次）→ 复用（不再确认） |
| 达成指标 | 越界生成工具在宿主内无法触达未授权目标；代码本体 + 审查报告 + 执行日志三者入证据包 |
| 依赖决策 | ADR-006 决策 2；OQ-15 |
| 状态 | 审查器 🟡；宿主 🔴 → `FR-TOOLGEN-*` / `P6` |

**人工确认的对象是代码，不是调用。** 这条决定确认界面必须能展示代码 diff 与审查报告，
否则"确认"是形式主义（用户点的是"确定"，不是"我读过这段代码"）。

## 7.2 静态审查规则（七条，确定性）

| # | 规则 | 违规判定方式 |
| --- | --- | --- |
| R1 | 只允许 import 注入的 `ToolContext` 及其类型 | AST：`ImportDeclaration` 白名单 |
| R2 | 禁止 `child_process`/`net`/`dgram`/`http`/`https`/`fs` | AST：字符串匹配 + 动态 `require` 检查 |
| R3 | 禁止 `eval` / `new Function` / `vm` | AST：`CallExpression` / `NewExpression` |
| R4 | 必须导出 `run(ctx, args): Promise<Observation>` | AST：导出声明 |
| R5 | 必须有 JSON Schema 参数声明，且请求目标能被 `extractTarget` 解析 | 静态 + 运行期双查 |
| R6 | ≤200 行 / ≤16KB | 文本统计 |
| R7 | 代码 + SHA-256 入证据包 | 证据收集器 |

审查器 `review(code) → {ok, violations[], ast?}` 是纯函数，可离线单测，**不依赖宿主**。
这也是为什么它可以先做：它是"能不能安全跑生成代码"的前置条件，而不是它的产物。

## 7.3 执行宿主接口

| 段 | 内容 |
| --- | --- |
| 实现手段 | `ToolHost.run(code, args, limits) → {observation, logs, exit}`；`limits` 含 cpu/mem/net 策略 |
| 达成指标 | 默认 `deny all` 出网，仅放开 `policy.allowedTargets` |
| 依赖决策 | **🔴 OQ-15**：至少两个候选实测比较后另开专题 ADR |
| 状态 | 🔴 |

```ts
export interface ToolHost {
  run(code: string, args: unknown, limits: {
    cpuMs: number; memMB: number;
    net: { allow: string[]; deny: string[] };
  }): Promise<{ observation: Observation; logs: string[]; exit: "ok" | "timeout" | "error" }>;
}
```

**候选与淘汰线**（不做选择，只定门槛）：

| 候选 | 必须回答 | 淘汰线 |
| --- | --- | --- |
| 子进程 + Node 权限模型 | 能否禁 fs/child_process；能否限资源；启动延迟 | 无法禁出网即淘汰 |
| 独立容器 | 能否 `--network=none` 或仅接内网；只读挂载；启动延迟 | 启动 >2s 需评估预算影响 |
| WASM | 可用库是否够写 HTTP 探测；能否限资源 | 无法发 HTTP 即淘汰 |

## 7.4 回连通道

| 段 | 内容 |
| --- | --- |
| 实现手段 | 独立能力 `callback`；监听器工具 + 三个审计事件 + 原始报文入 artifacts |
| 达成指标 | 能力授予时：完成一次靶→agent 回连且证据可复核；能力未授予时：端口**物理不可达** |
| 依赖决策 | ADR-006 决策 4、DCR-004；**🔴 OQ-16** |
| 状态 | 能力与审计 🟡；通道 🔴 → `FR-EXPLOIT-*` / `P7` |

**三个审计事件**（`callback_watch_start` / `callback_received` / `callback_watch_stop`）必须落：
时间、源 IP、方法、路径、头、体前 N 字节、`stateSeq`。原始报文进 `artifacts/` 复用 `artifactRef`。

**一条待验证的技术推断**（不是结论）：`pentest-net` 是 `internal: true`，只禁出网、网内互通，
因此自回连可能不需要改网络，只需 agent 侧监听 + payload 指向 agent。
验证命令见 `design/agent-refactor/45-RA3-行动与回连.md` §RA-3.3。
**推断未验证前不得写进验收结论。**

## 7.5 报告维度（与结论四态的关系）

| 段 | 内容 |
| --- | --- |
| 实现手段 | 四态**不动**，新增正交维度 `verificationLevel: RISK_SURFACE \| EXPLOIT_CONFIRMED \| CALLBACK_RECEIVED` |
| 达成指标 | 报告能区分"风险面存在"与"回连已验证"，且历史证据包口径不变 |
| 依赖决策 | 硬约束 2（`design/agent-refactor/05` §5）——**待确认** |
| 状态 | 🟡 → `FR-EXPLOIT-02` / `P7` |

**为什么不加第五态**：`3验收文档` 总则-1 的 `cve` 事实键里含四态字符串，
加态等于让历史台账与统计口径同时失效。代价是报告多一列，收益是历史可回溯。

若坚持加第五态，需同步改四处：总则-1、`report.ts` 的 `Conclusion`、`evidence.ts` 的键格式、历史证据包说明。

## 7.6 未调研项的写法规矩

`OQ-15`/`OQ-16` 关闭前，本文档**只写接口与判据，不写实现方案**。
允许写"候选 + 淘汰线"，不允许写"就用容器"。理由：ADR-000 第 3 条要求 ≥2 候选实测比较后才算决策，
提前写死方案会让实测变成"验证我的选择"，而不是"比较"。
