## 2.1 reducer 契约

| 段 | 内容 |
| --- | --- |
| 实现手段 | 纯函数 `reduce(state, input): { state, events, actions }`；不写盘、不调模型、不调工具 |
| 达成指标 | 同一 `state` + 同一 `input` 连续 100 次，输出 JSON 哈希一致 |
| 依赖决策 | ADR-005（内核外置）；实测 Q1（注入方式）不影响本签名 |
| 状态 | 🟡 设计完成待实现 → `FR-AGENT-02` / `P9` |

```ts
export type KernelInput =
  | { type: "task_submitted"; text: string }
  | { type: "policy_confirmed"; policy: TaskPolicy }
  | { type: "tool_result"; toolCallId: string; observation: Observation | null; failed: boolean;
    errorKind?: ErrorKind }
  | { type: "tick"; now: number }
  | { type: "user_command"; command: "pause" | "resume" | "revoke" | "escalate"; arg?: string };

export type KernelAction =
  | { type: "inject"; text: string; reason: string; tag: "plan" | "memory" | "budget" | "gate" }
  | { type: "ask_user"; question: string; options?: string[] }
  | { type: "require_level"; level: AuthorizationLevel; why: string }
  | { type: "stop"; reason: StopReason };
// 没有 call_tool：模型决定调哪个工具，内核只给约束。越界判据见 `05-执行控制.md` §6。
```

`ErrorKind` 是**六值封闭枚举**（`tool_missing` / `tool_crash` / `timeout` / `target_unreachable` /
`parse_failed` / `param_rejected`），定义与归属见 `06-工具层.md` §6.3。
`failed=true` 但缺 `errorKind` 的结果按 `tool_crash` 处理并落一条审计告警——**保守假定工具坏，不假定目标没问题**。

## 2.2 KernelState 字段

| 字段 | 类型 | 谁写 | 何时清 |
| --- | --- | --- | --- |
| `schemaVersion` | `1` | 常量 | 不 |
| `taskId` / `seq` | string / number | 内核 | `seq` 单调递增，永不回退 |
| `status` | 七状态枚举 | `machine.ts` | 不 |
| `stopReason` | `StopReason \| null` | `decision.ts` | 新任务时清 |
| `policy` / `policyVersion` | `TaskPolicy` / number | 宿主传入 | 新任务时清 |
| `phase` | `P0..P4` | `phaseOf(ledger)` 派生 | 派生字段，不持久化 |
| `plan` | `Plan`（假设清单） | `plan/*` | 新任务时清 |
| `ledger` | `Fact[]` | `evidence.extractFacts` 产出后并入 | 新任务时清 |
| `targetModel` | `TargetModel` | 投影器 | 与 `ledger` 同步（投影 ⊆ 台账） |
| `counters` | `{explore, verify, consecutiveFailures, transfersUsed}` | 判定层回写 | 新任务时清 |
| `targetStateVersion` | `Record<target, number>` | `verdict` / 判定层递增 | 新任务时清 |
| `toolHealth` | `Record<string, ok\|degraded\|unavailable>` | `verdict.ts` | 新任务时清 |
| `pending` | `Record<toolCallId, {hypothesisId, requestedAt}>` | 宿主发出调用时 | 拿到结果时删 |
| `authorization` | `{level, grantedAt}` | 宿主 | 新任务时清 |

**派生字段不落盘**：`phase` 与 `targetModel` 可由 `ledger` 重算，落盘会制造两份不一致的真相。
恢复时先载 `ledger` 再重算这两项。

## 2.3 幂等与序号

| 段 | 内容 |
| --- | --- |
| 实现手段 | 每个 reducer 分支必须幂等：同一 `seq` 的事件重复应用不改变状态；`seq` 由事件日志分配，不由时间戳 |
| 达成指标 | 任意事件重放两次，状态深等；`seq` 严格递增 |
| 状态 | 🟡 → `FR-TASK-02` / `P1` |

理由：恢复靠重放，重放必然可能重复（崩溃发生在写盘与确认之间）。不幂等就只能"尽力而为"，那等于没有恢复。

## 2.4 状态外置

| 段 | 内容 |
| --- | --- |
| 实现手段 | `state.jsonl`（append-only，权威）+ `snapshot-<seq>.json`（每 20 事件或阶段切换，留 3 份） |
| 达成指标 | 五步恢复全部通过；与 `audit.jsonl` 的 `max(stateSeq)` 双向对账无缺口 |
| 依赖决策 | 用户 2026-11-10 拍板存储形态，见 **ADR-007** |
| 状态 | 🟡 → `FR-TASK-02` / `P1` |

**事件类型（首版 10 类，新增走 `05` §5 五步清单）**

| type | payload 关键字段 |
| --- | --- |
| `task_transition` | `from` / `to` / `reason` |
| `policy_confirmed` | `policyVersion` / `level` |
| `hypothesis_upsert` | `id` / `status` / `attempts` |
| `hypothesis_reopened` | `id` / `reason` / `stepId`（每假设至多一次） |
| `plan_change` | `op` / `hypothesisId` / `trigger` |
| `fact_ingested` | `keys[]` / `targetStateVersionAfter` |
| `verdict` | `hypothesisId` / `kind` / `reason` |
| `tool_health` | `tool` / `state` |
| `budget_transfer` | `from` / `to` / `amount` / `triggerFactKey` |
| `stop` | `stopReason` |

> `budget_transfer` / `stop` 等在两处出现：`state.jsonl` 版用于**重放恢复**（预算余额、状态迁移必须能重算），
> `audit.jsonl` 版（`05` §5.5 的 kind）用于**审计消费**。两者同源不同用途，不是重复记账——
> 恢复只读 state，报告只读 audit。

**五个缺口码**（`reconstruct` 消费，`traceHealth` 据此降级）：

`GAP_STATE_TRUNCATED`（末 seq 不符）/ `GAP_STATE_AHEAD_OF_AUDIT`（崩在两次写之间）/
`GAP_AUDIT_AHEAD_OF_STATE`（状态写失败但审计成功，更严重）/ `GAP_SNAPSHOT_MISSING` /
`GAP_REPLAY_NONIDEMPOTENT`（重放两次结果不同）

**恢复五步**：载最新快照 → 重放 `seq > snapshot.seq` → 校验末 seq → 与审计对账 →
`pending` 全标 `UNKNOWN_OUTCOME` 且**不重放**（工具可能有副作用）。

## 2.5 越界线（自动可查）

| # | 禁止 | 检查方式 |
| --- | --- | --- |
| 1 | 内核调用模型 | AST 扫描：`kernel/` 不 import model client |
| 2 | 内核保存对话历史 | 类型检查：`KernelState` 无 `messages` 字段 |
| 3 | 内核需要轮次概念 | AST 扫描：无 `turn`/`round` 标识 |
| 4 | 内核处理流式 | AST 扫描：无 `stream`/`chunk` |
| 5 | 内核产工具调用指令 | 类型断言：`KernelAction` 无 `call_tool` 分支 |

**任一条不满足即视为越界**，需回到 ADR-005 重新讨论，不允许"先加上以后再说"。
