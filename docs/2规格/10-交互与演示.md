# 规格 10 · 交互与演示

> **层**：L5 接口
> 上位：`03-规划记忆与任务.md` §3.6（命令）、`08-报告证据与非功能.md`（观测字段）
> **服务需求**：NFR-02（可观测）、FR-TASK-02（状态可视）
> 验收：R1 / P2
> 状态：🟡 设计要求；§6 列当前实现与版本约束

## 1. 目标与边界

**目标**：用户能在 CLI 里看清 agent 正在做什么、为什么这么做、做到了哪一步，
并能用一条命令完成可重复的演示。

**三条边界**：

1. **只复用 pi 的 UI 能力，不自建 TUI 框架**——自建就是第二套 Runtime，与 ADR-005 冲突。
2. **界面不得自成状态源**：所有显示内容必须来自 `renderMemory` / trace 的同一份渲染，
   不允许 UI 自己算一遍。界面与台账对不上，比没有界面更糟。
3. **无交互 UI 时必须降级**：`ctx.hasUI = false` 时输出纯文本，不报错、不阻塞任务。

## 2. 能力分级（版本差异是硬约束）

| 档 | 依赖 | 内容 |
| --- | --- | --- |
| **基础档** | pi 1.2 已有 | `registerCommand` / `ui.confirm` / `ui.notify` |
| **增强档** | pi 1.5 新增 | `ui.setStatus` / `ui.setWidget` / `ui.select` / `ui.input` / `setWorkingMessage` |

增强档的每一项都必须**先探测再使用**：API 不存在时静默跳过该项，只保留基础档输出。
**不允许因为界面增强不可用而让任务失败。**

## 3. 三个界面

### 3.1 状态栏（增强档，常驻）

`ui.setStatus("pentest", text)`，格式固定：

```
pentest RUNNING | verify 12/40 explore 8/30 | H2 collecting
```

左：任务状态机当前态；中：两本账水位（已用/上限）；右：当前假设与状态。
**更新时机**：状态事件后更新，不轮询。

### 3.2 计划面板（增强档，widget）

`/pentest-plan` 开关 `ui.setWidget("pentest-plan", lines)`：

```
阶段 P2 验证 | 已授权: recon, verify
H1 fastjson@target:8090   CONFIRMED   (2 attempts)
H2 shiro@shiro:8080       collecting  (1 attempt)  <- current
H3 unknown@struts2:8080   unverifiable (unknown_component)
未覆盖 2 项 · 未执行 1 项
```

- 内容与 `renderMemory` **同源**，与 `/pentest-plan` 的文本输出逐字一致；
- **只读**：widget 里不能编辑假设，编辑走命令以保留审计；
- 超长按 `03` §3.4 的顺序折叠，**不改变事实集合**。

### 3.3 决策轨迹（基础档，按需）

`/pentest-trace [stepId]` 输出该步骤的 decision / execution / result 三件套，
用于演示"为什么这么做"，不是让人读全量 JSONL。

## 4. 演示模式

`/pentest-demo <scenario>`：用**录制好的输入**跑完整流程，供课程演示与答辩。

| 场景 | 内容 | 演示什么 |
| --- | --- | --- |
| `known` | 三靶场各一次（T1） | 端到端：授权 → 探测 → 验证 → 报告 |
| `unknown` | 伪 `Server` 头服务（T3） | 自主收集 → `INCONCLUSIVE` → 不误报 |
| `denied` | 尝试内置 bash 与越界目标 | 权限闭环：拒绝 + 审计留痕 |

**可重复性口径**：同一录制输入产出**同一轨迹结构**；
模型自由发挥的部分（参数选择、工具顺序）不断言，只断言约束成立——
无越权、无伪造结论、每条调用有审计。演示不是"每次跑出一样的结果"，而是"每次都不越界"。

## 6. 当前实现与版本约束

| 项 | 状态 | 位置 |
| --- | --- | --- |
| 四个已有命令 | ✅ | `index.ts:284/316/377/437` |
| `ui.confirm` 高危确认 | ✅ | `index.ts:209` |
| `ui.setStatus` / `setWidget` / `select` / `input` | 🔴 未使用 | pi 1.5 已提供，见下 |
| 本机 pi | **1.5.0** | `nodejs_envs/node_global` |
| 容器内 pi | **1.2.0** | `deploy/Dockerfile:49` |

**版本差异必须显式处理**：1.5 的 UI API 在容器 1.2 里不存在。
因此增强档默认关闭，由启动时的 API 探测决定，**不靠版本号字符串判断**。
