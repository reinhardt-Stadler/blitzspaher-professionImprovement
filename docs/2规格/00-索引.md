## 3. 每条规格的写法（四段，缺一段视为未完成）

| 段 | 内容 | 判据 |
| --- | --- | --- |
| 实现手段 | 用什么模块、什么接口、什么数据结构 | 能给签名或表结构 |
| 达成指标 | 怎么算做到了 | 可测量，不接受"良好""稳定" |
| 依赖决策 | 哪个 ADR / 哪项实测 / 哪个 OQ | 未关闭的 OQ 必须标明 |
| 状态 | ✅ 已实现 / 🟡 待实现 / ⏸ 卡实测 / 🔴 未调研 | 与设计文档一致 |

## 5. 读法

- **写代码**：先看 `01` 确认模块归属与依赖方向，再看对应层。
- **查某条需求怎么做**：查 §2 对照表，直接跳到规格节。
- **排期**：看 `4工作项与路线图.md` §3 的分工矩阵（行是模块、列是阶段）。
