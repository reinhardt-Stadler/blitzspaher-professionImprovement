# 2026-W46（续）· 自主扩展能力：自造验证器 + 在线取信息 + 缺口上报

> 触发：用户质疑「工具/验证器覆盖没做够，这不就要补自主设计工具的能力？最次也要把缺什么工具汇报给用户。
> 没有 CVE 列表可以自己去收集信息，agent 不能只靠 RAG」。

## 1. 先定了一个方向：造数据，不造代码

实测（`node --permission`，本机 v22.22.2）：

| 模块 | 权限模型下 |
| --- | --- |
| `fs` | **拒**（`ERR_ACCESS_DENIED`） |
| `child_process` | **拒** |
| `net` | **放行**（连 1.1.1.1 未被拦，只有网络本身超时） |

结论：**Node 权限模型挡不住出网**。生成出来的代码可以自己连任意主机，绕过目标授权，
而静态审查只是文本检查（`require("ch"+"ild_process")`、`globalThis["fe"+"tch"]` 都能过）。
所以规格里 RA-3.2 要求"至少两个候选实测比较"是对的，不能想当然写"用容器就行"。

由此定本期的形态：**让 agent 造声明式 spec（数据），不造可执行代码**。
spec 的请求由宿主发，`path` 钉死为相对路径、`Host` 头不许覆盖，
目标永远是 `TaskPolicy.allowedTargets` 里那个——授权边界不依赖审查质量。

代码形态的生成仍然做了管线（审查 + 注册记录），但 `executable` 恒为 `false`。

## 3. 实现中补的两条判据

**① 5xx 不得判 `NOT_CONFIRMED`**

spec 落地时发现：原硬编码探测器里有"5xx → INCONCLUSIVE"这条，而 spec 的判定表达式
表达不出它，语义会退化。这不是格式问题——2026-11-13 真实踩过，本机代理对连不上的
目标回 502，探测器判了 `NOT_CONFIRMED`，等于把"没问到"写成"问过了，没有"。

两层防护：内置 spec 的 baseline 带 `status < 500`（声明式表达），解释器再兜一层
（防模型生成的 spec 漏写）。测试里专门有一条"漏写 lt 500 也判 INCONCLUSIVE"。

**② `(?i)` 前缀要认**

写 spec 的人（包括模型）几乎必然用 `(?i)` 表示忽略大小写，那是 PCRE/Python/Java 的写法，
JS 的 `new RegExp` 不认，会抛 `Invalid group`。直接报错会让"看起来完全正确"的 spec
被判非法，这种失败最难理解。加 `compileRegex` 做一次转换。

结论必须一致（含干净靶的 `NOT_CONFIRMED`）。没有它，无法说"改成分 spec 没改变判定语义"。

## 5. 一个测试策略上的教训

`cve_lookup` 的真实 NVD 那条最初是"网络不通就跳过"。结果连跑两次全套测试，
第二次撞上 NVD 限流（无 key 时 5 请求/30 秒），表现为"这一条偶发失败"。
**测试依赖外部服务的节奏，是最难查的一类不稳定**。改为默认跳过、`PENTEST_TEST_NET=1`
显式开启，两种模式都验过。
