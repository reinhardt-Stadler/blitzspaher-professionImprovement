# 2026-W46（续）· 自主扩展能力：自造验证器 + 在线取信息 + 缺口上报

> 触发：用户质疑「工具/验证器覆盖没做够，这不就要补自主设计工具的能力？最次也要把缺什么工具汇报给用户。
> 没有 CVE 列表可以自己去收集信息，agent 不能只靠 RAG」。

## 1. 先定了一个方向：造数据，不造代码

实测（`node --permission`，本机 v22.22.2）：

| 模块 | 权限模型下 |
| --- | --- |
| `fs` | **拒**（`ERR_ACCESS_DENIED`） |
| `child_process` | **拒** |
| `net` | **放行**（连 1.1.1.1 未被拦，只有网络本身超时） |

结论：**Node 权限模型挡不住出网**。生成出来的代码可以自己连任意主机，绕过目标授权，
而静态审查只是文本检查（`require("ch"+"ild_process")`、`globalThis["fe"+"tch"]` 都能过）。
所以规格里 RA-3.2 要求"至少两个候选实测比较"是对的，不能想当然写"用容器就行"。

由此定本期的形态：**让 agent 造声明式 spec（数据），不造可执行代码**。
spec 的请求由宿主发，`path` 钉死为相对路径、`Host` 头不许覆盖，
目标永远是 `TaskPolicy.allowedTargets` 里那个——授权边界不依赖审查质量。

代码形态的生成仍然做了管线（审查 + 注册记录），但 `executable` 恒为 `false`。

## 3. 实现中补的两条判据

**① 5xx 不得判 `NOT_CONFIRMED`**

spec 落地时发现：原硬编码探测器里有"5xx → INCONCLUSIVE"这条，而 spec 的判定表达式
表达不出它，语义会退化。这不是格式问题——2026-11-13 真实踩过，本机代理对连不上的
目标回 502，探测器判了 `NOT_CONFIRMED`，等于把"没问到"写成"问过了，没有"。

两层防护：内置 spec 的 baseline 带 `status < 500`（声明式表达），解释器再兜一层
（防模型生成的 spec 漏写）。测试里专门有一条"漏写 lt 500 也判 INCONCLUSIVE"。

**② `(?i)` 前缀要认**

写 spec 的人（包括模型）几乎必然用 `(?i)` 表示忽略大小写，那是 PCRE/Python/Java 的写法，
JS 的 `new RegExp` 不认，会抛 `Invalid group`。直接报错会让"看起来完全正确"的 spec
被判非法，这种失败最难理解。加 `compileRegex` 做一次转换。

## 5. 一个测试策略上的教训

`cve_lookup` 的真实 NVD 那条最初是"网络不通就跳过"。结果连跑两次全套测试，
第二次撞上 NVD 限流（无 key 时 5 请求/30 秒），表现为"这一条偶发失败"。

显式开启，两种模式都验过。

## 5.5 追加：一次误判暴露的缺口（2026-11-15）

用户重启 WSL 后容器没起，`docker run` 报名字冲突。agent 跑了一轮，报"目标不可达"，
然后**推断"渗透工具运行在 Docker 内，容器视角的 127.0.0.1 是容器自身"**，并向用户索要
"宿主的可达地址（host.docker.internal 或宿主内网 IP）"。

它就在 Windows 宿主上跑。判断错了，但它没有可靠手段自证——`curl: Failed to connect`
这句话里既没说自己是 `refused` 还是 `timeout`，也没说进程在哪。

**补的工具**：`env_selfcheck`
- 报运行环境：`win32` → 宿主进程，并直接写明"127.0.0.1 就是宿主本机，
  不是视角不对"
- TCP 层探测：`open` / `refused` / `timeout` / `dns_failed` 分开。
  `refused` 配一句"服务没启动，不要换端口去扫"——它上次扫了 16 个端口，全是白的
- 不给 port 时只报环境，不虚构探测结果

**同时补的运维脚本**：`target.cmd`（start / status / stop / logs / reset）
处理"容器停止后名字仍被占用"这个坑：该用 `docker start`，不是 `docker run`。
写的时候踩到 `.cmd` 必须 CRLF——用 LF 写会让 `goto :label` 报
"The system cannot find the batch label"，这是 cmd 的已知限制。

**为什么这类缺失值得单独补**：它不是"少个功能"，是**让 agent 把可自决的事推给用户**。
用户上一轮刚提过这个毛病，这次它以另一种形式回来了。

## 5.5 RA-3.2 定案：执行宿主改为独立容器（2026-11-15）

用户在 WSL 内跑 [`deploy/ra32-host-isolation.sh`](../../deploy/ra32-host-isolation.sh)，10 项全 PASS。决定性数据：

| 检测 | 原始输出 |
| --- | --- |
| 宿主机直连基线 | `http=200`（排除"本来就没网"的假通过） |
| 默认桥接出网（对照） | `http=200` |
| `--network=none` | `curl: (6) Could not resolve host` / exit=6 |
| 实验室网络出网 | exit=6 |
| 实验室网络到靶场 | `bz-target-fastjson:8090 -> http=200` |
| 只读挂载 | `cannot create /work/ra32.txt: Read-only file system` |
| 128MB 内存 | `cgroup=134217728` |
| 启动延迟 | 252 / 272 / 281 ms（淘汰线 2s） |
| 出网套接字 | **`BLOCKED:ENETUNREACH`** |

于是：`ADR-008` 记录决策，OQ-15 关闭，`ADR-006` 状态转"已接受"。

**实现**：`src/toolhost/container.ts`。三个设计点：

1. **bootstrap 是我们写的，不是生成的**。它在容器内构造 `ctx.http`（发请求前校验 host
   是否在授权列表），再调用生成的 `run`，结果以固定标记打到 stdout。
   生成代码没有别的 IO 入口——与容器网络构成双保险：网络挡外网，ctx 挡同实验室的其它靶场。
2. **结果标记取最后一个**。生成代码可以自己打印带标记的字符串伪造结果，取 `lastIndexOf`
   才能防住。有测试固定这条。
3. **路径转换单独抽函数测**。`-v D://tmp//x:/work` 在 WSL 的 docker 里会被当成名为 `D` 的卷，
   挂载结果是空目录且不报错，表现为"工具什么都没做"——这类静默失败比报错难查。

`ToolRegistration.executable` 从"恒 false"改为三条件（审查过 + 人确认过 + 宿主就绪），
但 `hostReady` **缺省 false**：安全的默认值只能是"不许"。

**验收**：`npm run verify:toolhost`。两条必须同时成立——越界探测工具连不上，
授权内目标打得通。只验前者的话，"把一切拦死"也能通过。

**已知边界**：容器网络粒度是"实验室内部"，生成工具能连 `pentest-net` 里的其它靶场容器，
比"只能连本次授权那个"宽。收紧需每次执行动态建网络（叠加 250ms 启动开销），登记为后续优化。

**测试**：803 → **849** 项（26 文件）。`toolhost.test.ts` 27 项覆盖纯函数层；
真容器层在无 docker 环境明确 SKIP，不伪装。
