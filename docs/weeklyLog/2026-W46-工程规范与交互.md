### [2026-11-11] - 补 CLI 交互与演示规格（新增 `2规格/10`）

**更改方面**：新增 `2规格/10-交互与演示.md`；`2规格/00-索引.md`、`README.md` 同步登记

**类型**：A

**详细描述**：
- 需求来源：实现产物需给用户一个 CLI 界面，便于感知与功能演示，可复用 pi 框架
- **三条边界**：只复用 pi 的 UI 能力不自建 TUI；**界面不得自成状态源**（一律由 `renderMemory` / trace
  同源渲染）；`ctx.hasUI = false` 时降级为纯文本且不阻塞任务
- **能力分级**：基础档（pi 1.2 已有的命令 / confirm / notify）与增强档（1.5 的 `setStatus` /
  `setWidget` / `select` / `input`）。增强档逐项**先探测再使用**，API 缺失即跳过，
  **不允许界面增强不可用导致任务失败**
- **三界面**：状态栏（任务态 + 两本账水位 + 当前假设）、计划面板（widget，与 `/pentest-plan` 逐字一致、
  只读）、决策轨迹（`/pentest-trace` 输出单步三件套）
- **演示模式** `/pentest-demo <scenario>`：`known` / `unknown` / `denied` 三场景。
  可重复性口径为"同一录制输入产出同一轨迹结构"，只断言约束成立，不断言模型选择

**验收结果**：
- [x] 版本差异显式处理：本机 1.5.0 / 容器 1.2.0，增强档默认关闭、靠 API 探测而非版本号
- [x] 全文 ≤200 行（109 行），含"当前实现与版本约束"与"待验证"两节

**关联登记**：NFR-02、FR-TASK-02、`2规格/03` §3.6、OQ-14

### [2026-11-11] - 更正 OQ-14 的执行路径：pi 1.5.0 在本机

**更改方面**：`4工作项与路线图.md` OQ-14 行

**类型**：B（纠正既有记录中的错误事实）

**详细描述**：
- 原记录称"pi 只在 Docker 镜像里，本机无 node_modules，需用户在 WSL 内跑"，**与事实不符**。
- 实测：本机 `which pi` → `nodejs_envs/node_global/pi`，`pi --version` = **1.5.0**；
  `@earendil-works/pi-coding-agent/package.json` 版本同为 1.5.0，类型定义完整可读。

- 1.5 中已确认存在的相关能力：`context` / `context_with_system` 事件（`types.d.ts:698/707`，对应 Q1）、
  `ToolLoadout` + `ToolExposure`（`:447/:414`，对应 Q2）、`ui.setStatus` / `setWidget` / `select` / `input`
  （`:83-115`，对应 CLI 增强档）。
- **新约束**：容器镜像固定 1.2.0（`deploy/Dockerfile:49`），上述 1.5 API 在容器内不可用，
  是否升级需单独评估，已写入 OQ-14 备注。
