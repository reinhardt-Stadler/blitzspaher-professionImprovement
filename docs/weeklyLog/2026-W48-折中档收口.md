## 4. 一个隐患：两套相反的 `check` 签名

- `test/harness.ts`：`check(cond: boolean, name: string, detail?)`
- 7 个测试文件（budget / report / trace / observability / security-control / evidence-collector）：
  本地定义 `check(name: string, cond: boolean, detail?)`

两者**参数顺序相反**。写错时 TypeScript 只在类型不匹配处报错（string vs boolean），
而 `check("描述", cond)` 在 harness 里会变成"条件是字符串恒真"——**假绿**。

本次就踩了一次：按 harness 的签名写进 `report.test.ts`，tsc 报错才发现该文件用的是本地签名。

**没有统一的理由，也没有统一的计划**。建议后续把 7 个本地定义都删掉、统一用 harness，
但那是 241 处调用点的机械改动，不适合混在功能性提交里。

## 5. P14 为什么只能记 INSUFFICIENT_EVIDENCE

四类未知情形里，U1/U2 好构造（打个知识库未收录的组件），但：

- **U3（工具缺失）**没有对应开关，要新加环境变量
- **U4（异常响应）**需要一个返回畸形响应的靶，要自建 mock

硬跑只能造假数据，所以按 `00-索引` §5 的规矩记 INSUFFICIENT_EVIDENCE，不判 PASS 也不判 FAIL。
