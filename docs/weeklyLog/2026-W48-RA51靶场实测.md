**真跑才暴露的问题，共六条**（都在 `lab.sh` 里改掉）：

1. 无条件 `sudo` 会弹密码；verify 重定向了输出，没人应答的提示看起来和挂起一样 → 改为只在 `docker info` 失败时才提权
2. compose v2 拒绝带点的项目名（`fastjson-1.2.47`）→ `project_name` 归一化
3. 按容器名剥尾部索引会留下 service 名，项目比较永不匹配 → 改用 `com.docker.compose.project` label
4. `stop_project` 用 label 删容器与网络，不依赖 compose 文件（vulhub 根目录没有 compose）
5. 半创建的容器占着端口 → verify 开跑前先清残留
6. `labs.txt` 里 `struts2/S2-045` 实际目录是小写 `s2-045`；`fastjson/1.2.45-rce` 根本不存在

**第 2、3 条特别值得记**：它们都属于"看上去像环境坏了"。项目名被 compose 拒绝时输出在 `compose up` 里，
而那时输出已被重定向；项目名比较失败则让"先停掉别的靶"变成空操作，下一个靶撞 8080。
两者都会让人去查镜像、查 Docker 服务，而真凶全在脚本里。
