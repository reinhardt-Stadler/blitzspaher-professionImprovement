### [2026-11-10] - 补 P12 / P13 两条行为级验收

**更改方面**：`3验收/04-新增验收P1-P14.md`、`3验收/00-索引.md`、`2规格/00-索引.md`、`docs/README.md`

**类型**：A

**详细描述**：

上一条留的欠账——规格有了 `ErrorKind` 与 `objective_met`，但没有能判"分类对不对""完成没完成"的验收项。补两条：

| 项 | 判据要点 | 关键反证 |
| --- | --- | --- |
| **P12 工具失败分类** | 六值各注入一次且互斥；`failed` 缺 kind 按 `tool_crash` 落告警；无效调用率分母不含 `I4` | `target_unreachable` 连续 2 次后 `toolHealth=degraded` 而**非** `unavailable`（靶场重启不得判工具报废） |
| **P13 目标达成判定** | 假设全闭环 + 覆盖率达标 → `objective_met`；报告分组呈现；同配置重跑两次均须成立 | 覆盖率达标但仍有 `open` 假设 → **不得**判完成（否则变成"扫完就说做完了"） |

- 两项均标 **B 档必做**，阶段出口挂 **RA-1**
- `P13` 的覆盖率阈值未冻结前判 `INSUFFICIENT_EVIDENCE`，**不判 PASS、不判 FAIL**
- 依赖 C 项一栏均为"—（判据自足）"，不新增 C 编号
- 文件名 `04-新增验收P1-P14.md` **不重命名**，避免全库引用断链；标题与内容已含 P13

**验收结果**：

- [x] `3验收/04` 标题改 P1–P13，§0 范围表、末尾阶段对应表（RA-1 / RA-5）同步
- [x] `3验收/00` §2 章节表、§6 本期范围（P2/P9/P10/P11/P12/P13）同步，并加不重命名的说明
- [x] `2规格/00-索引` §2：FR-AGENT-04 验收列加 P12/P13，SEC-TOOL-01 加 P12，SEC-STOP-01 加 P13
- [x] 体量：`3验收/04` 182 行，≤200
- [x] 编号纪律：新增 2 个 P 编号（用户批准），**未新增需求 ID、未新增 C 条目**

**关联登记**：无（验收补充，不改需求与决策）

### [2026-11-11] - 定行为归属边界（决策 / 程序 / 控制层 / 持久化 / 人工）

**更改方面**：`2规格/02`、`03`、`04`、`05`、`08`、`00-索引`、`3验收/04`

**类型**：A

**详细描述**：

按运行流程八个环节（解析 → 授权 → 收集 → 事实化 → 假设 → 验证 → 停止 → 报告）过一遍"谁决定、谁实现、谁强制、谁持久、谁批准"，
定下四条判据（封闭集合归程序 / 能否撤回 / 是否需复现 / 是否需跨进程存活）与五处边界。

**五处拍板**：

| # | 决定 | 落点 |
| --- | --- | --- |
| ① | 重复调用指纹改为 `hash(工具 + 参数 + targetStateVersion)`。目标状态变了才解锁（`target_unreachable` 或新增 port/service 使版本 +1），**不做"申诉"通路** | `05` §5.4 / §5.4.1 / §5.4.2 |
| ② | 两本账允许**单向**跨账支取（explore → verify），单次 ≤ verify 剩余 20%、全任务 ≤ 3 次，落 `budget_transfer`；反向禁止 | `05` §5.3.1 |
| ③ | `suggestNext` **不再给排序**，只给候选集与约束。排序就是策略，藏进"软提示"比明说更糟（不可审查） | `03` §3.3 |
| ④ | 假设可 `reopen` **一次**：须给理由、须换参、占一次预算；reopen 后未闭环则 `objective_met` 不成立 | `03` §3.3.1、`04` §4.6 |
| ⑤ | 修复建议必须挂 `Finding.id` **且引用该 Finding 的至少一条证据键**，无引用不入报告 | `08` §8.1 |

**三处边界写明**（此前是糊的）：

| 边界 | 内容 | 落点 |
| --- | --- | --- |
| `verdict` 职权 | 只判**当前假设的处置**，不判下一条假设是哪个；`StepVerdict` 不得出现工具名 / 参数值 / 排序 | `04` §4.4 |
| `phaseOf` 代价 | 阶段由事实派生，模型不能宣布；事实不动阶段不动——**这是有意的**，不是 bug | `04` §4.2 |
| `scopeAmendment` 发起方 | 模型只能经 `ask_user` 提议，**不得先探一步再报**；先探一寸即已越界 | `03` §3.1.1 |

**持久化随之补两项**：`KernelState` 加 `targetStateVersion` 与 `counters.transfersUsed`；
`state.jsonl` 事件类型 8 → 10 类（加 `hypothesis_reopened`、`budget_transfer`）。
不加这两个字段，恢复后重复判定会误拦、预算余额会错。

**验收结果**：

- [x] 体量：`02` 117、`03` 159、`04` 145、`05` 152、`08` 190，全部 ≤200
- [x] `P12` 补判据⑥（版本解锁前后对照：同参先拒、版本 +1 后放行并标 `RESURRECTED_RETRY` 且不计重复），证据加一条跨版本同参记录
- [x] `00-索引` §1 三行、§2 两行（FR-AGENT-02 / SEC-BUDGET-01）同步
- [x] 未新增需求 ID、未新增 C 条目；新增 2 类事件
- [ ] 待评：跨账支取的 20% / 3 次为初值，须首次试跑后随 OQ-09 一并冻结

**关联登记**：无（规格内部边界收敛；未改需求条目本体与 ADR）
