# 验收 06 · 约束条目（C01–C36）

> **这是"约束体系"的正文。** 约束条目（C）是**性质级**要求：任何一次实现都必须成立，
> 与"某个任务跑通没有"无关。C 项不通过时，P/R 项的结果不可信——因为跑通可能是靠一个已经歪掉的架构蒙对的。

## 1. 约束条目的写法

一条约束必须包含四样东西，缺一样就不许立：

| 要素 | 要求 | 反例 |
| --- | --- | --- |
| 可判定的一话 | 能回答"怎么算违反" | "架构要清晰"（不可判定） |
| 规格出处 | 哪份文档哪节规定的 | 无出处的约束 = 拍脑袋 |
| 验收挂钩 | 被哪个 P/R 项间接验证，或用哪条单测 | 只写"应当" |
| 判定方式 | 单测 / 静态扫描 / 类型断言 / 走查 | "人工检查"（除非确实无法自动化） |

## 4. 怎么用这张表

1. **每次提交**：跑能自动化的 C（单测 + 扫描），红了先修，别往下走。
2. **阶段出口**：确认本阶段挂钩的 C 全绿，再跑对应 P 项。
3. **里程碑**：R 项 + P 项 + C 项三张表都过，才算阶段完成。
4. **发现新性质**：补一条 C，写清四要素，同步登记到 `00-索引.md` 的章节表。
