## 1. 结论先说

**「折中档完工」不等于「R1–R5 全绿」。** 它是三件事同时成立：

| 层 | 判据 | 为什么是这一条 |
| --- | --- | --- |
| ① 性质 | 适用的 C 项全部成立 | 性质不成立时跑场景只会得到无法解释的失败（`00-索引` §5 原文） |
| ② 阶段出口 | 本期 7 个 P 项判 PASS | P 是"能不能进下一阶段"的闸门 |
| ③ 里程碑 | R1–R5、R7–R10 **对 T1/T2** 判 PASS 或明确的 FAIL | R 项本期"全部照常"，不因折中档豁免 |

**当前状态（2026-11-28 场景复验后）：① 已判（23 PASS / 1 不适用）、② 已判（6 PASS / 1 证据不足）、
③ 已判（R1/R2/R3/R5/R7/R9 PASS；R4 预植 CVE 命中 2/5，判据保持原样）。**
明细见 [`08-P项判定.md`](08-P项判定.md)、[`09-C项判定.md`](09-C项判定.md)、
[`verify/2026-11-28-场景实测.md`](../verify/2026-11-28-场景实测.md)。

按陛下 2026-11-28 决定，**R4 判据、P14、RA 工作包正文本轮都不再追**：
R4 记实测值不改写判据；P14 保持 `INSUFFICIENT_EVIDENCE`；RA-0.5/5.2/5.3 不补。
这三项不阻塞"全量档实现完毕"的结论。

## 2. 三条判定规则（照抄既有约定，不新增）

1. **范围外的项记 `NOT_APPLICABLE（本期范围外）`，不记 FAIL、不记空**（`00-索引` §6）。
2. **数值依赖未冻结 OQ 的项记 `INSUFFICIENT_EVIDENCE`**，不判 PASS 也不判 FAIL
   （`04-新增验收` P6 判据原文）。
3. **`FAIL` 只留给真缺陷**。若某项 FAIL 的根因是"支撑能力不在本期"，那是**规格问题**，
   要改规格而不是改结论——见 §4。
