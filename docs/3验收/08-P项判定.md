## P2 计划可审查

| 判据 | 证据 | 结论 |

| ① 每步动作能挂到某条假设（或明确标 exploratory） | 2026-11-27 补 `execution.hypothesisId`：`P2-assoc2` 里后三次调用为 `H-001`，前三次为 `null`（尚无假设） | ✅ |
| ② 每次计划变更带 `trigger.stepId` | 两靶 run 的 plan 事件：`step=4/15/19/…`，全部非空 | ✅ |
| ③ 两次运行能 diff 出计划差异，且差异点前 fact 不同 | `reconstruct --compare`：A 9 条事实 / B 8 条，**共同 0 条**（两靶目标地址不同，差异从第一条事实起） | ✅ |

**补这一项时修的缺陷**：`decision` 事件在建模假设之前就写了，审计里看不出"某次调用为了验证什么"。
链路是 `ToolTrace.attachHypothesis` → `pending.hypothesisId` → `recordExecution` → 审计字段。

**说明**：`--compare` 的有效性检查会报 `CHECK_ARM_DIFFERS` 与 `CHECK_SAME_CONFIG_HASH` 不通过。
那是**A/B 对照实验**的准入条件，本例是两靶场景对比，不是开/关实验——结论按"diff 存在且差异前事实不同"取，
不引用差分数字作实验结论。

## P11 任务隔离

`kernel-skeleton:176` 起有「任务隔离（P11 前置）」一节，覆盖 `taskId` 反序列化保持与
同进程两任务的计数器/目标集合互不影响。38 项全过。

**限制**：这一节测的是内核状态层。`SecurityControl` 的 `callsUsed` / `allowedTargets` 在
同一进程连跑两任务时的隔离，目前靠 `install()` 每次新建闭包保证，**没有专门的"同进程跑 A 再跑 B"测试**。
真要坐实 P11①，应补一个集成测试：一次 `install` 里连发两轮 tool_call，断言 B 的 `callsUsed` 从 0 起算。

## P14 未知情形处置

**未跑。** 四类（U1 未知组件 / U2 无 probe spec / U3 工具缺失 / U4 异常响应）需要各构造一个场景真跑，
每类看：误报 0、分类正确、报告列出、无静默跳过、U1 先有自主收集动作。

可构造性评估：

| 类 | 构造方式 | 难度 |
| --- | --- | --- |
| U1 | 打一个知识库未收录的组件（如 `tomcat/CVE-2017-12615` 靶） | 低 |
| U2 | 识别为已知组件但 registry 无对应 spec（tomcat 即属此类） | 低 |
| U3 | 需要一个"工具不可用"的开关，当前无对应环境变量 | 中（要加开关） |
| U4 | 需要一个返回畸形响应的靶 | 中（要自建 mock） |

按判据 ④「无静默跳过」和 ⑤「U1 必须先有自主收集动作」，U1/U2 能一次跑完；
U3 缺环境变量、U4 缺靶，硬跑只能造假。**所以本项记 INSUFFICIENT_EVIDENCE，不记 PASS 也不记 FAIL**
（`00-索引` §5 的规矩：证据不够判时这样填）。
