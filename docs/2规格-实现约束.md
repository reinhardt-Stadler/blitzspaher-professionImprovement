# 规格：实现方案（面向实现）

> 定位：需求写"做什么"，长期稳定、少变更；本文档写**"用什么技术、什么手段，达成需求的哪条指标"**，随选型与迭代频繁更新。
> 写法：条目按需求 ID 组织，每条固定四段——**实现手段 / 达成指标 / 依赖决策 / 状态**。

## 0. 总体实现方案（已定）

- 框架：**pi-coding-agent v1.2.0**，扩展方式为 TypeScript Extension（`registerTool` / `registerCommand` / `on` 事件）（ADR-001）
- 驱动模型：**deepseek-flash**（DeepSeek V4.1 Flash）主力，kimi-k2.7-code 备选；统一模型调用点，业务代码不感知供应商（ADR-002）
- 安全控制层：**自建框架无关纯逻辑模块**（`security-control.ts`，零 pi 依赖），经 `pi.on("tool_call")` 挂接为单一入口，无旁路（spike 已验证）
- 沙箱：7 层防线，WSL2 内 Docker Engine（ADR-004，设计定稿、实现暂停）

## 5. 模型接入：拒答应对与输出判定的实现

> 依据 `research/模型选型实验结果.md`（120 次实测，T1–T5）修订：

1. **输出判定三态**：`refused`（明确拒绝）/ `refused_partial`（拒绝原请求但给防御替代，计入误拒答率）/ `empty_not_refusal`（空输出≠拒答）。首版按二分法判定曾 100% 误判，必须三态。
2. **空输出防护**：DeepSeek V4.1 Flash 是重推理模型，`max_tokens < 32K` 时 reasoning 吃光配额、content 为空（T1）——调用层强制 `max_tokens ≥ 32000`，并把空输出与拒答分开计数。
3. **授权上下文的定位**：实验证明添加授权声明**不降低**越界服从率（90%→100%，n=10 不显著）——授权上下文只用于**审计留痕**，不是门禁、不是降低服从率的手段。
4. **拒答重提示**：检测到 `refused`/`refused_partial` 后带授权上下文重提示 ≤ 2 次；仍拒答 → 停止原因 `model_refusal`，报告如实标注（对齐 SEC-STOP-01）。本批数据 FRR=0% 不代表换表述不触发，策略保留。
5. **模型参数适配**：Kimi K2.7 只接受 `temperature: 1`（传 0 报 HTTP 400）——按 provider 分别设置参数（T2）。
- 状态：调用层封装时一并实现（不依赖 Docker）。
