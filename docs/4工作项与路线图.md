# 工作项与路线图（层级 × 模块 × 阶段）

> **定位**：计划类更新的唯一入口。工作项进度、OQ 开闭、依赖变化一律更新本文并登记 §7。
> **组织方式**：同一模块的全部工作集中在一列，同一阶段的全部工作集中在一行，格子里是可独立提交的工作包。
> **配套**：规格见 `2规格/00-索引.md`；验收见 `3验收/00-索引.md`；设计与排期理由见 `design/agent-refactor/06-阶段总览与风险.md`。

## 0. 工作包定义与拆分规则

**一个工作包 = 一次可独立提交的改动**：改完能单独验收，不依赖任何未完成包。

| 规则 | 内容 |
| --- | --- |
| 大小 | 改动文件 ≤3 个；能在一次评审里讲完 |
| 必填字段 | 包号 / 范围（折中档·全量档）/ 内容 / 产出 / 验收挂钩 / 依赖 / 明细链接 |
| 验收挂钩 | 必须指向 R / P / C 之一；**写不出挂钩的包不许立项** |
| 依赖 | 只写包号或 OQ 号；依赖未实测的 OQ 时，该包**只能出方案不能出代码** |
| 禁止 | 一个包里混「修缺陷」与「加能力」——前者要回归证明，后者要新证据，验收口径不同 |

**该拆的信号**（任一成立就拆）：

1. 验收判据超过 3 条且互不相关；
2. 改动跨越两个模块（M1–M7）；
3. 依赖不同 OQ 的实测结论。

**编号**：`RA-<阶段>.<序号>`，序号在阶段内连续、不回收；包被取消时保留编号并标 `cancelled`，
避免历史引用指向别的内容。

**不在本表的东西**：探索性调研记 OQ，文档纯整理记周志，跨阶段的决策变更走 DCR。

## 5.1 为什么先做折中档（2026-11-10 决定）

| 范围 | 包数 | 拿到的验收 | 放弃的 |
| --- | --- | --- | --- |
| 最小档 | 6 | R1/R2/R4/R5/R7/R9/R10 | R3 只有弱证据、暂停恢复、模型看不到计划 |
| **折中档（本期）** | **17** | 上述 + **R3 强证据**（plan + trigger）+ P2 / P9 / P10 / P11 / P12 / P13 / P14 | 跨进程恢复、记忆回注、TargetModel、动态工具、回连 |
| 全量档 | +13 | 全部 P1–P14 | — |

**选折中档的三条理由**：

1. 它修掉一个**已存在的 bug**：`index.ts:96` 的 policy 在扩展加载时构建一次，同进程第二个任务会继承  
   第一任务的 `taskId` / `authorizedTargets` / `callsUsed`，且上一任务的调用指纹会被判 `DUPLICATE_CALL`。  
   折中档的 RA-1.2「状态按任务重建」解决它，**不需要**落盘。
2. 它拿到 R3 的强证据。R3 的判据是"决策由前序 Observation 驱动"，  
   弱记录只能答"前一步是什么"，答不了"它当时在验证什么假设"。
3. 暂停恢复、记忆回注、动态工具、回连都属于"有能力更好、没有也能交"。  
   **全量档是做给未来的，不是做给验收的**——这条要写清楚，避免以后被当成欠账。

**升全量档的触发条件**（任一成立就重开范围讨论）：

- 单次任务规模超过一个进程能撑住的量（T2 级"只给目标"任务会出现）；
- 出现"跑一半停、明天继续"的明确要求；
- 需要跨任务复用经验（RA-4.3）。
