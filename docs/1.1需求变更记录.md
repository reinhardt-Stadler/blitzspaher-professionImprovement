# 需求变更记录（对抗驱动）

> 机制（指导意见第 6 条）：对抗组不再以"挑错"形式协作，而是以**需求变更**形式发起——
> 例：原来只有 CLI → 新增前端界面；原报告为自研格式 → 新增 Excel 导出。
> 考察目标：我方能否快速、有序地响应需求变更。

## 变更单模板

| 字段 | 说明 |
| --- | --- |
| 变更编号 | CR-001 递增 |
| 发起方 | 对抗组 / 组内自查 |
| 变更描述 | 一句话说清要什么 |
| 影响范围 | 涉及的需求 ID / 规格 C-* / 验收 R* |
| 期望响应 | 交付物 + 时间盒 |
| 实际响应 | 改动摘要 + git 提交范围 |
| 复盘 | 响应过程的顺畅度与教训 |

## 变更记录

| 编号 | 描述 | 状态 |
| --- | --- | --- |
| （暂无） | 新文档骨架（四层结构）完成后，首次同步对抗组时可请对方按本模板发起第一个变更 | — |

## 流程

1. 对抗组提交变更单 → 2. 我方评估影响范围并回填时间盒 → 3. 实现并交付 → 4. 回填实际响应与复盘 → 5. 若影响需求/验收条目，同步更新 01-需求 / 03-验收 并标注版本。
