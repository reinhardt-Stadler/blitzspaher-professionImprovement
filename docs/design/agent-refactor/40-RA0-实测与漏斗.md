## RA-0.1 pi 能力实测（OQ-14）⏸

**为什么第一**：`00-索引.md` 的卡点表列了 7 条设计卡在这五项上。不先测，后面每条都要带"如果……否则……"双分支，代码没法写。

**方法：先静态读类型定义，再运行时验证。** 五项里至少四项能直接从 `.d.ts` 读出，只有钩子触发时机必须跑。

```bash
# 0) 定位包与版本
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "npm root -g; cat $(npm root -g)/@earendil-works/pi-coding-agent/package.json | jq -r .version"

# 1) 列全部公开类型与钩子名
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "find $(npm root -g)/@earendil-works -name '*.d.ts' | head -50"

# 2) 找上下文/系统提示注入点（Q1）
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "grep -rn 'systemPrompt\|system_prompt\|beforeMessage\|contextInject\|onContext' \
   $(npm root -g)/@earendil-works --include='*.d.ts' | head -40"

# 3) 找内置工具禁用/排除机制（Q2）
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "grep -rn 'disableTool\|excludeTool\|builtinTool\|allowedTools' \
   $(npm root -g)/@earendil-works --include='*.d.ts' | head -40"

# 4) 看 defineTool 的 details 类型说明（Q3）
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "grep -rn -A6 'details' $(npm root -g)/@earendil-works/pi-coding-agent/dist/*.d.ts | head -60"

# 5) 找子代理/并行 loop（Q4）
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "grep -rni 'subagent\|sub-agent\|spawn\|delegate\|parallel' \
   $(npm root -g)/@earendil-works --include='*.d.ts' | head -30"

# 6) 看 usage 类型（Q5）
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "grep -rn -A10 'interface.*Usage\|type.*Usage' $(npm root -g)/@earendil-works/pi-ai/dist/*.d.ts | head -60"

# 7) 运行时只需验两件静态读不出来的：
#    A. block 之后 tool_result 是否仍触发（Q6，决定记账逻辑怎么写）
#    B. 能否让 pi 完全不加载内置工具（决定 Q2 分支）
pi --extension ./src/index.ts --no-extensions --help | grep -i tool
```

## RA-0.2 漏斗白名单化 ✅

**目标**：`authorize_call` 从"白名单内拦"变成"默认拒绝 + 显式放行"，覆盖整个执行面。

| 文件 | 位置 | 改什么 |
| --- | --- | --- |
| `src/index.ts` | `:54` | `PENTEST_TOOLS` → `ALLOWED_TOOL_NAMES = new Set([...TOOL_REGISTRY.map(t=>t.name), "pentest_report", "evidence_collector"])` |
| `src/index.ts` | `:177-220` | 不在 `ALLOWED_TOOL_NAMES` 的直接 `block + audit(decision=deny, code=BUILTIN_TOOL_DENIED)` |
| `src/index.ts` | `:223-234` | `tool_result` 过滤条件同步改；按 Q6 结论决定"是否以裁决结果为准" |
| `src/index.ts` | `:126-174` | 三个工具注册不动（表驱动留给 RA-2.3）；`pentest_report`/`evidence_collector` 纳入裁决——两者无 `target` 参数，`security-control.ts:216` 的 null 短路行为要保持 |
| `test/builtin-bypass.test.ts` | 新建 | 五类事件：授权工具 allow、注册未授权 deny、内置 bash deny、内置 read deny、未知工具 deny |

**验收判据**

1. 容器内直接 `curl http://target:8090` 走内置 bash → `decision: deny, code: BUILTIN_TOOL_DENIED`，**执行侧 0 次到达**（用靶场访问日志反证）。
2. 五类事件全部有 `toolCallId`，`reconstruct` 能聚合成时间线且不产生 `GAP_EXECUTION_WITHOUT_DECISION`。
3. `callsUsed` 不因拦截而增加（`pipeline.ts:104` 的 `authorized` 门闩继续生效）。

**风险**：禁用内置 bash 后 Agent 失去通用 shell（ADR-006 后果 1）。**合并前必须确认三条探测链路能覆盖现有靶场任务**，否则不要合。
