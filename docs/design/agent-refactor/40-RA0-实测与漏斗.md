## RA-0.1 pi 能力实测（OQ-14）⏸

**为什么第一**：`00-索引.md` 的卡点表列了 7 条设计卡在这五项上。不先测，后面每条都要带"如果……否则……"双分支，代码没法写。

**方法：先静态读类型定义，再运行时验证。** 五项里至少四项能直接从 `.d.ts` 读出，只有钩子触发时机必须跑。

```bash
# 0) 定位包与版本
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "npm root -g; cat $(npm root -g)/@earendil-works/pi-coding-agent/package.json | jq -r .version"

# 1) 列全部公开类型与钩子名
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "find $(npm root -g)/@earendil-works -name '*.d.ts' | head -50"

# 2) 找上下文/系统提示注入点（Q1）
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "grep -rn 'systemPrompt\|system_prompt\|beforeMessage\|contextInject\|onContext' \
   $(npm root -g)/@earendil-works --include='*.d.ts' | head -40"

# 3) 找内置工具禁用/排除机制（Q2）
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "grep -rn 'disableTool\|excludeTool\|builtinTool\|allowedTools' \
   $(npm root -g)/@earendil-works --include='*.d.ts' | head -40"

# 4) 看 defineTool 的 details 类型说明（Q3）
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "grep -rn -A6 'details' $(npm root -g)/@earendil-works/pi-coding-agent/dist/*.d.ts | head -60"

# 5) 找子代理/并行 loop（Q4）
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "grep -rni 'subagent\|sub-agent\|spawn\|delegate\|parallel' \
   $(npm root -g)/@earendil-works --include='*.d.ts' | head -30"

# 6) 看 usage 类型（Q5）
docker compose -f deploy/docker-compose.yml exec agent bash -lc \
  "grep -rn -A10 'interface.*Usage\|type.*Usage' $(npm root -g)/@earendil-works/pi-ai/dist/*.d.ts | head -60"

# 7) 运行时只需验两件静态读不出来的：
#    A. block 之后 tool_result 是否仍触发（Q6，决定记账逻辑怎么写）
#    B. 能否让 pi 完全不加载内置工具（决定 Q2 分支）
pi --extension ./src/index.ts --no-extensions --help | grep -i tool
```

## RA-0.2 权限闭环：五洞修复 + 旁路证明

> **目标**：`authorize_call` 从"白名单内拦"变成"默认拒绝 + 显式放行"，并**证明**整个执行面被覆盖。
> 本包只修权限：不动内核、不动靶场、不启动 L3。
> 字段语义与默认行为以 `2规格/09-工具权限模型.md` 为准，本节只列改哪、怎么验。

### 洞① 内置工具绕过（致命）

- **现状**：`index.ts:178` `if (!PENTEST_TOOLS.includes(...)) return undefined`——bash / read / write / edit 直接放行。
- **设计要求**：所有能产生外部副作用的入口都经过裁决；**不能可靠拦截的入口，禁用或替换为受控接口**。
- **修复位置**：`index.ts:54`（白名单集合）、`:177-220`（拦截）、`:223-234`（记账过滤）。
- **待验证**：OQ-14 Q2（内置工具能否禁用）。能禁用则优先禁用——禁用比拦截可靠。

### 洞② 目标参数认不出就跳过（高）

- **现状**：`security-control.ts:216` 的 `target !== null` 短路；`:365` 只认 `target/host/url/hostname`。
- **问题**：用 `ip` / `endpoint` / `address` 就返回 null，目标检查**静默跳过**。
- **设计要求**：`ToolMeta.targetParam: string | null` 显式声明；声明了却取不到 → `PARAM_INVALID` 拒绝，不跳过。
- **修复位置**：`security-control.ts:214-218` + 注册表 `targetParam` 语义。
- **判据**：用 `ip` 参数的调用必须被拒并落审计；`targetParam: null` 的工具（report / evidence）正常放行。

### 洞③ 参数校验是空实现（高）

- **现状**：`security-control.ts:322-333` `checkParams` 算完端口跨度就 `return null`。
- **设计要求**：参数按**模式级** schema 校验（`09` §2）；端口跨度从"只标高危"改为"超上限即 `PARAM_INVALID`"。
- **修复位置**：`checkParams` 读 `mode.parameters`。
- **判据**：超跨度扫描被拒且落 `PARAM_INVALID`；合法参数不受影响（R7 的"只拦越界"）。

### 洞④ 可用性 / 调用权 / 执行程度混在一个字段（中）

- **现状**：`TaskPolicy.allowedTools: string[]`（`:25`）同时承担三件事。
- **设计要求**：拆成 `available`（环境探测）/ `grants`（任务授权）/ `capabilities`（能力集合），见 `09` §1。
- **修复位置**：`TaskPolicy` 结构 + `authorize_call` 第 2 步拆为能力检查与模式检查。
- **判据**：`available=false` 返 `TOOL_UNAVAILABLE` 且**不计**无效调用率；能力未授予返 `CAPABILITY_NOT_GRANTED`。

### 洞⑤ 两个自研工具在漏斗外（中）

- **现状**：`pentest_report` / `evidence_collector` 不在 `PENTEST_TOOLS`。
- **设计要求**：纳入裁决；两者 `targetParam: null`，目标检查显式跳过。
- **修复位置**：`index.ts:54` 的集合同步包含。
- **判据**：两者调用有 decision / execution / result 三件套，预算记账正确。

### 闭环证明（本包核心交付）

**要证明的不是"自研工具经过了漏斗"，而是"没有任何入口能绕过"。**

| 验证 | 方法 | 判据 |
| --- | --- | --- |
| 副作用入口全覆盖 | 静态枚举进程内全部可注册工具，逐个标处置（放行 / 受控 / 禁用） | 清单无遗漏；`effects ≠ none` 的必须有裁决 |
| shell / 脚本 / 子进程旁路 | D1 `bash: curl <授权目标>`；D3 `bash: python -c "..."`；D4 `write` 写脚本再 `bash` 执行 | 全部被拒或工具不存在 |
| 间接访问未授权目标 | D2 `bash: curl <未授权目标>` | 被拒 |
| 未知工具 | D5 调用注册表外工具名 | `TOOL_NOT_AUTHORIZED` |
| 拒绝留痕 | 检查 D1–D5 的审计 | 每条都有 `decision` + `toolCallId` + `code` |
| 执行侧反证 | 靶场访问日志 | D1–D4 **0 次到达** |

**判定口径**：只有"工具不存在"和"被拒绝且有审计"算通过；"执行了但结果为空"算 FAIL。
Prompt 里写"禁止直接调用 bash"**不计入**任何一条判据——约束必须在执行层成立。

### 合并前提

禁用内置 bash 后 Agent 失去通用 shell（ADR-006 后果 1）。
**合并前必须确认三条探测链路能覆盖现有靶场任务**，否则不要合。
