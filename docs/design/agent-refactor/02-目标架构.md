## 1. 目标架构

```
┌──────────────────────────────────────────────────────┐
│ 用户接口层：任务下达 / 澄清 / 能力授权 / 计划与进度可视      │
└───────────────────────┬──────────────────────────────┘
                        ↓
┌──────────────────────────────────────────────────────┐
│ Agent 内核（零 pi 依赖，ADR-005）                        │
│  任务状态机 · 显式计划(plan) · 假设清单 · 重规划           │
│  运行时记忆(台账回注) · TargetModel(认知层，关系型)        │
│  结果三态判定 · 停止决策 · 经验沉淀                       │
│  —— 全部状态可序列化、可恢复（状态外置）                   │
└───────────────────────┬──────────────────────────────┘
                        ↓ 仅通过明确接口驱动
┌──────────────────────────────────────────────────────┐
│ pi 执行宿主（ADR-001 角色收窄，DCR-002）                  │
│  agent loop / 工具 schema / 会话 / UI 确认               │
└───────────────────────┬──────────────────────────────┘
                        ↓ tool_call 单一漏斗（含内置工具）
┌──────────────────────────────────────────────────────┐
│ SecurityControl + Budget（判定层，保留封闭枚举事实口径）    │
└───────────────────────┬──────────────────────────────┘
                        ↓
┌──────────────────────────────────────────────────────┐
│ 工具层：注册表驱动（表驱动自动注册）                       │
│  预置工具 · 知识驱动探测器 · 动态生成工具(隔离执行)         │
└───────────────────────┬──────────────────────────────┘
                        ↓
┌──────────────────────────────────────────────────────┐

│  + 回连通道（靶→agent 反向，独立授权档）                   │
└──────────────────────────────────────────────────────┘
```

## 2. 三条分层原则

### 原则一：认知层 / 判定层分离

`host/port/service/version/path/cve` 扁平封闭枚举**保持不变**，
继续服务无效调用判定、R4 召回率、`phaseOf`、报告（它们已被验收定义冻结）。
关系型 `TargetModel` 是新增的认知层，仅供规划与覆盖率计算使用。**不允许直接改枚举**。
理由与实现见 `04-难点与扩展点索引.md` B4、`12-器官-状态建模与执行判定.md` §1.6。

### 原则二：内核零依赖

照 `security-control.ts` 先例，内核不 import 任何 pi API，可离线单测、可迁移宿主。
落地形态：`src/pi-pentest/src/kernel/`（同仓子目录，2026-11-10 定）。

### 原则三：循环归 pi、边界归内核

模型决定**这一步调哪个工具、传什么参数**；内核只决定**当前阶段、这个调用放不放行、
预算够不够、要不要停、状态怎么存**。

**内核不产出工具调用指令。** 否则与 pi loop 里的模型形成两个 planner：
内核说了算 → pi 被架空成 HTTP 客户端（等于自研框架）；模型说了算 → 内核计划沦为装饰。
两条都不可接受。分工表、越界线五条与"何时该真砍掉 pi"见 `05-与pi分工与硬约束.md`。

## 3. 一句话概括当前与目标

现在是一套很强的"执法与取证系统"，套在通用 coding agent 的裸循环上；
缺的是脑（规划/记忆/知识）、感知（状态建模/结果判定）、更长的手（动态工具/回连）。
