# 30 · 扩展点：具体扩法

> **位置**：参考层 · 覆盖 `04-难点与扩展点索引.md` §2 的十个扩展点
> 上游：`04-难点与扩展点索引.md`　下游：`44`（表驱动）、`46`（决策矩阵）
> 每条固定三段：承重结构在哪 → 怎么扩 → 扩的时候会踩什么

## 3.1 `authorize_call()` 判定序

**承重**：`security-control.ts:173`，纯函数、除审计写盘外无 IO，21 项单测现成。

**怎么扩**：
- 插 `authorizationLevel` 检查：**在 `stopped` 之后、预算之前**（归因要准确，见 §3.1 末）。
- 插两本账：替换现有 `callsUsed >= maxCalls` 那段，改问 `PhaseAllocator`。
- 重复判定改分级：`seen: Set<string>` → `Map<string, {count}>`，并在返回值加 `code=EXPLORATORY_RETRY`。
- `Decision` 类型已能承载（`allowed/code/reason/needsHuman`），**不需要改类型**。

**会踩什么**：新增的 `code` 必须同步进 `report.ts:216` 的 `buildCoverage`（它把 deny 事件写进"未执行项"），
否则报告里原因是 `UNKNOWN`。这是 B3 五步清单的一个具体实例。

## 3.2 `Observation` 统一结构

**承重**：`tools.ts:23-33` 六个字段；`pipeline.ts:126` 的 `asObservation` 靠
`"evidence" in details && "summary" in details` 判定。

**怎么扩**：
- 加字段一律可选（`rawOutput` 已是这个模式），旧 `observations/*.obs.json` 缺字段时消费者降级。
- **上下文分层的落点就在这**：`content` 只放 `summary`，`details` 放全量。

**会踩什么（最容易踩的一个）**：如果 `details` 改成 `{obsRef, artRef}`，`asObservation` 不再匹配，
`obs` 为 null → `observationRef` 为空 → `reconstruct` 报 `GAP_MISSING_OBSERVATION_REF`，**记账静默失效**。
改这里必须同时改判定条件（改判 `"obsRef" in details`），并用回归用例锁住。

## 3.3 `observationRef` / `artifactRef`

**承重**：`observability.ts:59`（`ObservationStore.save`）、`evidence-collector.ts:177`（`addFile` + `kind`）

**怎么扩**：新证据类型（生成代码、回连日志、plan 快照）复用同一命名空间，
`artifacts/<runId>/` 扩成子目录 `artifacts/<runId>/{tool,generated,callback}/...`；
`kind` 由路径前缀决定，避免调用方逐个传；`manifestVersion` 1→2，`counts` 增加对应计数。

**会踩什么**：`walkFiles` 是递归的，加子目录不改代码也能打包——但 `counts` 会算错（现在只数 `artFiles.length`）。
要改的是统计，不是打包。

## 3.4 `TOOL_REGISTRY`

**承重**：`tools.ts:44-63`（3 条元数据，无 schema）、`index.ts:54`、`index.ts:126-174`（三段手写注册）

**怎么扩**：

```ts
// tools.ts —— 保持零依赖，schema 用 JSON Schema 纯数据
export interface ToolMeta {
  name: string;
  category: "scanner" | "web_probe" | "vulnerability_check" | "evidence_collector"
          | "knowledge" | "callback" | "generated";
  description: string;
  targetParam: string;
  parameters: JsonSchemaObject;            // 新增
  levels: AuthorizationLevel[];             // 新增：哪些档位可用
  account: "explore" | "verify" | "none";   // 新增：记哪本账
}
```

```ts
// index.ts —— 一段循环替代三段样板
for (const meta of TOOL_REGISTRY) {
  pi.registerTool(defineTool({
    name: meta.name, label: meta.name, description: meta.description,
    parameters: jsonSchemaToTypeBox(meta.parameters),
    async execute(_id, params) { return toToolResult(await TOOL_IMPL[meta.name]!(params)); },
  }));
}
```

**会踩什么**：TypeBox 是 pi 的依赖，`tools.ts` 一旦 import 就失去零依赖属性。
转换函数**必须放 `index.ts`**，`tools.ts` 只存 JSON。硬约束，不是风格偏好。

## 3.5 `BudgetTracker` 四维取最紧 + 水位通知

**承重**：`budget.ts:99`（`usage()` 取 `tightest`）、`budget.ts:140`（`markNotified` 去重）

**怎么扩**：阶段/假设预算在外层包一层 `PhaseAllocator`，**不改内核**；
收束期白名单 `EVIDENCE_TOOLS`（`budget.ts:227`）要加新类别（`knowledge_query`、`callback_watch`）。

**会踩什么**：`level()` 只看 `tightest`。若阶段配额耗尽但全局健康，`level()` 仍返回 `normal`，
报告里会出现"预算健康但任务停了"。建议报告单列"阶段配额耗尽"，而不是把配额塞进 `tightest`（会让语义混乱）。

## 3.6 `report.ts` 固定模板 + 单测

**承重**：`report.ts:122`（`extractCveFindings`）、`report.ts:362`（`renderReport`）

**怎么扩**：新增结论维度见 `05-与pi分工与硬约束.md` 硬约束 2（正交维度，不加第五态）。

**会踩什么（两处硬编码）**：
① `extractCveFindings` 硬编码 `e.tool !== "cve_check"` 就跳过——新增验证工具不改这里，报告直接丢结论；
② `buildReproSteps`（`report.ts:165`）硬编码 fastjson 的请求体，新 CVE 会生成**错误的复现步骤**，必须改为从 probe spec 生成。
另：`Finding` 从 `resultSummary` 正则抓 `[CONFIRMED]`（`report.ts:130`），summary 改一个字就静默丢结论。
建议改读 `Observation.evidence.conclusion`（`tools.ts:534` 已有该字段），正则只做兜底。

## 3.7 `evidence-collector` MANIFEST / gaps

**承重**：`evidence-collector.ts:161-279`，`gaps` 是"缺失如实记录"的机制。

**怎么扩**：新证据类型作为 `addFile` 的新 `kind` 接入；缺失时 `gaps.push`；
包内 `README` 的复核指引加一步（"看 plan 快照：plan/snapshot-<seq>.json"）。

**会踩什么**：`readAuditEvents` 靠"最后一条事件的 runId"判断当前运行（`:147`）。多任务并行后会取错。
`--run` 显式指定是必须的，不能靠默认。

## 3.8 `reconstruct --compare`

**承重**：`reconstruct.ts:467` `compareRuns`，4 项对照有效性检查。

**怎么扩**：新指标加进 `metrics: MetricDelta[]`（一行一个）；plan 相关指标需先让 `plan` 事件进 `TimelineStep`
（现在只认 decision/execution/human 三类）。

**会踩什么**：`divergence` 按调用指纹逐位比较。plan 事件不产生指纹，加进去后路径分叉语义会模糊
——建议 plan 事件单独出一条 `planDivergence`，不要混进 `divergence`。

## 3.9 `knowledge/generated/index.json`

**承重**：124KB，`entries[].{slug,path,component,cve,title,lang,bytes}`

**怎么扩**：检索工具即接（字段够用）。若要做"版本→受影响"匹配，需在索引补结构化版本区间
——**但源数据没有**（`version` 大量为 null），要么回填索引，要么从正文抽。

**会踩什么**：124KB 整体塞进模型上下文约 30K+ token。只让模型看检索结果摘要。

## 3.10 审计事件 `kind` 枚举

**承重**：`security-control.ts:65`（联合类型）、`reconstruct.ts:181`（按 kind 分桶）、`report.ts` 多处 `e.kind ===`

**怎么扩**：走 `21-难点-结构性债.md` B3 的五步清单，一步不能省。

**会踩什么**：`kind` 是联合类型但消费方用 `===` 比较——新增 kind 不报编译错，只静默不被消费。
这正是为何要 contract test 而不是靠类型系统。
