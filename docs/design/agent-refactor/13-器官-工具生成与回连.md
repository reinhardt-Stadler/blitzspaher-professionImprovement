## 1.8 工具生成 🔴（OQ-15）

**现状**：`tools.ts` 用 `execFile(cmd, [args])` 调 nmap/curl，不拼 shell；工具集是编译期固定的三个函数。
无任何动态生成能力。

**目标**：Agent 能在"没有现成工具时自己造一个"，但造出来的东西可审查、可复现、可复用。

### 能确定的部分（本文写死）

管线四段，人工确认只发生在第三段：

```text
生成(模型写代码) → 静态审查(确定性规则) → 首次注册(人工确认一次) → 复用(不再确认)
```

静态审查规则（确定性、可单测，与隔离宿主选型无关）：

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 只允许 import 白名单模块（注入的 `ToolContext` 及其类型） | 阻断自建网络栈 |
| R2 | 禁止 `child_process`/`net`/`dgram`/`http`/`https`/`fs` 直接引用 | 一切 IO 走 `ctx.http`，它自带授权校验 |
| R3 | 禁止 `eval` / `new Function` / `vm` | 阻断审查绕过 |
| R4 | 必须导出 `run(ctx, args): Promise<Observation>` | 保证可被调度 |
| R5 | 必须有 JSON Schema 参数声明，且每次请求目标要能被 `extractTarget` 解析 | 让授权检查有抓手 |
| R6 | 体积上限（建议 ≤ 200 行 / ≤ 16KB） | 控制审查成本 |
| R7 | 代码文本 + sha256 入证据包 | NFR-01 可重复性 |

执行宿主抽象（选型留给 OQ-15，接口现在定）：

```ts
export interface ToolHost {
  run(code: string, args: unknown, limits: {
    cpuMs: number; memMB: number;
    net: { allow: string[]; deny: string[] };   // 默认 deny all，仅放开 policy.allowedTargets
  }): Promise<{ observation: Observation; logs: string[]; exit: "ok" | "timeout" | "error" }>;
}
```

### 未调研，不给方案的部分

具体隔离实现。候选至少三类——Node 权限模型子进程、独立容器、WASM 沙箱——各自能力边界、启动开销、
可用库范围均未实测，按 ADR-000 第 3 条（≥2 候选实测比较）不允许现在定。判定门槛见 `45-RA3-行动与回连.md` §2。

**一个容易漏的点**：C1 要求"确认只发生在首次注册"，意味着确认对象是**代码**而不是**调用**。
所以确认界面必须能展示代码 diff 与静态审查报告，否则"确认"是形式主义。

## 1.9 利用与回连验证 🔴（OQ-16）

**现状**：只有无损特征探测。`tools.ts:196` 明确"不发送任何攻击 payload"；三靶场报告 §1 有专门的无害性说明。
报告结论只有四态，没有"回连成功"这种强度。

**目标**：在能力授权内增加"靶 → agent"回连验证，但**不承诺**完整 RCE 利用链。

### 能确定的部分（三条，不依赖通道实现）

1. **能力授权语义**：`callback` 能力授予才允许监听与回连类工具；关闭时相关工具在 `authorize_call`
   直接 `deny(code=CAPABILITY_NOT_GRANTED)`。
2. **审计事件**：`callback_watch_start` / `callback_received` / `callback_watch_stop`。
   收到回连必须落：时间、源 IP、方法、路径、头、体前 N 字节、`stateSeq`；原始报文进 `artifacts/`（复用 `artifactRef`）。
3. **验收判据**：能力授予 → 完成一次真实回连，证据可复核；能力未授予 → 回连端口**物理不可达**（不是逻辑拦截）。

### 技术推断（标注为推断，待 OQ-16 验证）

按现有 `docker-compose.yml`：`pentest-net` 是 `internal: true`，**只禁出网，网内互通不受限**；
agent 与三个靶同在该网段。据此推断：**"靶 → agent 高位端口"这条自回连在现有拓扑下不需要改网络**，
只需 agent 侧 bind 一个监听端口（`read_only` + `cap_drop: ALL` 不影响 bind >1024）。

真正需要改网络的是 **dnslog 类外带**——那要经 `proxy`，而 `proxy/filter` 目前只放行模型 API。
所以 C2 的成本被高估的部分是"网络改造"，被低估的部分是"payload 生成与授权"。
**此推断在 OQ-16 实测（容器内 bind + 反向回连）确认前不得写入验收结论。**

### 未调研，不给方案的部分

回连监听器的生命周期与超时、并发上限、payload 由谁生成（动态工具还是预置模板）、
是否需要独立网络命名空间。等 OQ-16。
