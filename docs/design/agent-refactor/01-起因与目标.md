## 1. 为什么重构

项目最初目标是智能渗透 Agent，首版实现收敛为"渗透测试辅助系统"。2026-11-08 组内确认：
**按完整 Agent 的设计标准重新审视并重构，不做局部能力补齐**；无外部时间盒，由组内驱动。

三条实测证据说明差距不在模型，在系统：

**证据一：三靶场"端到端"的 CVE 编号是人填进去的。**
复现命令（`verify/2026-W45-W2三靶场验证报告.md` §9 原文，行号 220）为
"对三个授权目标做漏洞验证：target:8090 用 CVE-2017-18349，shiro:8080 用 CVE-2016-4437，struts2:8080 用 CVE-2017-5638"。
结果：3 次 `cve_check`、3.2 秒、0 次 nmap、0 次 http_probe。
目标上跑什么、可能有什么洞、该验哪一个，全部由人预先完成——系统只承担"工具翻译层 + 证据整理层"。

**证据二：340 条知识库已建好但未接给模型。**
`deploy/knowledge/generated/`（340 条，271 条带 CVE，152 个组件），
而 `grep -rn knowledge src/` **零命中**（2026-11-10 复核）：没有任何工具让 Agent 查询，只能由人在 prompt 里手填 CVE。

**证据三：动态闭环从未被证明。**
MVP-1 条件②（由前序 Observation 驱动的分支决策）在三靶场报告中为 🟡"未构造分支案例"，
同篇结论却写"W2 全面验证通过"。目前全部实测均为直线调用。

**判断**：已建成的 L3 控制层、审计、trace 重建、证据包、预算收束、报告诚实性，是多数渗透 Agent 项目最缺的部分，
**全部保留、不推倒**。缺的是上游：目标理解 → 假设生成 → 真实分支，以及下游：动态工具、受控利用。

## 2. 目标形态

用户以自然语言下达任务并确认授权后，Agent 自主完成
信息收集 → 目标状态建模 → 候选漏洞假设 → 受控验证（含动态生成工具与受控回连）→ 动态调整 → 结论 → 报告，
全程审计，边界由控制层与沙箱强制。

## 3. 仍然不承诺

沿用 v0.3 §1.5，不因重构放开：未知漏洞自动挖掘、任意互联网目标、真实第三方系统、
全自动 CVE 提交、企业级平台、完整 RCE 利用链。

## 4. 本期新增能力范围（2026-11-08 组内确认）

| 能力 | 范围 | 对应设计 |
| --- | --- | --- |
| 动态工具 | Agent 可动态收集 / 编写工具（11.4 构建指引第 4 行） | `13-器官-工具生成与回连.md` §1.8、`22-难点-冲突与验证链.md` C1 |
| 受控回连验证 | 在无损探测之上增加回连类验证（dnslog / HTTP 回连），**不等于承诺完整 RCE 利用链** | 同上 §1.9、C2 |

## 5. 指标口径警告（写验收前必读）

1. **自主性提升后，无效调用率上升不是退步，是任务终于真实。** 阈值须按任务等级分别冻结，
   不得沿用"人给 CVE"场景的 0% 作为标准。
2. **OQ-09 既有实测数据不可用于冻结预算**：它来自被预先消化过的任务，
   T2 级（只给目标）任务调用量将高一个数量级。
3. 预算由全局一池改为**阶段/假设分配**，否则前期信息收集会耗尽后期验证预算；
   收束期白名单 `allowedDuringConverge` 需同步支持新工具类别。
