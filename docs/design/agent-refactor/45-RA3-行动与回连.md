## RA-3.2 执行宿主（OQ-15）🔴

**先定门槛，不预设方案**：

| 候选 | 必须回答 | 淘汰线 |
| --- | --- | --- |
| 子进程 + Node 权限模型 | 能否禁 `fs`/`child_process`；能否限内存/CPU；启动延迟 | 无法禁出网即淘汰 |
| 独立容器 | 能否 `--network=none` 或仅接 pentest-net；能否只读挂载；启动延迟 | 启动 > 2s 需评估对预算影响 |
| WASM | 可用库范围是否够写 HTTP 探测；能否限资源 | 无法发 HTTP 即淘汰 |

**至少两个候选实测比较**（ADR-000 第 3 条），结论另开专题 ADR 并回填 ADR-006。

**验收（RA-3 硬证据）**：生成一个"越界探测工具"（目标写未授权主机），证明它在宿主内**无法触达**；
代码本体 + 执行日志 + 裁决记录三者全部入证据包。

## RA-3.3 回连通道（OQ-16）🔴

**先测一个推断**（`13-器官-工具生成与回连.md` §1.9）：`pentest-net` 是 `internal: true`，
只禁出网、网内互通。若推断成立，自回连不需改网络，只需 agent 侧监听 + payload 指向 agent。

```bash
# 前提：agent 镜像已装 netcat-openbsd（Dockerfile 有），非 root 用户可 bind >1024 端口
# 1) agent 侧起监听
docker compose -f deploy/docker-compose.yml exec agent bash -lc "nc -l 4444 -v"

# 2) 从同一网络里的另一个容器回连——不依赖靶场镜像里有没有 nc/curl
docker run --rm --network blitzspaher_pentest-net busybox sh -c "echo hi | nc agent 4444"
#    网络名 = compose 的 name + 网络名；实际值用 `docker network ls | grep pentest` 确认

# 3) 对照：能力未授予时应连不上（物理证据，不是逻辑拦截）
```

靶场镜像（`vulhub/fastjson`、`shiro`、`struts2`）多为精简 JRE，**不要假设里面有 `nc` 或 `bash`**。
第 2 步用独立 busybox 容器测网络可达性；"靶上的 payload 能不能连"是 payload 生成问题，不是网络问题。

能通 → 成本在"payload 生成与授权"；不通 → 需单独设计通道，且 L6 证据要重采。

**能确定的部分先做**：能力授权 `callback`、三个审计事件（`callback_watch_start/received/stop`）、证据落盘格式。

**验收**：能力授予 → 一次真实回连 + 证据可复核；能力未授予 → 端口不可达（**物理证据**，`nc` 连不上）。
