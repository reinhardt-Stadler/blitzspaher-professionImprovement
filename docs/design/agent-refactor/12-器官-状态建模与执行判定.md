## 1.6 环境状态建模 🟡

**现状**：只有 `evidence.ts:19` 的六类扁平事实，存在 `Map<key, Fact>` 里。无关系结构，
无法回答"8080 上跑什么组件、有哪些候选漏洞、验过哪个"。

**实现**：关系型认知层，供规划与覆盖率；**不动**扁平枚举（硬约束 1）。

```ts
export type NodeKind = "host" | "port" | "service" | "component" | "cve" | "path";
export interface TmNode { id: string;      // "port:target:8080/tcp"
                          kind: NodeKind; label: string; attrs: Record<string, unknown>; }
export interface TmEdge { from: string; to: string;
                          rel: "has_port" | "identified_as" | "serves" | "vulnerable_to"; }
export interface TargetModel { nodes: Map<string, TmNode>; edges: TmEdge[]; }
```

**投影规则**（同一份 Observation 派生，见 `02-目标架构.md` 原则一的配套纪律"同源投影"）：

| 观测事实 | 产生节点 | 产生边 |
| --- | --- | --- |
| nmap 开放端口 | `port:<host>:<p>/tcp` | `host → has_port` |
| nmap 服务+版本 | `service:<host>:<p>:<svc>`、`component:<name>@<ver>` | `port → identified_as` |
| http_probe 状态码/Server | `path:<host>:<path>`、`component:<server>` | `host → serves` |
| cve_check 结论 | `cve:<id>@<host>`（带 conclusion 属性） | `component → vulnerable_to` |

- **`coverage(model, policy)`** 三个比率：端口覆盖率（已扫/已知）、组件识别率（有 `identified_as` 的端口/开放端口）、
  验证完成率（有结论的 `cve` 节点/候选 `cve` 节点）。
- **与扁平枚举的关系**：`TargetModel` 是 `ledger` 的**投影视图**，不是替代。验收判定（R4、`phaseOf`、报告四态）
  继续读 `ledger`。允许的差异只有一种且是 bug：图里有节点但台账无对应事实 → 单测断言"投影 ⊆ 台账"。

**卡点**：`version` 字段缺失使 `component@ver` 的 ver 常为空——此时组件节点只按名字聚合，
覆盖率单列"版本未知"计数，**不得当成"无漏洞"**。

## 1.7 结果解析与三态判定 ✅

**现状**：`Observation` 结构统一（`tools.ts:23`：`ok/tool/summary/evidence/simulated/rawOutput`）；
运行时**无判定**（`index.ts` 拿到 `tool_result` 只做 `trace.end` + `budget.recordCall`）；
离线有判定（`evidence.ts:121` `assess()` 判 I1/I3/I2）；失败无重试、连续失败不停止。

**两个判定必须分开**，混在一起会互相污染：

| 判定 | 问题 | 位置 | 用途 |
| --- | --- | --- | --- |
| `assess()`（已有） | 这次调用**有没有新增事实** | 离线 `evidence.ts` | 无效调用率、R4、"无新增证据"停止条件 |
| `verdict()`（新增） | 下一步**该不该继续这条假设** | 内核 `verdict.ts`，纯函数 | 重试/换路/放弃 |

```ts
export type StepVerdict =
  | { kind: "advance"; hypothesisId: string | null; note: string }
  | { kind: "retry_change"; reason: "inconclusive" | "partial" | "fingerprint_unknown";
      allowedVariations: Array<"path" | "content_type" | "port"> }   // 可换维度，不给具体参数
  | { kind: "abandon"; reason: "retry_exhausted" | "tool_unavailable" | "contradicted" };
// 不含 halt_branch —— "是否停止整条任务"归 decideStop()；
// 不给 nextArgs —— 具体换什么由模型定（`05-与pi分工与硬约束.md` §2）。
```

判定表（6 行，纯函数直接实现）：

| 条件 | 判定 |
| --- | --- |
| `failed` 且 `consecutiveFailures >= 2` | `abandon(tool_unavailable)` + `toolHealth=unavailable` |
| `failed` 且未达上限 | `retry_change` |
| 结论 `CONFIRMED` / `NOT_CONFIRMED` | `advance`（假设闭环） |
| 结论 `INCONCLUSIVE` 且 `attempts < 2` | `retry_change`（必须换参数，同参重发被 I3 拦） |
| 结论 `INCONCLUSIVE` 且达上限 | `abandon(retry_exhausted)` → 假设 `inconclusive` |
| 新事实与假设 `basis` 矛盾 | `abandon(contradicted)` |

**停止决策收敛**：`SEC-STOP-01` 六个条件目前散在三处（`security-control.ts:195` 预算、`budget.ts` 水位、
`index.ts:255` 耗尽）。统一到 `kernel/decision.ts` 的 `decideStop(state): StopReason | null`，宿主只负责执行。

**收敛目标是七条件**（左边六条 + 目标达成 `objective_met`），口径以 `2规格/04` §4.6 为准。
本节六条是**代码现状**，不是收敛目标——照现状实现，会做出一个"只会中止、不会完成"的停止器，
正常跑完的任务只能报"无新增证据"。

**验收**：`OBS-CASE-003` 四类异常（超时/非零退出/空输出/损坏输出）分别落到不同分支，
且"工具未返回"不得被解释为"目标不存在"。

## 1.10 执行控制与安全 ✅

**现状（与原文档有出入，以此为准）**

- `authorize_call`（`security-control.ts:173`）判定序完整：arm → 停止 → 预算 → 工具白名单 → 目标 → 参数 → 重复 → 高危。21 项单测。
- **漏斗覆盖面被原文档高估**：`index.ts:54` 的 `PENTEST_TOOLS` 来自 `TOOL_REGISTRY`，后者只有 **3** 条。
  `pentest_report`（`index.ts:356`）与 `evidence_collector`（`index.ts:416`）虽注册但同样不经裁决。
  真实情况：**5 个注册工具中 2 个在漏斗外 + pi 全部内置工具在漏斗外**。
- 目标授权是精确主机匹配（`targetAllowed`），无 CIDR；`extractTarget` 已做 `host:port` / URL 归一化（W2 实测补的）。

**实现**：由"白名单内拦"改为"默认拒绝 + 显式放行"；授权由事中逐次确认改为事前能力授予 + 事中撤销。

```text
arm → stopped → capabilities（新增）→ 预算（改两本账）
     → 工具注册表（改为全量，含内置工具）→ 目标 → 参数 → 重复（改分级）→ 高危
```

- **能力检查放在工具白名单之前**：拒绝归因是 `CAPABILITY_NOT_GRANTED`（"这项能力未授予"）而非
  `TOOL_NOT_AUTHORIZED`（"工具没授权"）。两者整改动作完全不同——前者申请能力，后者改 policy。
- **全量注册表**：`ALLOWED = 注册表 ∪ {pentest_report, evidence_collector}`；不在 `ALLOWED` 的一切
  （含内置 bash/read/write）一律 `deny(code=BUILTIN_TOOL_DENIED)`。分支看 OQ-14-2：
  A 配置禁用（最干净）/ B 漏斗逐次 deny / **C 漏斗只对注册工具触发 → 本方案失效，须回到 A 或宿主级包装**。
- **两本账**（B5）：`BudgetTracker` 不动，外层加 `PhaseAllocator`，按 `TOOL_REGISTRY.category` 映射到
  `explore`（scanner/web_probe/knowledge）或 `verify`（vulnerability_check/callback）。
- **重复判定分级**：完全同参 → `deny(DUPLICATE_CALL)`；同工具同目标不同参 → `allow` + 标 `EXPLORATORY_RETRY`，计 explore 账。
- **高危语义**：`needsHuman` 改为"已授予能力范围内的一次性高风险确认"，不再逐次弹确认。

**验收**：`R7` 增加内置工具越界用例——容器内直接 `curl` 外网/非授权目标必须 0 次到达执行层，且有 `decision` 记录。
