## RA-1.1 内核骨架与可序列化状态 ✅

定义 `KernelState`（形状见 `20-难点-宿主与状态.md` B1 与 `05-与pi分工与硬约束.md` §2）、
`reduce()` 空实现（只做状态迁移、不产动作）、序列化往返测试。

**为什么先做**：RA-1.6 要求"每个 reducer 分支幂等"，这个约定必须在骨架阶段写进代码，后补改不动。

| 文件 | 内容 |
| --- | --- |
| `kernel/types.ts` | `KernelState`（`schemaVersion`/`seq`/`status`/`policy`/`plan`/`ledger`/`targetModel`/`counters`/`toolHealth`/`pending`/`authorization`） |
| `kernel/index.ts` | 按 `input.type` 分派，每个分支返回新 state + 事件 + 动作 |
| `kernel/persistence.ts` | `serialize` / `deserialize` / `assertRoundTrip` |
| `test/kernel-skeleton.test.ts` | 往返；非法输入不抛异常；`seq` 单调 |

**验收**：`deserialize(serialize(s))` 深等 `s`；十种 `KernelInput` 各一条用例。

## RA-1.2 任务状态机 ✅

转移表见 `10-器官-任务与规划.md` §1.1。三个要点：`PAUSED` 新增、`RUNNING ⇄ PAUSED` 双向；
非法转移**不抛异常**（写 `task_transition_rejected` 保持原状态）；每次转移写 `task_transition` 事件。

**验收**：转移表穷举（7 状态 × 6 事件 = 42 组合），合法与非法各自断言；`STOPPED` 之后任何输入不改状态。

## RA-1.3 plan / 假设清单 ✅

- Hypothesis 是主数据，Step 是 `suggestNext(state)` 派生；
- **`suggestNext` 只产 `PlanHint`，不产工具名与参数**（`05-与pi分工与硬约束.md` §3 越界线第 5 条）；
- 每次变更产 `PlanChangeEvent`，**必须带 `trigger`**；
- 六个重规划触发条件各一条实现，不合并。

**验收**：`trigger.stepId` 为空的变更被标 `untraced`，不计入 R3 证据；
`KernelAction` 联合类型不含 `call_tool`（类型断言即可）。

## RA-1.4 运行时记忆回注 🟡/⏸

`renderMemory(state)` + 裁剪 + 注入策略。**注入方式等 RA-0.1 的 Q1 结论**。

| 分支 | 宿主侧改动 | 内核侧改动 |
| --- | --- | --- |
| A（有钩子） | `index.ts` 注册钩子，传 `renderMemory` 结果 | 无 |
| B（只有 steer） | 注入文本加 `[SYSTEM-INJECT:plan]` 前缀；审计落 `kind=inject` | 标记由 `inject/render.ts` 产出 |

**验收**：同一 run 第 2 步后 L1 文本能看到第 1 步事实；L1 不超上限（字符数近似断言）；
裁剪发生时落 `memory_pruned` 事件。
