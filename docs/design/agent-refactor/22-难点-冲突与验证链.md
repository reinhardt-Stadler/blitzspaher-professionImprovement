## C1 动态工具 vs L4 白名单 🔴

**实质**：L4 的安全前提是"`execFile(cmd, [args])` 不拼 shell + 参数最小化"。生成代码天然不满足——它就是任意代码。

**已确定**：管线四段 + 七条静态审查规则（`13-器官-工具生成与回连.md` §1.8）；执行宿主接口 `ToolHost`；
代码本体入证据包。
**未调研**：隔离实现（OQ-15）。**不允许**在候选未比较前写"用容器就行"。
**一个容易漏的点**：要求"确认只发生在新工具首次注册"，意味着确认对象是**代码**而不是**调用**。
所以确认界面必须能展示代码 diff 与静态审查报告，否则"确认"是形式主义。

## C2 回连 vs ADR-004 网络方向 🔴

**实质**：现有流量方向 agent→靶，`internal: true` 禁出网；回连是靶→agent 反向。

**已确定**：能力授权、审计事件、验收判据（`13-器官-工具生成与回连.md` §1.9）；走 DCR-004，不开顺手洞。
**技术推断（待实测）**：网内自回连不需要改网络，改的只是 agent 侧监听与 payload 目标；
真正需要联网改造的是 dnslog 外带。推断依据与验证命令见 `45-RA3-行动与回连.md` §3。
**未调研**：监听器生命周期、并发上限、payload 由谁生成（OQ-16）。

## C3 知识库接线容易，变成能力难 🟡

**实质**：接一个检索工具是一天的事。让 `cve_check` 脱离硬编码，需要每条 CVE 配**机器可执行探测规格**
（请求模板 + 特征匹配 + 四态判定）。340 条里能自动转换的比例未知，其余人工写一条要多久也未知。

**处置**：schema 与解释器现在可写（零依赖、纯函数）：

```jsonc
{
  "specVersion": 1, "id": "fastjson-CVE-2017-18349",
  "component": "fastjson", "cve": "CVE-2017-18349",
  "safety": { "sideEffect": "none", "maxRequests": 2, "methods": ["GET", "POST"] },
  "steps": [
    { "id": "baseline", "request": { "method": "GET", "path": "/" },
      "expect": { "on": "status", "op": "gt", "value": 0 } },
    { "id": "probe",
      "request": { "method": "POST", "path": "/",
                   "headers": { "Content-Type": "application/json" },
                   "body": "{\"@type\":\"java.lang.Class\",\"val\":\"java.lang.Object\"}" },
      "expect": { "on": "body", "op": "regex", "value": "fastjson[\\s\\S]{0,80}type not match" } }
  ],
  "verdict": {
    "CONFIRMED": "baseline.ok && probe.ok",
    "NOT_CONFIRMED": "baseline.ok && probe.ok == false",
    "INCONCLUSIVE": "baseline.ok == false"
  }
}
```

- 判定表达式用一个极小布尔表达式解释器（`&&`/`||`/`==`/步骤名），不引入依赖。
- **"可自动转换"的判定标准必须写死**，否则覆盖率是玄学："正文里同时存在完整 HTTP 请求行 + 显式响应特征描述"。
  用脚本统计，输出实际数字（`44-RA2-感知与知识.md` RA-2.2）。
- **安全闸**：生成的 spec 若 `safety.sideEffect != none` 一律不自动启用。
  理由：340 条里不少条目带真实攻击载荷，自动跑等于批量发攻击。

## D1 缺 LLM 录制回放层 ✅

**实质**：现有 240 项单测全是离线纯逻辑（`security-control` 21、`observability` 57、`trace` 66、
`budget` 41、`report` 21、`evidence-collector` 34）。重构后核心行为变成"模型在某状态下如何决策"，
而 `temperature=0` 不保证跨版本可复现。

**处置**：两条腿，都不依赖模型可复现性：

1. **内核纯函数化**（`05-与pi分工与硬约束.md` §1）——状态到动作是纯函数，固定输入断言固定输出；
2. **`ModelClient` 接口 + 录制回放**：

```ts
export interface ModelClient {
  complete(req: { system?: string; messages: Message[]; tools: ToolSpec[] }): Promise<ModelResponse>;
}
// LiveModelClient（真调）/ RecordClient（透传 + 落 JSONL）/ ReplayClient（按 key 查 JSONL）
```

录制键 = `sha256(system + 最后 N 条消息 + 工具集版本)`。回放命中即返回，未命中即失败
——**不允许**静默 fallback 到真模型，否则回归测试退化为"跑一遍看看"。

## D2 部署链长 ✅

**实质**：`src/pi-pentest` → `prepare-build.mjs` 拷到 `deploy/pi-pentest` → 镜像 → WSL2 容器。
离线单测之外的实跑需明确执行人与复现命令。

**处置**：一条脚本串联（`40-RA0-实测与漏斗.md` 里给出）；
verify 报告模板固定四段：执行人 / 复现命令 / 环境快照（`docker compose ps` + `node -v` + `configHash`）/ 原始证据路径。
