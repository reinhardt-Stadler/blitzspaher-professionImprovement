## B2 `configHash` 哈希了 policy ✅

**实质**：`index.ts:104` `computeConfigHash({ policy, tools })`。policy 一旦可变（追加授权、多任务），
A/B 两组只要授权过程不同，`configHash` 就不同，`reconstruct --compare` 的 `CHECK_SAME_CONFIG_HASH`
直接判不通过，对照作废——而这套对照是 EXT-DIFF 全部实验的地基。

**处置**：引入 `configHashV2 = sha256({ toolSet, kernelVersion, policyShape, limits })`——
**只哈希"应该相同的部分"**（工具集、内核版本、策略结构、限额），不哈希 `taskId`/`targets`/`policyVersion`。
对照检查项相应改为 `CHECK_SAME_POLICY_SHAPE`。
**兼容**：旧事件仍只有 `configHash`，`reconstruct` 读到缺 `policyShapeHash` 时降级为旧口径，并在报告里标注。

## B3 审计以"工具调用"为中心，改动半径四倍 ✅

**实质**：`reconstruct.ts` 按 `toolCallId` 聚合。新增计划变更、假设迁移、生成代码、回连事件之后，
每加一类事件就要在四个文件里补洞，漏一个就产生"事件存在但没人消费"或"消费者不认识"。
更糟的是 `kind` 是联合类型但消费方用 `===` 比较——**新增 kind 不报错，只静默不被消费**。

**处置**：先立规矩（RA-0.3），规矩是**五步同步清单**：

| 步 | 文件 | 必做动作 |
| --- | --- | --- |
| 1 | `src/audit-schema.ts`（新建） | 加进 `AuditEventKind` 联合类型 + 定义必填字段 |
| 2 | `reconstruct.ts` | 决定是否进 `timeline`、是否算缺口、是否影响 `traceHealth` |
| 3 | `report.ts` | 决定是否进"未执行项/工具故障/覆盖情况" |
| 4 | `evidence-collector.ts` | 决定是否作为独立证据类型（`kind` 枚举 + `manifestVersion` 递增） |
| 5 | `test/audit-contract.test.ts`（新建） | 每种 kind 一条 golden JSON，断言四个消费者都能解析 |

规矩的强制力来自第 5 步：没有 contract test 的新事件类型不允许合入。

## B4 封闭枚举是验收地基 ✅

**实质**：`evidence.ts:19` 的六类事实与 `3验收文档` 总则-1 绑定，R4 召回率、`phaseOf`、报告四态都读它。
改枚举 = 作废已冻结的验收定义。

**处置**：不动。`TargetModel` 做投影（`12-器官-状态建模与执行判定.md` §1.6），
单测断言"投影 ⊆ 台账"。真要扩枚举，走验收文档修订，不在代码里偷偷加。

## B5 I3 重复指纹与探索性重试冲突 ✅

**实质**：`fingerprint()` 是"工具名 + 参数全等"。探索阶段"换个端口再扫一次"如果参数恰好相同，
会被判重复；而为了绕开限制每次微调参数，又会刷调用量。两个方向的坏结果都存在。

**处置**：分级 + 两本账，判据写成表：

| 情形 | 裁决 | 记账 |
| --- | --- | --- |
| 完全同参 | deny `DUPLICATE_CALL` | 不计 |
| 同工具同目标不同参 | allow + `EXPLORATORY_RETRY` | 计 explore 账 |
| 同工具不同目标 | allow | 计 explore 账 |

## B6 工具注册是手写样板 🟡

**实质**：`index.ts:126-174` 三个 `registerTool` 三段近乎重复；`tools.ts:44` 的 `TOOL_REGISTRY`
只有 `name/category/description/targetParam`，**没有 parameters schema**，所以无法自动注册。

**处置**：注册表补 `parameters`，**用 JSON Schema 纯数据，不用 TypeBox**——
`tools.ts` 必须保持零依赖（否则 `security-control.ts` 的整个先例作废）。
`index.ts` 写一个 `jsonSchemaToTypeBox` 子集转换（`object/string/number/boolean/array/required/optional`），
然后循环注册，三段样板收敛成一段。代码形状见 `30-扩展点-具体扩法.md` §3.4。
