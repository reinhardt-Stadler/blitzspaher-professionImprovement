| --- | --- | --- | --- |

| `DCR-NNN` | 决策变更记录（决策被推翻这件事本身） | `ADR/决策变更记录.md` | DCR-002 |

| `FR-*` / `SEC-*` / `NFR-*` | 需求条目（做什么，稳定 ID） | `1需求文档.md` | FR-AGENT-02 |
| `RA-N.x` | 工作包（一次可独立提交的改动） | `4工作项与路线图.md` §4 | RA-1.6 |
| `M1`–`M7` | 模块（内核/宿主/判定/工具/证据报告/评估/沙箱） | `4工作项与路线图.md` §2 | M1 内核 |
| `L0`–`L5` | 实现层（规格的组织维度） | `2规格/01` | L3 判定 |

| `T1`–`T3` | 任务自主性等级（输入条件，决定指标能不能横向比） | `3验收/01` 总则-7 | T1 人给 CVE |
| `U1`–`U4` | 未知情形构造用例（`T3` 下的四个难例） | `3验收/04` P14 | U2 无 probe spec |
| 最小档 / 折中档 / 全量档 | 实施范围（本期做多少工作包） | `4工作项与路线图.md` §5.1 | 折中档 17 包 |

### 1.1 字母复用怎么分辨

`A` / `B` / `C` 三个字母曾被三套体系共用，只看字母分辨不出来。**按长相认，别按字母认**：

| 长相 | 属于 | 出处 |
| --- | --- | --- |
| 字母 + 数字，出现在 `design/agent-refactor/20`–`22` | **难点编号**（哪里难） | `04-难点与扩展点索引.md` |
| `C` + 两位数字 | **约束条目**（性质级要求） | `3验收/06` |
| `T` + 一位数字 | **任务自主性等级** | `3验收/01` 总则-7 |
| `U` + 一位数字 | **未知情形构造用例** | `3验收/04` P14 |
| 中文档位名（最小 / 折中 / 全量） | **实施范围** | `4工作项与路线图.md` §5.1 |

范围档**不再使用字母**：早期文档与周志里的「A 档 / B 档 / C 档」分别对应现在的
**最小档 / 折中档 / 全量档**，历史周志保留原写法不改（流水记录不追改）。
自主性等级同理，早期写作 `A1`/`A2`/`A3`，现行写法是 `T1`/`T2`/`T3`——
`A1`–`A5` 留给难点编号，避免与「给不给 CVE」这件事混为一谈。

## 2. 状态标记与判定词汇

| 标记 | 含义 | 用法约束 |
| --- | --- | --- |
| ✅ | 已实现 / 策略已定 | 不用于"打算做" |
| 🟡 | 设计完成，待实现 | 必须能指出依赖哪个工作包 |
| ⏸ | 卡在实测（OQ-14/15/16） | **只写"卡在哪、有哪几种分支"，不写方案** |
| 🔴 | 未调研 | 只登记边界与判定门槛，不预设技术选型 |

| 判定词 | 含义 |
| --- | --- |
| `PASS` / `FAIL` | 按判据通过 / 不通过 |
| `INSUFFICIENT_EVIDENCE` | 证据不够判——**不得**当作 PASS，也不得当作"没问题" |
| `NOT_APPLICABLE` | 该场景不适用 |

## 3. 图示符号

| 符号 | 含义 |
| --- | --- |
| `→` 实线箭头 | 允许的调用/依赖方向 |
| `⇢` 虚线箭头 | 只能通过接口，不能直接引用内部 |
| `⊗` 或 `×` | 禁止的依赖方向（出现即违规） |
| `[ ... ]` | 一个模块/一层 |
| `{ ... }` | 一个数据结构 |
| `<...>` | 一次数据流（事件、输入） |

## 7. 图 4：判定序（唯一漏斗）

```
tool_call 进来
 0  arm=off?      是 → 基线放行（仍落 decision，供对照）
 1  已停止?        是 → STOPPED
 2  能力授予了吗?      否 → CAPABILITY_NOT_GRANTED      ← 放在白名单之前
 3  两本账够吗?    否 → PHASE_BUDGET_EXHAUSTED
 4  在白名单?      否 → BUILTIN_TOOL_DENIED     ← 含内置工具
 5  目标授权?      否 → TARGET_NOT_AUTHORIZED
 6  参数合法?      否 → PARAM_INVALID
 7  重复调用?      是 → DUPLICATE_CALL（三级，见 2规格/05 §5.4）
 8  高危?          是 → needsHuman（语义＝申请能力）
                    否 → 放行 → 执行 → 记账 → 落证据
```

## 10. 术语表

| 术语 | 含义（一句话） | 常见误解 |
| --- | --- | --- |
| **内核外置** | 把"状态与判定"从 pi 扩展文件里搬到独立目录 `kernel/`，依赖方向反转 | ❌ 不是"不用 pi 了"；pi 仍是宿主，只是不再持有状态与判断 |
| 宿主 | 跑循环、管会话、校验 schema、出 UI 的那一层（pi） | ❌ 不是"工具执行器" |
| 判定层 | 唯一裁决入口 `authorize_call` 所在的 L3 | ❌ 不是"内核"；判定层依赖内核类型，反过来不成立 |
| 零依赖 | 不 import 任何 pi API（`node:` 标准库仍可用） | ❌ 不是"不用任何库" |
| 同源投影 | 一份 Observation 只解析一次，同时产出 summary / Fact / TargetModel | ❌ 不是"三处各解析一遍再对齐" |
| 两本账 | 探索预算与验证预算分开记、分别冻结阈值 | ❌ 不是"两个计数器随便看看" |
| 约束条目（C） | 性质级要求，与"任务跑通没有"无关 | ❌ 不是场景验收的另一种写法 |
| 能力（capability） | 任务下发时授予的能力**集合**（recon/verify/callback/toolgen），并列、不强制累积 | ❌ 不是有序权限等级；也不是"每次调用弹一次确认" |
