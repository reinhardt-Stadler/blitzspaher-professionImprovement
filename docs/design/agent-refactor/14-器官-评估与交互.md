## 1.11 评估与自我改进 🟡

**现状**

- `reconstruct.ts:467` 的 `--compare`（EXT-DIFF 基建）可用：4 项对照有效性检查、指标差分、事实集合差分、路径分叉。
- **`decision-matrix.ts` 不存在**（`ls` 确认）。而 `8决策有效性验证-评估矩阵.md` §9 把 `phaseOf` /
  `evaluateDirection` / `DM-CASE-001~016` / L2 评分器四项都打了 `[x]`——文档与代码直接冲突。
- 无经验沉淀：每次 run 的证据互不相通。

**实现**

1. **按 `8` 文档的设计落地**（设计完整，只是没写代码）：`phaseOf(facts) → Phase`、
   `evaluateDirection(phase, call) → {inDirection, level}`、`DM-CASE-001~016` 数据驱动用例、L2 评分器复用 `reconstruct`。
2. **经验库**（`kernel/experience/store.ts`）：

```ts
interface ExperienceRecord {
  schemaVersion: 1;
  key: { component: string; version: string | null; probeId: string };
  outcome: { conclusion: Conclusion; attempts: number; failedReasons: string[] };
  runId: string; ts: string; configHash: string;   // 可追溯，可作废
}
```

铁律两条：**经验只能改变探测顺序，不能改变结论**；**跨 `configHash` 的经验默认不采信**
（工具或判定逻辑变了，旧经验可能失效）。

**卡点**：L2 基线数值要等实跑，不能预填（OQ-09 旧数据已作废）。

## 1.12 人机交互 ✅

**现状**：四个命令——`/pentest-status`、`/pentest-revoke`、`/pentest-report`、`/pentest-evidence`
（`index.ts:284,316,377,437`）。看不到计划、看不到下一步、不会主动澄清。

**实现**

| 命令 | 内容 | 需求 |
| --- | --- | --- |
| `/pentest-plan` | 当前阶段、假设清单（状态/尝试次数）、下一步及理由、两本账余额 | NFR-02 |
| `/pentest-pause` / `/pentest-resume` | 状态机迁移 + 恢复点 `seq` | FR-TASK-02 |
| `/pentest-escalate <level>` | 申请提升授权档位（一次性人工确认） | SEC-HUMAN-01 |
| 澄清交互 | `TaskDraft.ambiguities` 非空时阻塞并逐项提问 | FR-TASK-01、`总则-4` |

**一条硬要求**：`/pentest-plan` 的输出必须与 L1 记忆同源（`renderMemory`）。
否则人会看到和模型不同的"计划"——这比看不到更糟。
