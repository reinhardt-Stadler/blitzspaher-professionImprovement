## RA-2.1 知识检索工具 ✅

接口见 `11-器官-记忆与知识.md` §1.5。要点：

- 索引启动读一次（124KB 进内存），正文按需读盘；
- `knowledge_query` 只返回摘要；`knowledge_read` 必须带 `maxBytes`（默认 8KB，硬上限 64KB）；
- 两个工具进 `TOOL_REGISTRY`：`category: "knowledge"`、`account: "explore"`、`levels: ["recon"]` 起。

**验收**：`knowledge_query({component:"fastjson"})` 能返回 `CVE-2017-18349`；超限截断并标 `truncated`；
工具调用本身**不产生 `cve` 事实**（防止把检索当证据）。

## RA-2.2 探测规格化（C3）🟡

spec schema 与解释器见 `22-难点-冲突与验证链.md` C3。分三包：

| 子包 | 内容 | 产出 |
| --- | --- | --- |
| 2.2a | spec schema + 布尔表达式解释器 + 单测 | `kernel/knowledge/probe-spec.ts` |
| 2.2b | 从 340 条 md 抽 spec 的转换脚本（**只读不改源**） | `src/pi-pentest/scripts/extract-probe-spec.mjs` + 实际转换率 |
| 2.2c | `cve_check` 改为"先查 spec registry，再回落硬编码探测器" | `tools.ts` 的 `CVE_PROBES` 变 fallback |

**"可自动转换"判定标准（写死，避免玄学）**：条目正文同时满足
① 存在完整 HTTP 请求行（`METHOD /path HTTP/1.x`）；
② 存在显式响应特征描述（状态码/响应头/可对应的关键串）；
③ `safety.sideEffect == "none"` 可判定（正文未出现写文件、执行命令、反弹 shell 之类）。

**验收**：给出三个数字——总条目数、满足判定标准的条目数、转换后通过人工抽检的条目数。
**这三个数字现在不能预填。**

**安全闸**：自动转换的 spec 若 `sideEffect != none` 一律不自动启用，进人工队列。

## RA-2.3 表驱动自动注册 ✅

见 `30-扩展点-具体扩法.md` §3.4。要点：

- `TOOL_REGISTRY` 补 `parameters`（**JSON Schema 纯数据**）+ `levels` + `account`；
- `index.ts` 加 `jsonSchemaToTypeBox()`（子集：object/string/number/boolean/array/required/optional）；
- 三段手写注册收敛成一段循环；现有 3 个工具的 schema 从 `index.ts` 搬到 `tools.ts`（形状不变）。

**验收**：新增测试用工具只需在 `TOOL_REGISTRY` 加一条 + `TOOL_IMPL` 加一函数，`index.ts` 零改动；
`tools.ts` 仍不 import 任何 pi 包。

## RA-2.4 TargetModel 与覆盖率 ✅

投影表见 `12-器官-状态建模与执行判定.md` §1.6。要点：

- 投影在 `observation → fact` 的同一次解析里完成（同源投影）；
- 单测断言"投影 ⊆ 台账"（图里每个节点都能在 ledger 找到对应事实）；
- `coverage()` 三个比率；`version` 缺失时单列"版本未知"。

**验收**：用一份现有 `audit/observations/` 真实记录回放投影，人工核对 3 个节点的边。

## RA-2.5 判定接入探测器 🟡

把 RA-1.5 的 `verdict()` 接到真实探测流程：`cve_check` 返 `INCONCLUSIVE` 时内核判 `retry_change`
并给出 `allowedVariations`（换 path/Content-Type），由模型决定换成什么。

**验收**：`8决策有效性验证` 矩阵第 9 行（INCONCLUSIVE 后重发同一调用 → `DUPLICATE_CALL`）在真实 run 里成立；
换了参数的第二次调用被放行且计入 explore 账。
