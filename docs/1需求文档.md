# 需求文档（面向用户）

> 状态：骨架 v0.1（待与组内逐项过 v0.3 指导意见后冻结）
> 来源：课程稿《智能渗透测试 Agent 规划_前期聚焦版 v0.3》第 1–3 章；问题框架、用户画像与场景剧本继续以课程稿为准，本节只维护**需求条目本体**。

## 0. 编写约定

- 编号规则：FR-功能，SEC-安全控制，NFR-非功能。关键条目标注 MUST/SHOULD。
- 每个 MUST 必须在《验收文档》第一层有对应验收项；没有验收映射的需求不允许标 MUST。
- 本文件只写"做什么 / 不做什么"，**不写实现方式**（那是 02-规格的事）。

## 1. 功能需求（FR）

### 1.1 任务管理（FR-TASK）

- **FR-TASK-01 (MUST)** 系统支持以自然语言创建安全测试任务，并解析为结构化配置：授权目标、允许工具集与任务预算；解析结果须经用户确认后方可启动。
- **FR-TASK-02 (MUST)** 系统支持启动/暂停/终止任务，并查看任务状态与审计日志。
- **FR-TASK-03 (MUST)** 任务生命周期与测试结论采用两层状态模型：
  - 任务层：`PLANNED → AUTHORIZED → RUNNING → STOPPED`（停止原因含 budget_exceeded / revoked / user / error / boundary_blocked）
  - 测试项结论层：`CONFIRMED / NOT_CONFIRMED / INCONCLUSIVE / NOT_EXECUTED`

### 1.2 Agent 核心能力（FR-AGENT）

- **FR-AGENT-01 (MUST)** 信息分析：从工具结果中提取 IP/域名、端口、服务、Web 路径、版本信息、漏洞线索与工具异常。
- **FR-AGENT-02 (MUST)** 任务规划：依据当前任务、已获信息、已完成测试、剩余预算与当前授权范围决定下一项测试。
- **FR-AGENT-03 (MUST)** 工具调用：仅可调用系统注册且当前任务授权的工具；LLM 只决定"是否需要工具与调用哪个"，实际执行由受控执行层完成。
- **FR-AGENT-04 (MUST)** 结果分析：判断结果有效性、提取安全相关信息、评估进一步测试价值、选择下一操作或按停止规则结束。
- **FR-AGENT-05 (MUST)** 报告生成：报告字段见 1.3；结论必须与实际执行范围一致，并携带效率事实字段。

**高效要求**：无效调用率 ≤ 30%（数值首次试跑后冻结；定义见验收文档总则）。

### 1.3 报告内容（FR-REPORT）

报告至少包含：测试目标、授权范围、使用工具、已执行测试、漏洞结论（四态区分）、证据与复现步骤、未覆盖项目、工具故障、停止原因、效率事实字段（实际工具调用次数、任务耗时、无效调用率）、建议的后续检查。

## 2. 安全控制需求（SEC）

| ID | 需求 | 关键约束 |
| --- | --- | --- |
| SEC-AUTHZ-01 (MUST) | 目标授权 | Agent 只能访问预注册目标（如 target-01）；不得自行扩展至其他目标/网段/新 URL，除非获得新授权 |
| SEC-TOOL-01 (MUST) | 工具授权 | 维护工具注册表（scanner / web_probe / vulnerability_check / evidence_collector）；只能用任务允许的工具 |
| SEC-PARAM-01 (MUST) | 参数约束 | 高风险参数（target、port range、request method、execution count、timeout）由执行层校验，不依赖 LLM 自觉 |
| SEC-BUDGET-01 (MUST) | 执行预算 | 限预算机制：最大检查次数、最大逻辑运行时间、最大并发数、单项工具超时（数值首次试跑后冻结） |
| SEC-STOP-01 (MUST) | 停止机制 | 触发条件：越界、授权撤销、预算耗尽、连续工具失败、重复执行、无新增有效证据、用户终止 |
| SEC-AUDIT-01 (MUST) | 审计 | 记录任务 ID、时间、Agent 决定、调用工具、调用参数、执行结果、授权状态、预算消耗、停止原因；日志不存不必要敏感信息 |
| SEC-HUMAN-01 (MUST) | 人工确认 | 越界重规划确认、预算告警、高危操作执行前；确认过程记入审计日志 |

## 3. 非功能需求（NFR）

- **NFR-01 可重复性**：相同靶场 + 相同配置 + 相同任务 → 可重复运行且结果可比较。
- **NFR-02 可解释性**：展示当前任务、已执行动作、工具调用、结果摘要、下一步计划、停止原因；不展示模型完整内部思维。
- **NFR-03 可控性**：Agent 无宿主机无限权限；一切动作经 `Agent → 控制层 → 工具 → 靶场` 执行链。
- **NFR-04 可演进性**：架构允许新增工具/靶场/任务/安全策略；控制层与工具层同编排层解耦，为多 Agent 协作预留编排抽象。

## 4. 模型能力需求（FR-MODEL，2026-10-19 由 ADR-002 实验结论转化）

> 来源：120 次实测（`research/模型选型实验结果.md`）。这些条目是"驱动模型的最低能力线"，
> 不满足即需重开 ADR-002；满足不代表安全——安全由控制层兜底。

- **FR-MODEL-01 (MUST)** 工具调用稳定性：在 pi 框架内对结构化工具调用（schema 校验 + 参数抽取）的成功率 ≥ 90%，且能对结果做主动分析（指出风险方向与下一步建议），非仅复述输出。
- **FR-MODEL-02 (MUST)** 可复现性：支持 `temperature=0`（或等效确定性设置）下重复运行结果可比对。
- **FR-MODEL-03 (MUST)** 输出预算可控：单次任务输出在预设 `max_tokens` 内可完整返回，不产生"空 content"型截断（或调用层可按 provider 特征正确配置）。
- **FR-MODEL-04 (SHOULD)** 中文能力：对中文渗透任务的自然语言交互与报告生成达到可用水平（中文实测后确认）。
- **FR-MODEL-05 (SHOULD)** 本机可替换：存在本机开源模型兜底路径（Ollama 等），用于离线或云端不可用场景（可行性待验证）。

**安全红线（非需求，是边界声明）**：越界服从事项**不参与模型选型打分**——实测两个候选模型越界服从率 90–100%，证明安全边界必须由控制层强制（支撑 R7），不指望模型自觉。
