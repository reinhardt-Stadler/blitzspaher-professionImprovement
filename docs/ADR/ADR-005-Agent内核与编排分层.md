# ADR-005：Agent 内核外置与编排分层

- 状态：**已决定**（含待验证前提，见"关联"）
- 修订：**DCR-005**（2026-11-10，内核不产工具调用指令，动作限定为约束类）
- 日期：2026-11-08
- 决策者：组内（用户确认重构方向）
- 对应需求变更：CR-001；对应设计文档：`design/Agent重构设计-2026-11-08.md`
- 连带修订：ADR-001（DCR-002，pi 角色收窄）

## 背景（Context）

项目定位由"渗透测试辅助系统"回到"完整自主渗透 Agent"（CR-001）。现有实现是
**一次性、单任务、全内存**的 pi 扩展：`buildPolicy()` 在扩展加载时执行一次（`index.ts:80`），
控制层、预算、trace、事实台账均为内存对象，跑一轮即结束。

完整 Agent 要求长程任务、显式计划、运行时记忆、重规划、暂停恢复。必须回答三个问题：

1. **规划/记忆/状态机写在哪里？** 写在 pi 扩展内，还是独立模块？
2. **长任务状态如何持久化与恢复？**
3. **目标状态建模要关系型数据，而已冻结的验收判定建立在扁平封闭枚举事实上，二者如何共存？**

约束条件：

- pi 的 agent loop 主权不在我们手里，扩展仅有 4 个事件钩子（`index.ts` 注册点）；
- 行为级回归测试需要可离线、可重复的决策逻辑（`design` 文档 §4.4 D1）；
- NFR-04 要求控制层/工具层与编排层解耦，ADR-001 已用 `security-control.ts` 零依赖验证过该路线可行。

候选方案：

- **方案一：全部写在 pi 扩展内**（沿用现状延伸）。
- **方案二：内核外置，pi 作为执行宿主**（本决策）。
- **方案三：自研 Orchestrator，取代 pi 的 loop**。

## 决策（Decision）

> **Agent 内核（任务状态机、显式计划与假设清单、运行时记忆、TargetModel、结果三态判定、
> 重规划与停止决策、经验沉淀）实现为零 pi 依赖的独立模块；pi 保留为执行宿主与交互壳。
> 内核全部状态可序列化、可恢复（状态外置）；认知层与判定层分离。**

具体四条：

1. **内核零依赖**：不 import 任何 pi API，经明确接口由 pi 扩展驱动；离线单测覆盖全部决策点。
   决策点为纯函数（状态 → 动作），模型只在边缘。
2. **状态外置**：任务状态、计划、预算、台账、停止状态均可序列化，恢复点与 `audit.jsonl` 事件序对齐；
   进程重启后可续跑。"暂停恢复"在此之前不成立，不得对外宣称具备。
3. **认知层 / 判定层分离**：`host/port/service/version/path/cve` 扁平封闭枚举**不变**，
   继续支撑无效调用判定、R4 召回率、`phaseOf`、报告；新增关系型 `TargetModel` 仅供规划与覆盖率计算。
4. **pi 角色收窄**：pi 负责 agent loop、工具 schema 校验、会话与 UI 确认；
   不负责规划、记忆与任务语义（见 DCR-002）。

## 备选方案（Alternatives）

| 方案 | 优点 | 缺点 / 淘汰原因 |
| --- | --- | --- |
| 一：写在 pi 扩展内 | 无新模块边界，短期改动少 | 决策逻辑无法脱离宿主单测，行为回归只能"跑一遍看看"；状态与进程生命周期绑定，暂停恢复做不了；换宿主即重写，违背 NFR-04 |
| 三：自研 Orchestrator 取代 pi | 循环主权完整，记忆/计划注入位置自由 | 需自建会话管理、schema 校验、流式输出、上下文压缩等基础设施，与项目核心价值无关——即 ADR-001 否决"自研"的同一理由，本期不推翻 |
| **二：内核外置（采用）** | 决策可离线测试；状态可外置；宿主可替换；与 ADR-001 的零依赖先例一致 | 需要定义内核与宿主之间的接口；pi 侧注入能力若不足，部分功能需绕行（见待验证前提） |

## 最小实验 / 证据

- **已有先例**：`security-control.ts` 零 pi 依赖，离线单测 16 → 21 项全绿，经 `pi.on("tool_call")` 挂接，
  R7 端到端实测拦截生效（ADR-001、`verify/2026-W45-W2单点验证报告-Fastjson.md`）。
  证明"零依赖模块 + 事件挂接"路线在本项目可行。
- **待做验证（RA-0）**：pi 能力实测五项（系统提示/上下文注入钩子、内置工具禁用、`details` 是否入上下文、
  子代理支持、`usage` 字段形态）。**若第 1 项不成立，记忆回注的注入位置需重开讨论，本 ADR 其余部分不受影响。**
- **决策门槛**：内核模块在无 pi、无模型、无 Docker 环境下完成单测，且同一状态输入产生同一决策输出。

## 后果（Consequences）

### 正面

1. 行为级回归测试可行：决策点纯函数化后可离线重放，不依赖模型可复现性。
2. 长任务、暂停恢复、多任务有实现前提；R3 可获得 plan diff 这一直接证据形式。
3. 已冻结的验收定义（总则-1/-3、R4、决策矩阵）不受关系建模影响，避免验收地基返工。
4. 多 Agent 演进时内核可复用，与 G5"演进不重构"一致。

### 负面 / 成本

1. 新增内核与宿主的接口层，短期代码量上升。
2. 状态外置是本期最大单项工程之一（`design` 文档 §4.2 B1）：所有内存对象需可序列化并与审计事件序对齐。
3. 审计事件类型需随内核扩张，连带 `reconstruct.ts` / `report.ts` / `evidence-collector.ts` / 决策矩阵四处同步（§4.2 B3）。
4. `configHash` 目前哈希 policy，policy 可变后 A/B 对照口径需重定义（§4.2 B2）。
