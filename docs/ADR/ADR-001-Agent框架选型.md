# ADR-001：Agent 框架选型

- 状态：**已决定**
- 日期：2026-10-15（提议 2026-10-13 → 决定 2026-10-15）
- 决策者：组内（用户拍板）
- 对应开放问题：OQ-02；指导意见第 8、9 条

## 背景（Context）

两条路线：

1. **自研**：从零搭建 Orchestrator 与工具调用循环。
2. **借鉴已有框架做扩展**（指导意见第 8 条倾向方向）。

候选框架在 2026-10-15 收敛为两个：**pi-coding-agent**（下称 pi）与 **DeepSeek Harness**（下称 DSH）。
课程稿原有的 LangGraph / CrewAI 候选因以下原因退出候选：

- 与实际工作环境不匹配（本项目已具备 pi 环境与 DeepSeek 账号体系）
- 组内无使用经验，且 pivot 到真实可跑的框架后二者的调研价值下降

若走路线 2，课程稿 MVP 中"两个 tool call"的验证即失去意义（框架自带工具调用），MVP 需按"框架 + 一个真实业务场景跑通"重定义。

## 决策（Decision）

> **采用 pi-coding-agent 作为首版主框架。**

- pi 版本：v1.2.0（正式版）
- 扩展方式：TypeScript Extension（`registerTool` / `registerCommand` / `on` 事件）
- 安全控制层：**自建为框架无关的纯逻辑模块**（不依赖 pi API），通过 `pi.on("tool_call")` 挂接
- 沙箱：WSL2 内 Docker Engine（不属于本 ADR 范围，见 ADR-004）

## 评估维度与实测结果

| 维度 | pi | DSH | 判定 |
| --- | --- | --- | --- |
| **成熟度** | v1.2.0 正式版，40+ 篇文档，70+ extension 示例，随包提供 `.d.ts` | 0.2.0-rc.2 候选版，**无扩展文档**（知识需逆向 `app.asar`） | pi |
| **安全控制层接入难度** | `pi.on("tool_call")` 返回 `{block,reason}`；**实测无旁路 + R7 拦截生效** | 宿主内置 `tools/pre-execute` + `guard()`；插件需适配，且预算/停止/审计需自建 | pi |
| **Tool Calling 稳定性** | 实测结构化调用稳定（16 项单测 + 端到端闭环） | 仅验证到"能注册/能跑"，未做多次稳定性统计 | pi |
| **状态管理/调试** | 会话 JSONL + `session.subscribe()` 事件（可程序化重建 trace） | 会话日志 + **Web 可视化**（探索链路/漏洞/资产/报告） | DSH（演示面） |
| **沙箱** | 无内置，需 Docker | 内置命令级沙箱（`dsh-sandbox` 系列），**但覆盖不了环境/网络隔离** | 平（Docker 两边都要做） |
| **学习曲线** | 单文件即可注册工具（jiti 直跑 TS），实测 <1 小时跑通 | 需理解 Cordis 插件 → bundle → profile → preset 四层，且无文档 | pi |
| **演进不重构（NFR-04）** | 安全层写成零依赖模块即可复用（已验证） | 宿主管道强制，换框架不可迁移 | pi |
| **License** | 未构成障碍 | 未构成障碍 | 平 |

## 备选方案（Alternatives）

### pi-coding-agent（采用）

- 优点：正式版可交付；安全层完全可控；文档齐全可查；安全层可写为框架无关模块
- 缺点：无内置沙箱（需自备 Docker）；无内置 Web 可视化（需自建）
- **实测证据**：`spike/spike实验产出.md` §2

### DeepSeek Harness（未采用）

- 优点：Cordis 插件化架构完整；**内置命令级沙箱**；**Web 可视化**在演示上明显更强；技能体系（`SKILL.md`）成熟
- 缺点（决定性）：
  1. **RC 阶段**（0.2.0-rc.2），交付窗口内存在破坏性变更风险
  2. **无扩展文档**，扩展知识需逆向 `app.asar`
  3. 唯一可参考的渗透插件 **`@howmp/dsh-pentest` 已于 2026-10-09 归档**，不再维护、不再适配新版
  4. **内置安全层不覆盖本项目的授权/预算/停止/审计需求**——该插件的 `authorization` 参数"只是审计事实，不是门禁"，边界完全依赖宿主沙箱与审批
- 说明：不采用的原因是**交付风险与控制粒度**，不是 DSH 能力不足
- **实测证据**：`spike/dsh-plugin-probe/RESULT.md`、`spike/spike实验产出.md` §3

### LangGraph / CrewAI（退出候选）

- 退出原因：与实际工作环境不匹配；组内无经验；真实可跑框架已收敛为 pi/DSH 后调研价值下降
- 备查：CrewAI 组装下模型拒答率显著低于其他框架（见 `research/模型安全策略与拒答调研.md` §3），若未来重新引入需纳入安全评估

### 自研（未采用）

- 未采用原因：不是能力问题，而是**工期与可验证性**问题。自研需自行解决会话管理、工具 schema 校验、
  流式输出、上下文压缩等基础设施，而这些与项目核心价值（安全控制层 + 渗透闭环）无关。
  采用 pi 可将精力集中在安全层与工具层。

## 后果（Consequences）

### 正面

1. **安全控制层完全自主**：SEC-AUTHZ/TOOL/PARAM/BUDGET/STOP/AUDIT/HUMAN 七条 MUST 全部可在自有代码中实现，
   并且实测 R7 拦截生效、审计字段完整。
2. **NFR-04 可兑现**：`security-control.ts` 零 pi 依赖，16 项单测可在无框架环境独立运行；
   未来演进到多 Agent 或更换框架时，该模块可直接复用。
3. **交付风险低**：正式版 + 完整文档 + 可查类型定义，问题可自行定位。
4. **技能资产通用**：pi 与 DSH 都遵循 Agent Skills 规范（`SKILL.md`），技能可复用。

### 负面 / 需自建

1. **无内置沙箱**：需自建 Docker 环境隔离（已作为独立决策项写入 ADR-004）。
2. **无内置 Web 可视化**：R3 的 trace 回放需从 JSONL 审计日志自行重建（工作量约 1 天）。
3. **无多 Agent 编排原语**：多 Agent 演进需自行设计编排抽象（但本项目首版为单 Orchestrator，暂不需要）。

### 中性

- DSH 的 Web 可视化能力作为**未来可选增强**记录：若后期演示需要，可基于 pi 的 JSONL 审计日志自建等价视图。
