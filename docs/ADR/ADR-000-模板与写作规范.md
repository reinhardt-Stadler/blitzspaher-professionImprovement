# ADR-000：ADR 模板与写作规范

> ADR（Architecture Decision Record，架构决策记录）：记录"重要的技术选择 + 当时为什么这么做"，让后人（和对抗组）不用重新踩一遍。

## 模板

```markdown
# ADR-NNN：<决策标题>

- 状态：提议 / 已决定 / 已废弃（被 ADR-XXX 取代）
- 日期：YYYY-MM-DD
- 决策者：<谁拍的板>

## 背景（Context）
必须回答的问题、约束条件、候选方案清单。

## 决策（Decision）
选了什么，一句话能说清。

## 备选方案（Alternatives）
每个主要备选：优点 / 缺点 / 被淘汰的原因。

## 后果（Consequences）
这个决策带来什么影响（好的和坏的都要写）。

## 关联
需求 ID / 验收 ID / 相关 ADR / 后续待验证假设。
```

## 写作规范

1. ADR 一旦进入"已决定"状态不再改写，纠错写新 ADR 并标废弃链。
2. 每个 ADR 必须有"最小实验/证据"一节或引用实验记录（时间盒 + 决策门槛），防止"凭感觉选型"——呼应指导意见第 8 条"用 AI 对话快速理解框架再决策"。
3. 候选方案没调研过 2 个以上的，不允许进入"已决定"。
