# ADR-006：执行面扩展与动态工具安全边界

- 状态：**提议**（方向已经组内确认；具体隔离与网络方案未调研，满足 ADR-000 第 3 条后方可转"已决定"）
- 日期：2026-11-08
- 决策者：组内（用户确认纳入动态工具与受控回连）
- 对应设计文档：`design/Agent重构设计-2026-11-08.md` §4.3
- 连带修订：ADR-003（DCR-003，工具集开放化）、ADR-004（DCR-004，回连通道与执行面覆盖）

## 背景（Context）

重构后执行面从"4 个自研工具、无损探测、单向 agent→靶流量"扩展为三种新形态，
每一种都与既有安全前提冲突：

1. **pi 内置工具构成旁路**：`index.ts:179` 对非注册工具直接 `return undefined`，
   即内置 bash/read/write 等不经 `authorize_call()`。"L3 单一入口无旁路"当前只对自研工具成立。
2. **动态工具**：组内确认 Agent 可动态收集/编写工具（11.4 构建指引第 4 行）。
   L4 的"`execFile` 白名单 + 不拼 shell"前提对生成代码不成立。
3. **受控回连验证**：组内确认在无损探测之上增加回连类验证。
   现有沙箱为 internal 网络 + 出网代理白名单，流量方向 agent→靶；回连为靶→agent，方向相反。

必须回答：旁路如何处置、生成代码在哪执行、人工确认放在哪个环节、回连通道如何不开公网后门。

## 决策（Decision，方向性四条；实现方案待后续专题 ADR）

1. **内置执行类工具：禁用，不做 shell 文本解析授权。**
   bash 类工具的目标可藏于管道、变量、编码之中，解析 shell 做目标授权不可靠。
   优先使用 pi 的禁用机制；若无禁用机制，则在 `tool_call` 漏斗中对内置执行类工具一律 deny。
   内置只读工具是否保留及其审计方式，随 RA-0 实测另定。
2. **动态工具走"生成 → 审查 → 注册 → 复用"管线，人工确认只发生在首次注册。**
   每次生成都要求确认会使自主性失效；注册后复用不重复确认。
   生成代码在独立执行宿主中运行，**代码本体必须入证据包**（否则 NFR-01 可重复性不成立）。
   隔离方案（独立容器 / 子进程 + 资源限额 / 网络策略）为 OQ-15，未调研前不定。
3. **授权由事中逐次确认改为事前授权档位 + 事中撤销。**
   长任务必然无人值守，而 `ctx.hasUI` 为假时高危默认拒绝（`index.ts:204`），二者冲突。
   任务下发时一次性授予档位（如：无损探测 / 回连验证 / 动态工具注册），事中保留 `/pentest-revoke`。
4. **回连验证作为独立授权档位，网络通道单独设计（OQ-16），走 DCR-004 修订 ADR-004。**
   不允许在现有 internal 网络与出网白名单上顺手开洞；dnslog 类外部服务的出网例外需单独论证，
   优先评估靶场内自回连（靶→agent 监听端口）能否满足验证目的。
   **回连验证不等于承诺完整 RCE 利用链**；报告需区分"风险面存在"与"已回连验证"。

## 备选方案（Alternatives）

| 方案 | 优点 | 缺点 / 当前结论 |
| --- | --- | --- |
| 对 bash 命令做文本解析后授权 | 保留内置工具灵活性 | 自由文本 shell 无法可靠判定目标与副作用，**否决** |
| 维持现状只拦自研工具 | 无改动 | 自主性越高旁路越危险；动态工具上线后等于开天窗，**否决** |
| 动态工具每次执行前人工确认 | 看似最稳 | 与长程自主直接冲突，**否决**；确认前移至首次注册 |
| 动态工具在 agent 主容器内直接执行 | 实现最简单 | 生成代码与主控同权，L5 容器隔离形同虚设，**否决** |
| 回连直接放开 agent 容器入向 + dnslog 出网 | 验证能力最强 | 破坏 L6 物理兜底与"公网情报首版禁止"的既定边界，需专项论证，**暂否** |
| 完整 RCE 利用链验证 | 结论最有说服力 | 授权模型、报告结论态、沙箱策略均需重做，本期不承诺 |

> 说明：本 ADR 的备选比较针对"处置原则"；**隔离宿主与回连通道的具体技术方案尚未调研**，
> 故整体状态保持"提议"。OQ-15 / OQ-16 各需 ≥2 个候选方案的实测比较后，另开专题 ADR 并回填此处引用。

## 最小实验 / 证据（RA-0 与 RA-3）

- RA-0：实测 pi 内置工具清单与禁用机制；给出"自研工具 + 内置工具全部经过漏斗"的拦截证据（含一条内置 bash 越界用例）。
- RA-3：动态工具隔离宿主的最小验证——生成一个越界探测工具，证明其在隔离宿主内无法触达未授权目标，
  且代码本体、执行日志、裁决记录全部入证据包。
- RA-3：回连通道最小验证——在授权档位开启时完成一次靶→agent 回连；档位关闭时回连端口不可达。

## 后果（Consequences）

### 正面

1. "单一入口无旁路"从只对自研工具成立，变为对整个执行面成立，R7 证据更完整。
2. 动态工具获得可审计、可复现、可复用的落地形态，而不是"模型写代码直接跑"。
3. 事前授权档位解决长程自主与人工确认的死结，SEC-HUMAN-01 语义更清晰。

### 负面 / 成本

1. 禁用内置 bash 后，Agent 失去通用 shell 能力，所有动作必须来自注册工具——**工具覆盖不足会直接表现为任务失败**，
   这使工具层与知识层的工作量前置。
2. 动态工具隔离宿主是本期最大单项工程之一；生成物审计使证据包与 trace 重建同步扩张。
3. 回连通道增加沙箱网络复杂度，L6 证据需要重新采集。
4. 授权档位引入新的策略维度，`TaskPolicy` 与 `configHash` 结构需同步调整（见 ADR-005 后果 4）。
