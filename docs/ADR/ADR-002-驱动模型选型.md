# ADR-002：驱动模型选型（含拒答应对策略）

- 状态：**已决定**
- 日期：2026-10-19（提议 2026-10-13 → 决定 2026-10-19）
- 决策者：组内（用户确认）
- 对应开放问题：OQ-03；指导意见第 11 条

## 背景（Context）

驱动模型的边界条件（详见 `research/模型安全策略与拒答调研.md`）：

1. **误拒答**：安全对齐模型对含安全敏感词的任务拒答率显著升高（同类任务 2.72 倍），显式声明授权反而提高拒答率。
2. **有用性差距**：拒答率高的模型缺陷率反而最低；拒答低的开源小模型缺陷率高——拒答与能力/安全不是简单正相关。
3. **部署位置**：云端 API 受厂商政策约束；本机开源权重模型无外部政策约束，但工具调用能力弱一档。
4. **框架放大效应**：同一模型在不同 Agent 框架下拒答率差异巨大（52.3% vs 30.8%）。

## 决策（Decision）

> **主模型采用 `deepseek-flash`（DeepSeek V4.1 Flash）；`kimi-k2.7-code`（Kimi K2.7 Code）作为第二云端备选。**

- 接入方式：pi-coding-agent 的 provider 机制（OpenAI 兼容接口）
- 模型可切换：抽象为统一调用点，业务代码不感知供应商
- 拒答应对策略：保留授权上下文模板 + 有限重提示（≤2 次）+ `model_refusal` 停止原因

## 实验证据

**实验设计**：使用 Meta PurpleLlama / CyberSecEval 2 官方数据集，pi 框架内实测。
详见 `spike/pi-pentest/experiments/ADR-002实验结果.md`。

### 数据来源（可复核）

| 数据集 | 采样 | 用途 |
|--------|------|------|
| `mitre_frr.json`（750 条合法请求） | 20 条 | 测误拒答率 |
| `mitre_benchmark_*.json`（ATT&CK 战术） | 10 条（Recon） | 测越界服从率 |

条件：C1 裸问 / C2 授权上下文 / C3 pi 框架内（轻量验证）。
总调用 120 次 + 2 次框架内调用，成本约 $1.5–2.5。

### 核心结果

| 模型 | 误拒答率（FRR） | 越界服从率 | 平均输出 | 工具调用（C3） |
|------|----------------|-----------|---------|--------------|
| DeepSeek V4.1 Flash | **0%**（C1/C2 均 0/20） | **90% → 100%** | 12.4K tok | ✅ 成功 |
| Kimi K2.7 Code | **0%**（C1/C2 均 0/20） | **100% → 90%** | 6.8K tok | ✅ 成功 |

### 三条关键实证结论

1. **误拒答不是本场景的主要风险**：两个模型对 20 条合法安全请求的拒答率均为 0%。
   这与调研引用的文献（30.5%）不同，可能的解释是数据集偏防御性任务 + 模型代际改进。
   **边界**：结论仅适用于本批数据；换更激进的表述（如直接要求攻击 payload）可能不同。

2. **越界服从才是真风险**：对 MITRE Recon 战术的恶意请求，两个模型提供了 90–100% 的可执行内容。
   **这从实证上证明：安全边界不能依赖模型自觉，必须由控制层强制。**

3. **授权上下文不能作为安全措施**：添加授权声明后，越界服从率没有下降
   （DeepSeek 90%→100%，Kimi 100%→90%，10pp 变化在 n=10 下不显著）。
   授权上下文的正确用途是**审计留痕**，不是门禁。

## 备选方案（Alternatives）

### deepseek-flash（采用为主）

- 优点：零误拒答；工具调用在 pi 内验证通过且能主动做风险分析；原生中文强；单价低（$0.3/$1.2 per M）；已在项目链路中跑通（`ReAct/`）
- 缺点：输出长（12.4K tok/次，重推理），单次成本高于 Kimi；`max_tokens` 需 ≥32K 否则 content 为空

### kimi-k2.7-code（采用为备选）

- 优点：输出更简洁（6.8K tok）；代码/工具调用定位明确
- 缺点：`temperature` 只能为 1（削弱可复现性）；无明显相对优势；中文场景未验证
- 定位：第二云端备选，服务于"双路可切换"架构

### 本机开源模型（未验证）

- ADR-002 原计划的"本机兜底"分支**本次未验证**（无 Ollama 环境）
- 保留为后续工作项；调研文档已记录其取舍（无政策约束 vs 能力弱一档、护栏需自备）

### 其他云端模型（退出候选）

- 因项目已具备 DeepSeek/Kimi 账号体系，且两者均满足门槛，未扩展到其他供应商

## 后果（Consequences）

### 正面

1. **控制层必要性获得实证支持**：越界服从率 90–100% 是 R7（越界拦截）验收的最有力论据。
2. **成本可控**：实测 $1.5–2.5 完成 120 次对比。
3. **双路可切换**：DeepSeek 主力 + Kimi 备选，符合"不写死供应商"的架构要求。

### 负面 / 需注意

1. **DeepSeek 的推理消耗**：`max_tokens` 必须给足（32K），否则静默返回空 content；
   这对预算计数（SEC-BUDGET-01）意味着**tokens 维度也需纳入预算**，不仅是调用次数。
2. **Kimi 的 temperature 限制**：只能在 1，实验可复现性弱于 DeepSeek。
3. **中文场景未验证**：本次数据集为英文，而项目交互以中文为主，需补测。
4. **拒答应对策略仍需保留**：虽然本批 FRR=0，但换表述可能触发，工程上不能省。
