# ADR-004：沙箱分层选型（7 层）

- 状态：**已决定（设计定稿，实现暂停）**
- 日期：2026-10-19
- 决策者：组内
- 对应需求：NFR-03（可控性）、NFR-01（可重复性）、SEC-AUTHZ-01、G3（受控执行边界）
- 设计全文：`agentsbuild/spike/沙箱设计说明.md`（本 ADR 为其 §2 的决策化提取）

## 背景（Context）

渗透测试 Agent 的沙箱目标与一般应用相反：不是"能力最小化"，而是**"边界精确"**——
允许对授权靶场发起扫描/验证流量，禁止对靶场以外的任何目标产生副作用。
由此推导出信任模型三层：**不可信的模型输出 → 可信的控制层裁决 → 不可绕过的内核/容器强制隔离**。

## 决策（Decision）

采用 **7 层防线**，强制力由内向外递增：

| # | 层 | 目的 | 强制力 | 必做 | 状态 |
| --- | --- | --- | --- | --- | --- |
| L1 | 提示词 | 减少误伤（**不承担安全**） | 无 | 顺带 | — |
| L2 | 输出结构化 | 阻止非法工具调用格式 | 代码 | 必做 | pi TypeBox（已验证） |
| **L3** | **控制层** | 授权/预算/停止/参数/审计，单一入口 `authorize_call()` 无旁路 | 代码 | **必做** | **已实现（spike 16 项单测 + R7 实测）** |
| L4 | 工具实现 | 防命令注入（`execFile` 不拼 shell）/ 硬超时 / 输出上限 | 代码 | 必做 | 已实现（spike） |
| L5 | 容器 | 非 root + `cap-drop ALL` + 只读 rootfs + 资源配额 | 内核 | **必做** | ⏸ 待 Docker |
| **L6** | **网络** | `internal: true` 网络——物理上只允许打到授权靶场 | 内核 | **必做（物理兜底）** | ⏸ 待 Docker |
| L7 | 宿主机 | WSL2 边界最终兜底 | 平台 | 顺带 | 已有 |

**核心论证**：L3 的目标白名单是逻辑检查，可被 DNS 重绑定/IP 直连/重定向绕过；**L6 的网络隔离是物理检查，绕不过**。多层组合应对单点失效（详见设计文档 §2.3 攻防矩阵）。

**实现选型**：WSL2（Ubuntu 22.04）内 Docker Engine（不装 Docker Desktop，无商业授权问题）+ `internal` 网络 + agent 跑在容器内（否则 L5 失效）。

**明确放弃**：seccomp 系统调用过滤（课程项目收益低、调试痛苦，P3 不做）。

## 备选方案（Alternatives）

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 只做到 L3/L4（控制层+工具层） | 放弃 | L3 有 bug 或被绕过时无兜底；R7"100% 拦截"承诺没有物理支撑 |
| DSH 内置命令级沙箱 | 不采用 | 只覆盖命令执行级，**覆盖不了环境/网络隔离**；且 DSH 本身未入选（ADR-001） |
| 独立 VM 隔离 | 暂缓 | L7 用 WSL2 已够课程场景；VM 作为 P3 演进项 |
| 公网只读情报通道 | 首版禁止 | 需要查 CVE 时用离线知识库；放开网络面违背 L6 设计初衷 |

## 后果（Consequences）

### 正面

1. R7/R9/R10 的验收证据可以**分层出示**：逻辑拦截（L3 审计日志）+ 物理拦截（L6 网络不通），答辩说服力远胜单层。
2. 结对组构造对抗用例时有明确靶点（每层至少 1 个用例，见验收文档）。
3. 沙箱不依赖框架选型——pi 已选，若未来换框架 L5/L6 原样保留。

### 负面 / 成本

1. 环境前置：WSL2 内 Docker Engine 安装 + agent 镜像 + compose，约 3 天（S1–S6 见设计文档 §4.2）。
2. L6 `internal` 网络禁止公网 → 模型 API 调用（云端 LLM）与容器隔离冲突，**agent 容器需要单独放网络出口策略或宿主侧代理**——实现时必须解决，已列入设计文档待办。
3. 演示链路口径变化：Web 可视化没有现成（DSH 不选后），R3 trace 回放需从 JSONL 自建（约 1 天）。
