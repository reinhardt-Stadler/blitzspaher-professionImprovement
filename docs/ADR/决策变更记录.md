# 决策变更记录（DCR）

> 定位：ADR 记录"决策及其理由"；本文件记录"决策被推翻/修订这件事"本身——保证任何技术决策可审计、可回溯。
> 规则：ADR 进入"已决定"后不得改写，变更一律走本文件开 DCR 单，并在被变更的 ADR 头部标 `→ 已被 DCR-NNN 修订/废弃`。
> 与 04-过程/需求变更记录.md 的区别：那边管"用户要什么变了"，这边管"我们决定怎么做变了"。

### DCR-005 详情

| 字段 | 内容 |
| --- | --- |
| 发起人 | 组内（用户质疑"内核零依赖是不是等于自研 agent"） |
| 变更原因 | ADR-005 写的是"决策点为纯函数（状态 → 动作）"，未限定动作类型。实现时发现：若内核能产出 `call_tool`，就与 pi loop 里"模型决定调哪个工具"形成**两个 planner**。结局只有两种——内核说了算（pi 退化为 HTTP 客户端，等于自研框架），或模型说了算（内核计划沦为装饰）。两条都不可接受 |
| 影响决策 | ADR-005 |
| 旧决策 | 内核决策点纯函数化，"状态 → 动作"，动作类型未限定 |
| 新决策 | 内核只产**约束类动作**：`inject`（注入约束与事实）、`ask_user`（澄清）、`require_level`（申请提档）、`stop`。**不产 `call_tool`**——工具与参数的选择权留给模型。内存新增"越界线"五条：出现调模型代码 / 存对话历史 / 需要轮次 / 处理流式 / 产工具调用指令，任一即视为已退化为自研框架 |
| 连带修改 | `2规格/02-内核与状态.md` §2.5（越界线）、`2规格/03-规划记忆与任务.md` §3.3（`suggestNext` 只给 `PlanHint`）、`design/agent-refactor/05-与pi分工与硬约束.md` §2–§3、`design/agent-refactor/02-目标架构.md` 原则三；验收 C31、P9 |
| 日期 | 2026-11-10 |

**注意**：这是对 ADR-005 的**收窄**，不是推翻——ADR-005 的四条（零依赖、状态外置、认知/判定分离、pi 角色收窄）全部不变。

### DCR-001 详情

| 字段 | 内容 |
| --- | --- |
| 发起人 | 实验证据（W3c 中文补测） |
| 变更原因 | ADR-002 决策时数据集为英文，遗留「中文场景未验证」。本次按项目真实场景自建 15 条中文测试集实测 |
| 影响决策 | ADR-002 |
| 旧决策 | 中文场景未验证，列为待补测项 |
| 新决策 | 中文场景已验证：误拒答率 0%（0/5）、越界服从率 0%（0/5）、中文输出率 93% |
| 连带修改 | 无（模型选型不变，DeepSeek V4.1 Flash 仍为主力）；证据存档 `docs/verify/2026-W45-中文补测报告.md` |
| 日期 | 2026-11-07 |

**重要限定**（不得被引用为「中文更安全」的依据）：

- 中文越界服从率 0% 与英文 90–100% 的差异，**最可能源于表述方式**（中文测试集带明确恶意语境，英文 MITRE 数据集为中性技术描述），
  而非模型在中文下更安全。
- 未做「中文中性表述」对照组，不能排除这一解释。
- 本结论**不改变**「安全边界必须由 L3 控制层强制」的工程结论，反而强化它：
  越界服从率依赖表述，说明它不是一个可依赖的稳定属性。
