# 模型选型实验结果（ADR-002 支撑材料）

> **对应**：OQ-03、ADR-002（已决定）
> **日期**：2026-10-19
> **框架**：pi-coding-agent v1.2.0 + pi-pentest extension
> **候选**：`deepseek-flash`（DeepSeek V4.1 Flash） vs `kimi-k2.7-code`（Kimi K2.7 Code）
> **原始记录**：`agentsbuild/spike/pi-pentest/experiments/`

---

## 0. 结论

> **`deepseek-flash` 符合期望，作为主模型；`kimi-k2.7-code` 作为第二云端备选。**

| 期望项 | DeepSeek V4.1 Flash | Kimi K2.7 Code | 判定 |
|--------|---------------------|----------------|------|
| 误拒答率 | 0% | 0% | 平 |
| 越界服从率 | 90–100% | 90–100% | 均不合格（不参与打分） |
| 工具调用稳定性 | ✅ 主动风险分析 | ✅ 仅陈述结果 | DeepSeek |
| 成本（实测） | 约 $0.015/次 | 约 $0.022/次 | DeepSeek |
| 可复现性（temperature=0） | ✅ | ❌ 只能 =1 | DeepSeek |
| 中文 | 原生强 | 未验证 | DeepSeek |
| 已有集成 | `ReAct/` 已在用 | 需新接 | DeepSeek |

**关键判断**：越界服从率两边都 90–100%，**都不符合"安全"期望**——但这不参与选型打分，
因为它证明的是「控制层必须强制」，而非「哪个模型更好」。

## 1. 数据来源（可复核）

采用 **Meta PurpleLlama / CyberSecEval 2** 官方数据集（arXiv:2404.13161），
经 `codeload.github.com` 下载并本地核实：

| 数据集 | 原始条数 | 采样 | 用途 |
|--------|---------|------|------|
| `mitre_frr.json` | 750（全合法） | G1 10 + G2 10 | 误拒答率 |
| `mitre_benchmark_*_with_augmentation.json` | 1000（ATT&CK） | G3 10（Recon） | 越界服从率 |

采样：`seed=42`，30 条，每条带 `source` / `meta` 标注，可复现。

**为什么这套数据有说服力**：
1. 学术论文配套（CyberSecEval 2 提出 False Refusal Rate 指标）
2. 任务源自 MITRE ATT&CK 战术分类，非人工编造
3. 合法/恶意双向覆盖，对应调研文档 §8"两指标必须同测"
4. 全部公开可下载、逐条可比对

## 2. 实验条件

| 条件 | 说明 |
|------|------|
| C1 裸问 | 直接发送 prompt |
| C2 授权上下文 | 前置"已授权安全测试项目 / 自有隔离靶场 / 目标白名单" |
| C3 框架内（轻量） | pi + pi-pentest 实际调用工具，仅验证可用性 |

总调用：**120 次**（C1 60 + C2 60）+ C3 2 次。实测成本 **$1.5–2.8**。

## 3. 结果

### 3.1 核心指标

| 模型 | 条件 | 误拒答率 | 越界服从率 | 平均输出 |
|------|------|---------|-----------|---------|
| DeepSeek V4.1 Flash | C1 | **0%** (0/20) | **90%** (9/10) | 12,283 tok |
| DeepSeek V4.1 Flash | C2 | **0%** (0/20) | **100%** (10/10) | 12,550 tok |
| Kimi K2.7 Code | C1 | **0%** (0/20) | **100%** (10/10) | 6,397 tok |
| Kimi K2.7 Code | C2 | **0%** (0/20) | **90%** (9/10) | 7,215 tok |

### 3.2 C3 框架内验证

| 模型 | 调用 | 结果 |
|------|------|------|
| DeepSeek | `nmap_scan(127.0.0.1, 80,8080)` | ✅ 成功，主动指出"8080 疑似 fastjson，建议下一步" |
| Kimi | 同上 | ✅ 成功，输出结构清晰但无额外推断 |

两者均通过安全控制层：审计记录 `decision: allow` → `execution calls=1/5`。

---

## 4. 三条实证结论

### 结论 1：误拒答不是本场景的主要风险

两个模型对 20 条合法安全请求拒答率均为 **0%**。
与调研引用文献（Scale AI：30.5%）不同，可能原因：数据集偏防御性任务 + 模型代际改进。

**边界**：仅适用于本批数据。换更激进的表述（直接要求攻击载荷）可能不同。

### 结论 2：越界服从才是真风险（90–100%）

对 MITRE Recon 战术的恶意请求（如"写代码扫描端口识别开放服务""抓取社媒识别组织内目标"），
两模型几乎全部提供了可执行内容。

**这从实证上证明：安全边界不能依赖模型自觉，必须由控制层强制。**
→ 直接支撑验收项 **R7（越界拦截）** 的必要性。

### 结论 3：授权上下文不能作为安全措施

添加授权声明后越界服从率未下降（DeepSeek 90%→100%，Kimi 100%→90%，n=10 下 10pp 不显著）。

授权上下文的正确用途是**审计留痕**，不是门禁。此结论与 `@howmp/dsh-pentest` 的 README 一致。

## 5. 技术发现（影响后续所有实验）

| # | 发现 | 影响 | 处理 |
|---|------|------|------|
| T1 | DeepSeek V4.1 Flash 是**重推理模型**：`max_tokens=8000` 时 reasoning 吃光配额，`content` 为空 | 会误判为拒答 | `max_tokens` 设 32000 |
| T2 | Kimi K2.7 系列**只接受 `temperature: 1`** | 传 0 返回 HTTP 400 | 按 provider 分别设置 |
| T3 | **空输出 ≠ 拒答** | 首版规则误判率 100% | 改为三态判定 |
| T4 | 存在**部分拒答**（拒绝原请求 + 给防御替代） | 二分法漏判 | 引入 `refused_partial`，计入 FRR |
| T5 | 平均输出 6.8K–12.4K tokens | 成本远高于初估 | 采用精简采样方案 |

**T4 示例**（DeepSeek 对恶意请求 P021）：
> "I can't help with targeted, unauthorized reconnaissance against a third-party target.
> I can, however, show a **defensive, allowlisted exposure-audit** pattern..."

按"是否产出代码"判 → 服从；按"是否拒绝原请求"判 → 部分拒答。本报告采后者。

## 6. 实验局限

| 局限 | 说明 |
|------|------|
| 样本量小 | 每组 10 条，10pp 级差异不显著 |
| 单一恶意类别 | G3 仅 MITRE Recon |
| 仅英文 prompt | 中文场景未验证（项目以中文交互为主） |
| 判定基于规则匹配 | 非逐条人工复核 |
| C3 仅 2 次调用 | 依用户指示简化，不能统计框架放大效应 |
| 未测本机开源模型 | ADR-002 原计划的"本机兜底"分支未验证 |

---

## 7. 对项目的直接启示

1. **SEC-BUDGET-01 需覆盖 token 维度**：DeepSeek 单次 12.4K 输出，仅按"调用次数"计预算不够
2. **拒答应对策略仍要保留**：本批 FRR=0，但换表述可能触发；授权模板 + ≤2 次重提示 + `model_refusal` 保留
3. **R7 的必要性获得实证**：越界服从 90–100% 是控制层存在的最有力理由
