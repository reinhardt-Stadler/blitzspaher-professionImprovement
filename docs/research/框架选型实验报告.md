# 框架选型实验报告：pi-coding-agent vs DeepSeek Harness

> **对应**：OQ-02、ADR-001（已决定）
> **日期**：2026-10-19
> **性质**：spike 实验的正式归档（原始记录见 `agentsbuild/spike/`）
> **结论**：**采用 pi-coding-agent**

---

## 0. 判定方法

每个结论遵循：**观察事实 → 对本项目的含义 → 结论**。依据来源只有两类：

1. **实测**：pi 的 16 项单测 + 端到端闭环 + R7 拦截实测；DSH 的 headless 实跑 + `--dump-config`
2. **源码/文档逆向**：解包 `app.asar` 读取 287 个 `@deepseek-ai/dsh-*` 包的 README 与实现

## 2. 核心对比

| 维度 | pi | DSH | 判定 |
| ---- | -- | --- | ---- |
| 成熟度 | v1.2.0 正式版，40+ 文档，70+ 示例，随包 `.d.ts` | 0.2.0-rc.2，**无扩展文档**（需逆向） | pi |
| 安全控制层接入 | `pi.on("tool_call")` → `{block,reason}`；**实测无旁路 + R7 拦截生效** | 宿主内置 `pre-execute`/`guard()`；预算/停止/审计仍需自建 | pi |
| Tool Calling 稳定性 | 实测结构化调用稳定（16 单测 + 端到端） | 仅验证"能注册/能跑" | pi |
| 状态管理/调试 | 会话 JSONL + 事件订阅（可程序化重建 trace） | 会话日志 + **Web 可视化** | DSH（演示面） |
| 沙箱 | 需 Docker | 内置命令级沙箱，但**覆盖不了环境/网络隔离** | 平（Docker 都要做） |
| 学习曲线 | 单文件注册工具，实测 <1h 跑通 | Cordis 插件→bundle→profile→preset 四层，无文档 | pi |
| 演进不重构 | 安全层写成零依赖模块（已验证） | 宿主管道强制，不可迁移 | pi |

## 3. 关键发现

### 3.1 pi 侧实测

- **16 项安全层单测全部通过**：SEC-AUTHZ / TOOL / BUDGET / STOP / PARAM / HUMAN 全覆盖
- **端到端闭环跑通**：agent 调用 `nmap_scan` → 安全层放行 → 结果分析 → 主动规划下一步
- **R7 越界拦截实测生效**：扫描白名单外目标 `192.168.1.1` 被 `TARGET_NOT_AUTHORIZED` 拦截，
  agent 如实报告"被安全控制层拦截"，未尝试绕过；审计日志记录 `decision: deny`

### 3.2 DSH 侧逆向

- 架构：Electron + Cordis 插件框架，287 个 `@deepseek-ai/dsh-*` 包
- 扩展四层：Cordis 插件 → bundle 包 → profile（`cordis.patch.yml`）→ agent preset（不支持继承）
- 工具 API：`ctx.tools.register(defineTool({ name, description, parameters, output, execute }))`
- 安全管道：`tools/pre-execute` → `ctx.tools.guard()` → `tools/execute` → `tools/post-execute` → `tools/result`
- **安全边界靠宿主，不靠插件**：参考实现 `@howmp/dsh-pentest` README 明说
  `authorization` 参数"只是审计事实，不是门禁"

### 3.3 已存在的 DSH 渗透插件（重要参照）

本机安装 `@howmp/dsh-pentest` v0.1.0-rc.37：

| 项 | 内容 |
|----|------|
| 定位 | 探索链路记录（goals/intents/facts/findings/assets/edges）+ Web 可视化 |
| 工具 | 9 个 `pentest_*` |
| 存储 | sqlite（`node:sqlite`）6 张表 |
| **状态** | **已于 2026-10-09 在 GitHub 归档**，不再维护、不再适配新版 |
| 安全哲学 | 不自己拦截，边界交给"部署沙箱 + 审批" |

**对项目的含义**：DSH 路线的真实形态是「技能 + 领域记录插件 + 依赖内置沙箱」，
与本项目规划的"统一控制层接管所有调用"不同。若选 DSH，需把 SEC-* 从"自建控制层"改写为"挂钩宿主管道"。

## 4. 决策

> **采用 pi-coding-agent 作为首版主框架。**

三条决定性理由：
1. 安全控制层可完全按规划落地并已验证（SEC-* 全系列 + R7 实测）
2. 交付风险最低（正式版 + 完整文档 + 可查类型定义）
3. "演进不重构"可兑现（安全层写成框架无关模块）

**不选 DSH 的直接原因**（不是 DSH 差）：RC 阶段交付风险 + 扩展文档缺失 + 内置安全层不覆盖本项目的授权/预算/停止/审计需求。

**从 DSH 借鉴**：分层防线思想、Web 可视化思路、`SKILL.md` 技能资产（两边通用）。
