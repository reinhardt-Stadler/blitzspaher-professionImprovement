# 模型安全策略与拒答调研

> 对应：v0.3 指导意见第 11 条——"通用模型有安全策略限制，最终驱动效果边界在哪里？本机 or 云端？"
> 方法：按指导意见要求走查资料，优先选取 2024–2026 年、可核查的客观来源（论文、厂商官方文件、公开事件复盘）。
> 日期：2026-10-13　状态：初版，供 ADR-002 与组内讨论使用

## 0. 一句话结论

**拒答不是"会不会"的问题，而是"在哪个环节、以多大概率发生"的问题**：云端安全对齐模型对授权防御/测试任务的误拒答有量化证据（最高 43.8%），且显式声明授权反而加重拒答；但同一批模型在"已授权渗透测试"的 Agent 脚手架下拒答可趋近于零；本机开源模型几乎不拒答，但工具调用能力和护栏要自备。**对本项目意味着：模型选型必须与框架、拒答应对策略成对验证，且工程上不能依赖模型自觉（控制层兜底）**——这与规格文档 §3 安全控制的分层防线设计互相印证。

## 1. 误拒答（False Refusal）有硬数据，且渗透任务恰好在重灾区

- **Defensive Refusal Bias（Scale AI，2026-03，基于 NCCDC 大学生防御竞赛 2,390 条真实任务）**：含安全敏感关键词（exploit、payload 等）的**合法防御任务**被拒答率是语义等价中性表述的 **2.72 倍**（30.5% vs 11.2%，p<0.001）；拒答率最高的恰是关键操作类——系统加固 43.8%、恶意软件分析 34.3%、漏洞评估 22.7%、事件响应 18.9%。
- **反直觉发现**：用户显式声明"我有授权"会**提高**拒答率——模型把授权辩解当作对抗信号，说明当前对齐靠"语义相似度"而非"意图/授权推理"。
- 来源：https://arxiv.org/abs/2603.01246
- 启示：我们的场景（对授权靶场跑 nmap、漏洞验证）在词汇面上与攻击任务几乎不可区分，必须预期主力云模型会出现不成比例的拒答。

## 2. 拒答率与"安全性"不是简单正相关——拒答高≠更安全

- **Safety and Security Analysis of LLMs（2025-09，九个主流模型横评）**：网络安全类有害 prompt 的平均拒答率仅 **12%**（安全类 22%），多个开源模型（DeepSeek V3、Qwen 3 1.7B、Grok 3、Mistral 7B）对网络安全类 prompt 拒答率为 **0%**；而拒答率最高的 Gemini 2.5 Flash（48%）与 GPT-4o（42%）缺陷率反而最低（39%），DeepSeek 系缺陷率高达 86–90%。
- 来源：https://arxiv.org/abs/2509.10655
- 启示：选模型不能只看"拒答少"，低拒答可能只是护栏薄（缺陷率高）。要同时测"误拒答率"和"越界服从率"两个方向。

## 3. 框架会放大/改变模型行为——"模型 × 框架"必须成对验证

- **Penetration Testing of Agentic AI（2025-12，首个系统化横评）**：同一批模型在 AutoGen 与 CrewAI 两个框架下拒答率分别为 52.3% 与 30.8%，总体 41.5%——**超过一半恶意 prompt 在企业级安全机制下仍成功**；并复述了 Unit 42 的发现：ChatGPT-4o 作为 Agent 能执行它在聊天模式下会拒绝的攻击。
- 来源：https://arxiv.org/abs/2512.14860
- 启示：① 框架选型的评估维度里应加入"安全行为面"（CrewAI 组装下拒答率最低，对我们反而是风险信号——意味着约束更依赖我们自建的控制层）；② 我们的控制层设计（C-ARCH-01 无旁路）是正确方向，因为框架层护栏不可靠。

## 4. 授权脚手架可以基本消除拒答——但要想清楚它在测什么

- **400-run 实证研究（2026-03）**：在标准 prompt 中明确"已授权渗透测试"框架 + 编排层对第 0/1 次拒答自动带授权上下文重提示、第 2 次仍拒答则终止的规则下，400 次运行**零持久拒答**。作者特别声明：这测的是"授权脚手架 + 一次性重提示下的拒答"，不是任意框架下安全机制的被动测试。
- 来源：https://arxiv.org/html/2605.30096v1
- 启示：这正是我们 ADR-002 中"拒答应对策略"的原型——授权上下文模板化 + 有限重提示 + 如实记录。注意边界：它能解决"误拒答"，不能替代"越界拦截"（后者必须靠控制层）。

## 5. 云端模型的政策边界：禁的是"未经授权"，但豁免通道很窄

- 三家现行政策文本均**没有**明文禁止"分析自己系统上的攻击数据"：Anthropic 政策（2025-09-15 生效）禁止"未经系统所有者授权发现或利用漏洞"；OpenAI（2025-10-29 生效）禁止"破坏、入侵他人系统"；Google 只禁"促成恶意软件的生成与分发"。三者都**没有**面向安全研究/事件响应的明确豁免条款（仅 Google 有宽泛的"公共利益例外"，无申请路径）。
- 实际事件：2026 年 Hugging Face 用前沿云模型分析自家被攻击日志，被安全护栏拒答，最终转向可内部部署的开源权重模型完成分析。Anthropic 另有 **Cyber Verification Program**（企业可申请的合法安全验证通道）。
- 来源：https://servola.de/journal/nobody-forbade-it-the-filter-refused-anyway/ ；https://www.anthropic.com/glasswing
- 启示：走云端 API 在法律文本上站得住（授权靶场 = 我们是系统所有者），但**无豁免通道意味着被误伤时没有申诉路径**——这是云端的结构性风险。

## 6. 本机开源模型：无政策约束，但能力与护栏是自助模式

- 无外部使用政策、无供应商审计、数据不出本机；PentestGPT、Darkmoon 等开源渗透 Agent 均支持 Ollama/LM Studio 本地模型路线。
- 代价：① 同档参数下工具调用稳定性弱于前沿云模型（需实测，ADR-002 已列验证项）；② 没有内置安全对齐，护栏需自行加装——Meta 官方路径是用 **Llama Guard 3 / PromptGuard / Code Shield** 等外挂护栏（CyberSecEval 3 配套开源）。
- 另需记录：CyberSecEval 3（Meta，2024-08）的人机对照实验显示，LLM 对人类攻击者完成率的提升**无统计显著性**，自主黑客进展有限——即当前模型更偏" copilot "而非"自主攻击者"，这对我们的教学定位是利好。
- 来源：https://arxiv.org/abs/2408.01605 ；https://arxiv.org/abs/2404.13161

## 7. 补充事实：提示注入是所有模型的共同短板

- CyberSecEval 2（Meta，2024-04）：所有受测模型对提示注入的屈服率 **26%–41%**（平均 28%），官方结论明确"不能只靠 system prompt 约束模型行为，必须在应用层加护栏"。
- 这直接支撑我们规格文档的设计决定：**提示词层只做意图对齐，安全约束全部下沉控制层**（L1–L4 分层防线）。
- 来源：https://arxiv.org/abs/2404.13161

## 8. 对本项目的落地建议（已同步进 ADR-002）

1. **双路可切换**：云端主力（强工具调用）+ 本机开源兜底（离线/拒答时降级），抽象成统一模型接口，不在业务代码里写死供应商。
2. **拒答应对三件套**：授权上下文模板（每次调用携带任务 ID + 目标白名单）→ 检测拒答 + ≤2 次重提示 → 仍拒答则停止，停止原因记 `model_refusal`，报告如实标注（对齐 SEC-STOP-01 与报告诚实性验收）。
3. **选型指标成对测量**：误拒答率（对授权任务的拒答比例）与越界服从率（对越界请求的服从比例）必须同测，只看一个是盲人摸象。
4. **模型 × 框架成对验证**：拒答率随框架显著波动（52.3% vs 30.8%），ADR-001 的框架对比实验须复用同一组渗透 prompt，顺带测量安全行为面。
