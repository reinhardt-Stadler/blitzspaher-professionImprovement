## 1. 网络拓扑（V1）

**实测**：

```
pentest-net  Internal=true  Subnet=172.28.0.0/24

bz-agent:              blitzspaher_pentest-net                      ← 只有内网
bz-target-fastjson:    blitzspaher_pentest-net                      ← 只有内网
bz-proxy:              blitzspaher_outbound blitzspaher_pentest-net ← 唯一双网卡
```

**含义**：agent 容器**没有任何一张能出网的网卡**。它的唯一出网路径是 `proxy`
（由 `HTTP_PROXY=http://proxy:8888` 环境变量指定）。

## 2. L6 网络隔离（V2/V3/V4/V5）

### 2.1 正向：能访问靶场

```bash
$ docker compose exec agent curl -s -i http://target:8090/
HTTP/1.1 200
Content-Type: application/json;charset=UTF-8

{
    "age":25,
    "name":"Bob"
}
```

**含义**：靶场（Vulhub Fastjson）正常可访问，渗透工具可工作。

### 2.2 反向：访问公网被物理拒绝（★ R7 核心证据）

```bash
$ docker compose exec agent curl -s -m 10 https://www.baidu.com
HTTP=000
退出码=5
```

**三重保障在此处同时生效**：

| 层 | 机制 | 效果 |
|----|------|------|
| L6-a | agent 只有 internal 网卡 | 无路由 |
| L6-b | 唯一出口是 proxy | 必须走白名单 |
| L6-c | proxy `FilterDefaultDeny Yes` | baidu.com 不在白名单 → 拒绝 |

### 2.3 白名单生效验证（V4/V5）

| 目标 | HTTP | 退出码 | 代理日志 |
|------|------|--------|---------|
| `api.deepseek.com` | **401** | 0 | `Established connection to host "api.deepseek.com"` |
| `api.github.com` | 000 | 56 | `Proxying refused on filtered url "api.github.com:443"` |

> 401 = 连接成功但未携带 API key，正是"代理放行"的证据。

**代理原始日志**（`deploy/runs/proxy-logs/tinyproxy.log`）：

```
CONNECT   Request (file descriptor 5): CONNECT api.deepseek.com:443 HTTP/1.1
INFO      opensock: opening connection to api.deepseek.com:443
CONNECT   Established connection to host "api.deepseek.com"

CONNECT   Request (file descriptor 5): CONNECT api.github.com:443 HTTP/1.1
NOTICE    Proxying refused on filtered url "api.github.com:443"
```

## 3. L5 容器隔离（V6/V7）

| 验证 | 命令 | 实测结果 |
|------|------|---------|
| 读敏感文件 | `cat /etc/shadow` | `Permission denied` |
| 写系统目录 | `touch /usr/bin/x` | `Read-only file system` |
| 写临时目录 | `touch /tmp/ok` | ✅ 成功（tmpfs 预期行为） |
| 运行用户 | `id` | `uid=10001(agent)`，非 root |
| 权限集 | `/proc/self/status` | `CapPrm/CapEff/CapBnd = 0000000000000000` |

**含义**：即使 agent 进程被攻破，也无法提权、无法篡改系统、无法读宿主敏感文件。

## 5. 过程中发现并修复的问题（如实记录）

| # | 问题 | 现象 | 修复 |
|---|------|------|------|
| P1 | `docker compose` 插件未安装 | `unknown command: docker compose` | 安装 `docker-compose` CLI 插件 v5.7.0 |
| P2 | Docker Hub 不可达 | `connection reset by peer` | 配置国内镜像加速（daocloud / 1ms / xuanyuan） |
| P3 | 靶场镜像 tag 错误 | `vulhub/fastjson:1.2.47` 403 | 实际 tag 是 **1.2.45**（目录名 ≠ 镜像 tag） |
| P4 | buildx 插件缺失 | `additional contexts` 不可用 | 改用 `prepare-build.mjs` 预拷上下文（classic builder） |
| P5 | tinyproxy 指令不存在 | `LogConnects Yes` → 语法错误，代理不启动 | 移除该指令（LogLevel Info 已含连接记录） |
| P6 | **filter 正则不匹配** | `Proxying refused` 拒绝了**白名单内**的域名 | `$` 锚定匹配不到 `host:443`，改为 `([:/]\|$)` |

**P6 是最有教学价值的一个**：过滤器看到的是 `api.deepseek.com:443` 而非纯域名。
若不实测，会误以为"白名单已生效"（因为外部域名确实被拒），实际是**全拒**——
V3 在代理故障时"碰巧"也是失败，这类"假通过"必须靠 V4 的正向用例才能发现。
