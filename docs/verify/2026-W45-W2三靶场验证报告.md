## 1. 三个靶场

| 靶场 | 镜像 | 漏洞类型 | 探测方式（无损） |
|------|------|---------|----------------|
| Fastjson | `vulhub/fastjson:1.2.45` | 反序列化（@type） | POST 畸形 `@type` JSON，看 `JSONException` + `type not match` |
| Shiro | `vulhub/shiro:1.2.4` | 反序列化（rememberMe） | 发畸形 `rememberMe` Cookie，看 `Set-Cookie: rememberMe=deleteMe` |
| Struts2 | `vulhub/struts2:2.3.30` | OGNL 注入（S2-045） | Content-Type 带 OGNL `1+1`，看响应头 `bz-probe: 2` |

### 探测的无害性说明

三者都**不发送攻击载荷**：

- Fastjson：只触发 JSON 解析类型不匹配
- Shiro：只发一段非法 Base64，触发解密失败（不触发反序列化）
- Struts2：OGNL 只做 `1+1` 算术并写响应头，不执行命令

> 这是"证明风险面存在"，**不等于**"已完成实际利用"。

## 3. 报告生成器（方案 B）

### 3.1 设计

| 模块 | 职责 |
|------|------|
| `src/pi-pentest/src/report.ts` | 从审计目录生成渗透报告（四态 / 证据 / 覆盖率 / 效率） |
| `src/pi-pentest/src/index.ts` | `/pentest-report` 命令（模型可主动调用） |
| `src/pi-pentest/test/report.test.ts` | 21 项离线单测 |

**与 `reconstruct.ts` 的分工**（关键）：

- `reconstruct.ts` = **运行视角**：这一轮跑得怎么样（trace / 缺口 / 指标）
- `report.ts` = **渗透视角**：发现了什么、确认了什么（结论 / 证据 / 复现步骤）

### 3.2 报告结构（固定模板，模型不参与结构决定）

```
1. 测试目标与授权范围
2. 漏洞结论（四态）        ← CONFIRMED / NOT_CONFIRMED / INCONCLUSIVE / NOT_EXECUTED
3. 已执行测试
4. 未执行 / 未覆盖         ← 诚实性：deny / 人工拒绝 如实列出
5. 工具故障
6. 效率事实                ← 调用次数 / 决策次数 / 拦截次数 / 无效调用率 / 耗时
7. 报告声明                ← 固定免责声明
```

### 3.3 实测输出（节选）

```markdown

| 编号 | 结论 | 测试项 | 目标 |
| F-001 | ✅ CONFIRMED（已确认） | CVE-2016-4437 验证结果 | `http://shiro:8080/` |
| F-002 | ✅ CONFIRMED（已确认） | CVE-2017-18349 验证结果 | `http://target:8090/` |
| F-003 | ✅ CONFIRMED（已确认） | CVE-2017-5638 验证结果 | `http://struts2:8080/` |

## 6. 效率事实

| 指标 | 数值 |
| 工具调用次数 | 3 |
| 决策次数 | 3 |
| 拦截次数 | 0 |
| 无效调用数 | 0 |
| 无效调用率 | 0.0% |
| 任务耗时 | 3.2 秒 |
| 发现事实数 | 6 |
```

### 3.4 诚实性设计（可测试）

报告里有几条**硬编码**的诚实性保证，不依赖模型：

- 未执行验证工具时，`findings` 为空，并显式写"这不代表目标安全"
- `INCONCLUSIVE` 自动附"**不得**解读为无漏洞"
- `NOT_CONFIRMED` 自动附"不等于系统安全"
- `CONFIRMED` 自动附"仅证明风险面存在，不等于已实现利用"
- 无运行记录时 `buildReport()` 返回 `null`，**不虚构空报告**
