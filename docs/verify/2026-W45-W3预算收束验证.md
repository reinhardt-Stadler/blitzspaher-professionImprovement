# W3 预算收束机制：实现与验证

> **归属周志**：`docs/weeklyLog/2026-W45-W2单点验证-Fastjson.md`
> **对应**：SEC-BUDGET-01、SEC-STOP-01、FR-AGENT-05、OQ-09
> **日期**：2026-11-07
> **设计文档**：`docs/design/预算收束设计.md`

---

## 0. 结论

> **预算收束机制已实现并实测生效：预算耗尽时模型不被硬砍，而是收到"请收束"提示，
> 主动汇总已有证据、调用 `pentest_report` 生成报告，报告中自动记录 `停止原因：budget_exceeded`。**

---

## 1. 为什么不做硬停止

用户明确要求：**"预算到了就要有计划的收束工作"**。

硬停止的问题：
- 任务被砍在半路，模型没机会整理结论
- 报告只剩半截，违反 G4「证据驱动报告」与 R5「四态结论」

---

## 2. 三档水位设计

```
100% ───────────── exhausted   停止 + 提示出报告
  │
 90% ───────────── converge    提示收束 + 阻断新验证调用
  │
 80% ───────────── warn        提示聚焦已有线索
  │
  0% ───────────── normal
```

### 为什么 90% 就阻断

DeepSeek V4.1 Flash 单次推理约 12K token（ADR-002 实测），再调一个工具可能直接打穿预算。
**留 10% 给模型写总结**——总结本身也要花 token。

### 收束期保留的工具（Q1 决策）

| 工具 | 收束期 | 理由 |
|------|--------|------|
| `nmap_scan` / `http_probe` / `cve_check` | 🚫 阻断 | 验证类，会产生新消耗 |
| `evidence_collector` | ✅ 允许 | 证据类，允许先固化证据 |
| `pentest_report` | ✅ 允许 | 出报告必须可用 |

---

## 3. 预算维度（Q2 决策：加成本维度）

| 维度 | 来源 | 说明 |
|------|------|------|
| `maxCalls` | 已有 | 工具调用次数 |
| `maxTokens` | **新增** | pi `message_end` 的 `usage.totalTokens` |
| `maxRuntimeMs` | 已有 | 运行时长 |
| `maxCostUsd` | **新增** | pi `usage.cost.total` |

**多维度取最紧**：任一维度达到水位即触发（取比例最大的那个）。

### pi 的 usage 结构（实测）

```json
{
  "input": 1646, "output": 12, "reasoning": 10,
  "cacheRead": 0, "cacheWrite": 0, "totalTokens": 1658,
  "cost": { "input": 0.00217, "output": 0.0000475, "total": 0.00222 }
}
```

> pi 直接提供了 token 与成本，无需自建估算。

---

## 4. 提示词投递（Q3 决策：steer）

用 `pi.sendUserMessage(..., { deliverAs: "steer" })`——**当前轮工具调用结束后立即插入**，
不等整轮跑完。收束要即时。

### 收束提示原文

```
[预算收束] 预算即将耗尽：调用 3 次（15%）、token 5800（97%）。

从现在起请按以下顺序收尾：
1. 停止发起新的**验证类**工具调用（nmap_scan / http_probe / cve_check 会被阻断）
2. 如需固化证据，仍可使用证据类工具
3. 基于已有证据汇总结论，区分 CONFIRMED / NOT_CONFIRMED / INCONCLUSIVE / NOT_EXECUTED
4. 调用 pentest_report 工具生成报告

未完成的测试项请在报告中如实标注为 NOT_EXECUTED，不要省略。
```

### 通知去重

`markNotified(level)` 保证每个水位只提示一次，避免每轮刷屏。

## 5. 实测验证

### 5.1 测试条件

```bash
PENTEST_MAX_TOKENS=6000   # 故意设很小以触发收束
PENTEST_MAX_CALLS=20
任务：验证三个靶场并生成报告
```

### 5.2 实测结果

**审计事件**：

```
3 × decision   (allow)
3 × execution  (CONFIRMED ×3)
1 × stop       {"stopReason":"budget_exceeded","note":"预算耗尽（调用 3，token 9142）"}
```

**模型输出**（`runs/agent-work/b3.out`）：

```
报告已生成完成。

## 最终结论

**报告路径**：/work/report-w3-budget3.md
**运行**：w3-budget3，观测完整度 TRACE_COMPLETE

| 目标 | CVE | 结论 |
| target:8090 | CVE-2017-18349 (Fastjson RCE) | CONFIRMED |
| shiro:8080  | CVE-2016-4437 (Shiro rememberMe) | CONFIRMED |
| struts2:8080| CVE-2017-5638 (S2-045 OGNL) | CONFIRMED |

3 项全部 CONFIRMED，工具调用 3 次，无效调用率 0.0%。
```

**生成的报告**（`/work/report-w3-budget3.md`）：

```markdown
> 观测完整度：**TRACE_COMPLETE**
> 停止原因：**budget_exceeded**

## 2. 漏洞结论（四态）
| F-001 | ✅ CONFIRMED | CVE-2016-4437 验证结果 | `shiro:8080` |
| F-002 | ✅ CONFIRMED | CVE-2017-18349 验证结果 | `target:8090` |
| F-003 | ✅ CONFIRMED | CVE-2017-5638 验证结果 | `struts2:8080` |

## 6. 效率事实
| 工具调用次数 | 3 |
| 无效调用率 | 0.0% |
| 任务耗时 | 7.0 秒 |
```

### 5.3 关键观察

1. **收束生效**：模型明确说"预算已耗尽，不再发起新的工具调用"，然后汇总
2. **报告可用**：模型成功调用了 `pentest_report` 工具，报告落盘
3. **诚实性保持**：报告自动记录 `停止原因：budget_exceeded`
4. **无数据丢失**：三靶场结论在收束前已全部完成，报告完整

## 6. 过程中发现并修复的问题

### P1：`/pentest-report` 是命令，模型无法主动调用

**现象**：首次实测时模型报告"`/pentest-report` 不在当前可用工具集中"。

**原因**：slash 命令是**用户输入**，不是模型可调用的工具。

**修复**：抽出 `generateReport()` 公共函数，同时注册为：
- **工具** `pentest_report`（模型可调，收束时用）
- **命令** `/pentest-report`（用户手动调）

并把 `pentest_report` 加入收束白名单。

### P2：收束拦截放在 `PENTEST_TOOLS` 判断之前

**现象**：理论上会误拦 pi 内置工具（read/bash）。

**修复**：收束判断移到"只拦截渗透工具"之后（已确认顺序正确）。

### P3：首次测试预算未触发

**现象**：`PENTEST_MAX_TOKENS=30000`，实际只用了约 9K，任务自然完成。

**处理**：改用 6000 触发；这也说明**实测数据可用于 OQ-09 冻结**。

## 7. 对 OQ-09 的数据贡献

| 场景 | 调用次数 | token | 耗时 |
|------|---------|-------|------|
| 三靶场验证（完整） | 3 | ~9,100 | 7.0 秒 |
| 单靶场验证（早期） | 1 | ~5,000 | 5.0 秒 |

**初步建议**（待更多样本）：
- `maxCalls`: 12（当前默认，足够三靶场 + 余量）
- `maxTokens`: 60,000（约 6–7 次完整验证的余量）
- `warnAt` / `convergeAt`: 0.8 / 0.9
